Q1

What is the difference between var, let and const?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: let and const live only inside their { } box. var leaks out. const means 'this name always points to the same thing'.

var is function-scoped and can be re-declared. let and const are block-scoped, which means they live only inside the nearest { }.

const means you cannot re-assign the variable. It does not make an object frozen: you can still change the properties of a const object.

All three are hoisted, but let and const are in the temporal dead zone until their line runs, so using them early throws an error. var gives undefined instead.

💡 Easy example: const is like a locker number given to you. You can't change your locker number, but you can change what is inside the locker.

console.log(a); // undefined (var is hoisted with undefined)
var a = 1;

const user = { name: "Ravi" };
user.name = "Priya"; // allowed: we changed a property
console.log(user.name);

try {
  console.log(b); // let in temporal dead zone
  let b = 2;
} catch (e) {
  console.log(e.name);
}

🗣️ Say it in one line: var is function-scoped, let and const are block-scoped, and const stops re-assignment, not mutation.

↪️ Follow-up: Why do people avoid var today? Because it leaks out of blocks like if and for, which causes bugs, especially in loops with callbacks.

Q2

What is a closure? Give a real use.

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: A closure is a function that carries a small backpack of variables from the place where it was born.

🖼️ Picture it

A closure is a function that remembers the variables from the place where it was created, even after that outer function has finished.

Real uses: keeping private data (like a counter), creating functions with a preset value, and debounce/throttle, which remember a timer between calls. React hooks also depend on closures.

💡 Easy example: Think of a tiffin packed at home. Even when you are in the office in Noida, you still have the food from home. The inner function carries its 'home' variables with it.

function makeCounter() {
  let count = 0; // private: nobody outside can touch it
  return function () {
    count++;
    return count;
  };
}
const next = makeCounter();
next();
next();
console.log(next());

🗣️ Say it in one line: A closure is a function plus the variables it remembers from where it was created.

↪️ Follow-up: Can closures cause memory leaks? Yes, if a long-living closure (like an event listener) holds a big object you no longer need. Remove listeners and clear timers when done.

Q3

What will this print, and how do you fix it? for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: With var all three timers share one i, which is already 3. With let, each timer gets its own i.

It prints 3 3 3. There is only one i because var is function-scoped, and by the time the timers run, the loop has finished and i is 3.

Fix: use let. let creates a new i for every loop round, so each callback closes over its own copy and you get 0 1 2.

for (var i = 0; i < 3; i++) setTimeout(() => console.log("var", i));
for (let j = 0; j < 3; j++) setTimeout(() => console.log("let", j));

🗣️ Say it in one line: var shares one variable across the loop; let gives each round its own copy.

Q4

What is the difference between == and ===?

3–5 yrs
Show answer

🟢 In simple words: === checks 'same value and same type'. == first tries to convert types, which surprises people.

=== checks value and type, with no conversion. == converts types first and then compares, which gives surprising results like 0 == "" being true.

Use === always. The only common exception is x == null, which checks for both null and undefined in one go.

console.log(0 == "", 0 === "");
console.log(null == undefined, null === undefined);
console.log(typeof null); // a famous old bug in JavaScript

🗣️ Say it in one line: === compares without type conversion, so it is predictable; I use it everywhere.

Q5

Explain this in JavaScript. How is an arrow function different?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: this means 'the object before the dot when the function is called'. Arrow functions don't have their own this; they borrow it from outside.

this depends on how a function is called, not where it is written:

  • obj.method() → this is obj
  • a plain call fn() → undefined in strict mode
  • new Fn() → the new object
  • fn.call(x) / apply / bind → x

Arrow functions do not have their own this. They use the this of the code around them. That is why arrow functions are handy inside callbacks, and why you should not use an arrow function as an object method that needs this.

"use strict";
const team = {
  name: "Payments",
  normal() { return this.name; },
  arrow: () => this === team, // arrow takes 'this' from outside, so it is not team
  later() { return [1].map(() => this.name)[0]; }, // arrow inside method: works
};
console.log(team.normal(), team.arrow(), team.later());
const loose = team.normal;
try { loose(); } catch (e) { console.log("lost this:", e.name); }

🗣️ Say it in one line: this is decided by the call site; arrow functions borrow this from the surrounding scope.

↪️ Follow-up: What do call, apply and bind do? All three set this. call passes arguments one by one, apply passes them as an array, and bind returns a new function for later.

Q6

What will this print? console.log(1); setTimeout(() => console.log(2)); Promise.resolve().then(() => console.log(3)); console.log(4);

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Normal code first, then promise callbacks, then timers. So: 1, 4, 3, 2.

🖼️ Picture it

It prints 1, 4, 3, 2.

  • 1 and 4 are normal code, so they run first.
  • Promise callbacks go to the microtask queue.
  • setTimeout goes to the task (macrotask) queue.
  • After the current code finishes, the event loop empties all microtasks first, then picks the next task.

💡 Easy example: At a bank counter, the person already being served finishes first (sync code). Then 'quick questions' (microtasks) are answered. Only then is the next token number (setTimeout) called.

console.log(1);
setTimeout(() => console.log(2));
Promise.resolve().then(() => console.log(3));
console.log(4);

🗣️ Say it in one line: Sync code runs first, then all microtasks like promises, then the next macrotask like setTimeout.

↪️ Follow-up: Where does await fit in? Code after await continues as a microtask, just like .then().

Q7

Explain the event loop in simple words.

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: JavaScript has one worker. The event loop is the manager who gives it the next ready job only when it is free.

🖼️ Picture it

JavaScript runs on one main thread. The event loop is the system that lets it handle many things without blocking:

  • The call stack runs your current code.
  • Slow work (timers, network, file reads) is handed to the browser or Node.js.
  • When that work finishes, its callback waits in a queue.
  • When the call stack is empty, the event loop moves callbacks in: microtasks first, then one macrotask, then rendering in the browser.

This is why a long for loop freezes the page: the stack never becomes empty, so nothing else (clicks, painting) can run.

🗣️ Say it in one line: One thread runs code; slow work happens outside; the event loop feeds finished callbacks back when the stack is empty.

Q8

Difference between Promise.all, allSettled, race and any?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: all = 'everyone must pass'. allSettled = 'tell me everyone's result'. race = 'first to finish'. any = 'first to succeed'.

  • Promise.all: waits for all. Fails fast if any one fails.
  • Promise.allSettled: waits for all and gives each result as fulfilled or rejected. Never fails.
  • Promise.race: settles with the first one to finish, success or failure.
  • Promise.any: gives the first success. Fails only if all fail.

Real use: a dashboard that loads 4 widgets should use allSettled, so one broken widget doesn't blank the whole page. A timeout wrapper uses race.

const ok = (v, ms) => new Promise((r) => setTimeout(() => r(v), ms));
const bad = (v, ms) => new Promise((_, j) => setTimeout(() => j(new Error(v)), ms));

(async () => {
  try { await Promise.all([ok("a", 10), bad("b", 5)]); } catch (e) { console.log("all failed:", e.message); }
  const s = await Promise.allSettled([ok("a", 10), bad("b", 5)]);
  console.log(s.map((x) => x.status).join(","));
  console.log("race:", await Promise.race([ok("slow", 20), ok("fast", 5)]));
  console.log("any:", await Promise.any([bad("x", 5), ok("first ok", 10)]));
})();

🗣️ Say it in one line: all fails fast, allSettled never fails, race takes the first to finish, any takes the first success.

↪️ Follow-up: How would you write Promise.all yourself? Return a new promise, keep a results array and a counter, resolve when the counter reaches the length, and reject on the first error.

Q9

async/await vs .then(): which is better and how do you handle errors?

3–5 yrs
Show answer

🟢 In simple words: Both do the same thing; async/await just reads like normal top-to-bottom code. Wrap it in try/catch for errors.

Both use promises underneath. async/await reads like normal top-to-bottom code, so it is easier to follow. Handle errors with try/catch.

A common mistake: awaiting independent calls one by one. If two API calls don't depend on each other, start both and await Promise.all, which can halve the waiting time.

async function loadDashboard(api) {
  try {
    // Slow: await one, then the other.
    // Fast: start both together.
    const [user, orders] = await Promise.all([api.user(), api.orders()]);
    return { user, orders };
  } catch (err) {
    console.error("Dashboard failed", err);
    throw err;
  }
}

🗣️ Say it in one line: I prefer async/await with try/catch, and I run independent calls in parallel with Promise.all.

Q10

What is debounce vs throttle? Write a debounce function.

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Debounce: wait until the user stops, then run once. Throttle: run at most once every X milliseconds.

🖼️ Picture it

Debounce waits until the user stops doing something for a set time, then runs once. Use it for a search box: call the API only after typing stops for 300 ms.

Throttle runs at most once every X ms, no matter how many events come. Use it for scroll or resize handlers.

💡 Easy example: Debounce is a lift door that waits until people stop entering before it closes. Throttle is a Delhi Metro gate that lets one person through every second, however big the crowd.

function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer); // cancel the previous plan
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

const search = debounce((q) => console.log("API call for:", q), 50);
search("n"); search("no"); search("noida"); // only the last one runs

🗣️ Say it in one line: Debounce runs after activity stops; throttle runs at a fixed maximum rate.

↪️ Follow-up: Write throttle too. Keep a last timestamp; run only if Date.now() - last >= limit, then update last.

Q11

Shallow copy vs deep copy. How do you deep copy an object?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: A shallow copy copies only the outer box; the inner boxes are still shared. A deep copy copies every box.

A shallow copy ({...obj}, Object.assign, [...arr]) copies only the top level. Nested objects are still shared, so changing them changes the original too.

A deep copy copies everything. Use structuredClone(obj), which is built into modern browsers and Node.js. JSON.parse(JSON.stringify(obj)) is the old trick, but it loses dates, undefined, Maps and functions.

In React this matters a lot: you must create new objects for the parts you change, or React may not re-render.

const order = { id: 1, address: { city: "Noida" } };
const shallow = { ...order };
shallow.address.city = "Gurugram";
console.log(order.address.city); // original changed too!

const deep = structuredClone(order);
deep.address.city = "Delhi";
console.log(order.address.city); // original safe

🗣️ Say it in one line: Spread copies one level; structuredClone copies everything.

Q12

Explain prototypes. How is a JavaScript class related to them?

5–8 yrs
Show answer

🟢 In simple words: Every object has a hidden 'parent' object. If a property isn't found, JavaScript asks the parent. class is a neat way to set that up.

🖼️ Picture it

Every object has a hidden link to another object called its prototype. When you read a property that the object doesn't have, JavaScript looks up this chain. That is how arrays get .map: from Array.prototype.

class is mostly cleaner syntax over prototypes. Methods written in a class are placed on ClassName.prototype and shared by all objects, which saves memory.

class Employee {
  constructor(name) { this.name = name; }
  greet() { return "Hi " + this.name; }
}
const e = new Employee("Aman");
console.log(e.greet(), Object.getPrototypeOf(e) === Employee.prototype);
console.log(e.hasOwnProperty("greet")); // greet lives on the prototype

🗣️ Say it in one line: Objects inherit through a prototype chain, and class is a cleaner way to write that.

Q13

What is the output? [1, 2, 3].map(parseInt)

5–8 yrs
Show answer

🟢 In simple words: map gives parseInt two values (item and index), and parseInt treats the index as the number base. That breaks it.

It gives [1, NaN, NaN]. map passes three arguments: value, index and array. parseInt takes the second argument as the radix (number base):

  • parseInt(1, 0) → radix 0 means 'guess', so 1
  • parseInt(2, 1) → base 1 is invalid, so NaN
  • parseInt(3, 2) → "3" is not a valid binary digit, so NaN

Lesson: pass a small arrow function, like .map((x) => parseInt(x, 10)) or .map(Number).

console.log([1, 2, 3].map(parseInt));
console.log(["1", "2", "3"].map(Number));

🗣️ Say it in one line: map passes the index as a second argument, and parseInt treats it as the number base.

Mock task 1: Write your own Promise.all.

Show a sample answer

Keep a results array in the right order and a counter of finished promises. Reject on the first error.

function promiseAll(list) {
  return new Promise((resolve, reject) => {
    const results = [];
    let done = 0;
    if (list.length === 0) return resolve(results);
    list.forEach((p, i) => {
      Promise.resolve(p).then((value) => {
        results[i] = value; // keep the original order
        done++;
        if (done === list.length) resolve(results);
      }, reject);
    });
  });
}

Mock task 2: Flatten [1, [2, [3, [4]]]] to [1, 2, 3, 4] without .flat().

Show a sample answer

Use recursion: for each item, if it is an array, flatten it and spread the result; otherwise push the item.

function flatten(arr) {
  const out = [];
  for (const item of arr) {
    if (Array.isArray(item)) out.push(...flatten(item));
    else out.push(item);
  }
  return out;
}

Mock task 3: Explain to a fresher why the page freezes during a big for loop.

Show a sample answer

JavaScript has one main thread. While the loop runs, the call stack is never empty, so the event loop can't handle clicks or let the browser paint. Fix: split the work into chunks with setTimeout, or move it to a Web Worker.

Q1

Why does setCount(count + 1) three times only add 1? How do you fix it?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Inside one click, count is frozen at its old value. Use setCount(c => c + 1) to always add to the latest value.

Inside one render, count is a fixed value (a snapshot). All three calls say "set to 0 + 1", so the result is 1. React also batches them into one render.

Fix: use the updater function setCount(c => c + 1). React passes the latest value each time, so you get 3.

function Counter() {
  const [count, setCount] = useState(0);
  function addThree() {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
    setCount((c) => c + 1); // count becomes 3
  }
  return <button onClick={addThree}>{count}</button>;
}

🗣️ Say it in one line: State is a snapshot per render; use the updater form when the new value depends on the old one.

↪️ Follow-up: What is automatic batching? Since React 18, multiple state updates in the same event, timeout or promise are combined into one re-render.

Q2

Explain the useEffect dependency array: none, empty and with values.

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: The dependency array says when the effect should run again: every render, only once, or when certain values change.

🖼️ Picture it

  • No array: runs after every render.
  • Empty []: runs once after the first render (and cleanup on unmount).
  • [userId]: runs after the first render and again whenever userId changes.

The cleanup function (the function you return) runs before the next effect and on unmount. Use it to clear timers, remove listeners and cancel requests.

Rule: include everything from the component that the effect uses. Don't silence the ESLint exhaustive-deps warning; fix the code instead.

useEffect(() => {
  const id = setInterval(() => refreshPrices(), 5000);
  window.addEventListener("resize", onResize);
  return () => {
    clearInterval(id); // cleanup
    window.removeEventListener("resize", onResize);
  };
}, [refreshPrices, onResize]);

🗣️ Say it in one line: No array runs every render, [] runs once, [x] runs when x changes; cleanup runs before the next run and on unmount.

Q3

How do you avoid a race condition when fetching in useEffect?

5–8 yrs🔥 Very common
Show answer

🟢 In simple words: If an old request finishes late, it can overwrite new data. Cancel the old request when a new one starts.

If the user switches from employee 1 to employee 2 quickly, the reply for 1 may arrive after 2 and show the wrong data.

Fix: in the cleanup, abort the old request with AbortController, or set an ignore flag. Better still, use TanStack Query, which handles this, caching and retries for you.

useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/employees/${id}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setEmployee)
    .catch((e) => { if (e.name !== "AbortError") setError(e); });
  return () => controller.abort(); // old request is cancelled
}, [id]);

🗣️ Say it in one line: I cancel the previous request in the cleanup with AbortController, or let React Query handle it.

Q4

What is a stale closure in React?

5–8 yrs🔥 Very common
Show answer

🟢 In simple words: A function made in an old render still sees old values, like reading yesterday's newspaper.

A function created in an old render remembers old state. Classic example: a setInterval started in useEffect(..., []) always sees count = 0, because the callback closed over the first render's value.

Fixes:

  • use the updater setCount(c => c + 1),
  • add the value to the dependency array,
  • or keep the latest value in a useRef.
// Bug: always logs 0
useEffect(() => {
  const id = setInterval(() => console.log(count), 1000);
  return () => clearInterval(id);
}, []);

// Fix for updates: the updater always gets the latest value
useEffect(() => {
  const id = setInterval(() => setCount((c) => c + 1), 1000);
  return () => clearInterval(id);
}, []);

🗣️ Say it in one line: A callback from an old render sees old state; fix it with updater functions, correct deps or a ref.

Q5

When should you NOT use useEffect?

5–8 yrs
Show answer

🟢 In simple words: useEffect is for talking to things outside React. If you can calculate something during render, just calculate it.

Effects are for syncing with outside systems (network, timers, browser APIs, third-party widgets). They are often overused:

  • Derived data: don't store fullName in state and sync it with an effect. Just calculate first + " " + last during render.
  • User events: put the logic in the click handler, not in an effect that watches a flag.
  • Resetting state on a prop change: give the component a key instead.
  • Data fetching: prefer TanStack Query.

🗣️ Say it in one line: Effects are for outside systems; derived values are calculated during render and event logic goes in handlers.

Q6

useMemo vs useCallback vs React.memo?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: useMemo remembers a value, useCallback remembers a function, and memo skips redrawing a component when its props didn't change.

  • useMemo(fn, deps): remembers a calculated value, like a filtered list.
  • useCallback(fn, deps): remembers a function, so its identity stays the same.
  • memo(Component): skips re-rendering a component if its props are the same (shallow compare).

They work together: memo on a child is useless if the parent passes a new function or object every render. That is where useCallback and useMemo help.

Don't wrap everything. Memoisation has its own cost; use it for heavy calculations or a memoised child that renders a lot.

const visible = useMemo(() => orders.filter((o) => o.status === tab), [orders, tab]);
const onSelect = useCallback((id) => setSelected(id), []);
return <OrderTable rows={visible} onSelect={onSelect} />; // OrderTable = memo(...)

🗣️ Say it in one line: useMemo caches a value, useCallback caches a function, memo skips a component's render when props are equal.

Q7

What is useRef used for?

3–5 yrs
Show answer

🟢 In simple words: useRef is a box that keeps a value between renders without causing a redraw, often used to grab a DOM element.

useRef gives a box (ref.current) that survives renders and does not cause a re-render when changed.

Two uses: reaching a DOM element (focus an input, scroll to a row), and keeping a mutable value like a timer id, the previous value, or "is this the first render".

function SearchBox() {
  const inputRef = useRef(null);
  useEffect(() => { inputRef.current.focus(); }, []);
  return <input ref={inputRef} />;
}

🗣️ Say it in one line: useRef holds a DOM node or a value that survives renders without causing one.

Q8

When would you use useReducer instead of useState?

5–8 yrs
Show answer

🟢 In simple words: When state has many parts that change together, put all the update rules in one reducer function.

Use useReducer when state has many related fields or the next state depends on what happened (an action), like a multi-step form, a cart, or a table with filters, sort and page.

All the update logic sits in one pure function, which is easy to test and read: dispatch({ type: "addItem", item }).

function cartReducer(state, action) {
  switch (action.type) {
    case "add": return { ...state, items: [...state.items, action.item] };
    case "remove": return { ...state, items: state.items.filter((i) => i.id !== action.id) };
    case "clear": return { ...state, items: [] };
    default: return state;
  }
}
const [cart, dispatch] = useReducer(cartReducer, { items: [] });

🗣️ Say it in one line: useReducer when many fields change together or updates depend on an action type.

Q9

useEffect vs useLayoutEffect?

5–8 yrs
Show answer

🟢 In simple words: useEffect runs after the screen is painted. useLayoutEffect runs just before, for measuring things without flicker.

useEffect runs after the browser paints, so it doesn't block the screen. Use it for almost everything.

useLayoutEffect runs after DOM changes but before paint. Use it only when you must measure the DOM and fix the position before the user sees a flicker, like placing a tooltip.

🗣️ Say it in one line: useLayoutEffect runs before paint for measuring the DOM; everything else uses useEffect.

Q10

What is a custom hook? Write one.

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: A custom hook is your own reusable useSomething function that packs hook logic, like useDebounce.

A custom hook is a function starting with use that reuses stateful logic (not UI) across components. Each component that uses it gets its own state.

Good examples: useDebounce, useOnlineStatus, usePermission, useLocalStorage.

function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

// usage
const debouncedQuery = useDebounce(query);
const { data } = useQuery({ queryKey: ["search", debouncedQuery], queryFn: () => search(debouncedQuery) });

🗣️ Say it in one line: A custom hook shares stateful logic, not state; each user gets its own copy.

↪️ Follow-up: What are the rules of hooks? Call hooks only at the top level (not in loops or conditions) and only from components or other hooks. React matches hooks by call order.

Mock task 1: Write usePrevious(value) that returns the value from the last render.

Show a sample answer

Store the value in a ref inside an effect; the effect runs after render, so during render the ref still holds the old value.

function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; }, [value]);
  return ref.current;
}

Mock task 2: Write useOnlineStatus() that returns true or false and updates live.

Show a sample answer

Subscribe to the window's online and offline events and clean up.

function useOnlineStatus() {
  const [online, setOnline] = useState(navigator.onLine);
  useEffect(() => {
    const on = () => setOnline(true);
    const off = () => setOnline(false);
    window.addEventListener("online", on);
    window.addEventListener("offline", off);
    return () => {
      window.removeEventListener("online", on);
      window.removeEventListener("offline", off);
    };
  }, []);
  return online;
}

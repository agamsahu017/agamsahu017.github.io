Q1

How do nested routes and <Outlet /> work?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: The layout (header and sidebar) stays; only the middle part, the Outlet, changes with the URL.

🖼️ Picture it

A parent route renders a layout (header and sidebar), and <Outlet /> is the slot where the matching child route appears. The layout stays on screen while only the inner part changes.

An index route is the default child, and path="*" catches unknown URLs for a 404 page.

<Routes>
  <Route path="/" element={<AppLayout />}>      {/* header + sidebar + <Outlet /> */}
    <Route index element={<Dashboard />} />
    <Route path="employees" element={<EmployeeList />} />
    <Route path="employees/:id" element={<EmployeeDetail />} />
  </Route>
  <Route path="/login" element={<Login />} />
  <Route path="*" element={<NotFound />} />
</Routes>

🗣️ Say it in one line: The parent renders a layout and <Outlet /> shows whichever child route matches.

Q2

How do you build a protected route that sends the user back after login?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: If not logged in, send the user to login and remember where they wanted to go. After login, send them back there.

🖼️ Picture it

Make a guard component. If there is no user, <Navigate> to /login with replace, and pass the current location in state. After a successful login, navigate to state.from.

Use it as a layout route with <Outlet />, so you protect a whole group of pages at once. Add a permission check for role-based pages.

function RequireAuth({ permission }) {
  const { user } = useAuth();
  const location = useLocation();
  if (!user) return <Navigate to="/login" replace state={{ from: location }} />;
  if (permission && !user.permissions.includes(permission)) return <Navigate to="/403" replace />;
  return <Outlet />;
}

// routes
<Route element={<RequireAuth permission="report:view" />}>
  <Route path="reports" element={<Reports />} />
</Route>

// after login
const from = location.state?.from?.pathname || "/";
navigate(from, { replace: true });

🗣️ Say it in one line: A guard layout route redirects to login with the current location in state, then login navigates back to it.

Q3

useParams vs useSearchParams? Where should table filters live?

3–5 yrs
Show answer

🟢 In simple words: useParams reads the 'which item' part of the URL. useSearchParams reads the filters after the ?. Keep filters in the URL.

  • useParams: values from the path, like /employees/:id → id. Used for "which item".
  • useSearchParams: values from the query string, like ?status=pending&page=2. Used for filters, sort and page.

Keep table filters in the URL: the page then survives a refresh, the browser Back button works, and users can share the link. Combine it with React Query by putting the params in the queryKey.

const [params, setParams] = useSearchParams();
const status = params.get("status") ?? "all";
const page = Number(params.get("page") ?? 1);

const changeStatus = (s) => setParams({ status: s, page: "1" });

🗣️ Say it in one line: Path params identify the item; search params hold filters, so links are shareable and refresh-safe.

Q4

How do you lazy-load pages to reduce the bundle size?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Load a page's code only when the user opens that page, so the first load is smaller.

Use React.lazy with a dynamic import(), and wrap the routes in <Suspense> with a fallback. Each page becomes a separate JS file, downloaded only when the user opens it.

Good candidates: admin screens, reports and chart-heavy pages. Keep the login and dashboard in the main bundle so they open fast.

const Reports = lazy(() => import("./pages/Reports"));

<Suspense fallback={<PageSkeleton />}>
  <Routes>
    <Route path="reports" element={<Reports />} />
  </Routes>
</Suspense>

🗣️ Say it in one line: React.lazy plus Suspense splits each page into its own chunk that loads on demand.

Q5

What are data routers, loaders and actions in React Router 6.4+? What changed in v7?

5–8 yrs
Show answer

🟢 In simple words: Loaders fetch a page's data before it shows, and actions handle form submits. v7 merged Remix in.

From 6.4, you can create the router with createBrowserRouter and give routes a loader (fetch data before the page renders), an action (handle form submits) and an errorElement. This avoids "render, then fetch" waterfalls.

React Router v7 combined React Router with Remix. Upgrading from v6 is mostly smooth if you turn on the v6 "future flags" first. Many projects in NCR are still on v6, which is fine. Say which one your project uses and why.

🗣️ Say it in one line: Loaders fetch before render and actions handle submits; v7 merged in Remix and upgrades smoothly via future flags.

Q6

Why is react-hook-form faster than controlled forms?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: react-hook-form doesn't redraw the whole form on every key press, so big forms stay fast.

It keeps inputs uncontrolled and registers them with refs, so typing doesn't re-render the whole form. Only the parts that subscribe to a value (like an error message or a useWatch) re-render.

For a 60-field registration form, a controlled approach re-renders the full form on every key press. RHF doesn't.

const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm({
  defaultValues: { name: "", email: "" },
  mode: "onBlur", // validate when the user leaves a field
});

<form onSubmit={handleSubmit(onSubmit)}>
  <input {...register("name", { required: "Name is required" })} />
  {errors.name && <p>{errors.name.message}</p>}
  <input {...register("email", { required: "Email is required", pattern: { value: /^\S+@\S+$/, message: "Enter a valid email" } })} />
  {errors.email && <p>{errors.email.message}</p>}
  <button disabled={isSubmitting}>Submit</button>
</form>

🗣️ Say it in one line: Inputs stay uncontrolled and register via refs, so typing doesn't re-render the whole form.

Q7

How do you use react-hook-form with MUI, a date picker or react-select?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: MUI selects and date pickers need value and onChange, so wrap them in Controller to connect them to the form.

Those components are controlled (they need value and onChange) and don't accept register. Use <Controller> (or useController), which connects them to the form state.

<Controller
  name="state"
  control={control}
  rules={{ required: "Select a state" }}
  render={({ field, fieldState }) => (
    <Select {...field} options={stateOptions} />
  )}
/>

🗣️ Say it in one line: Controller connects controlled UI components to the form state.

Q8

How do you validate with a schema (zod or yup)? Why?

5–8 yrs
Show answer

🟢 In simple words: Write all form rules in one schema (zod), and the form uses it for validation and for TypeScript types.

Write the rules once as a schema and pass it with resolver: zodResolver(schema) from @hookform/resolvers. Benefits: all rules in one place, cross-field rules (end date after start date, password match), and with zod you get the TypeScript type for free with z.infer<typeof schema>.

Remember: frontend validation is for user experience. The backend must validate again.

🗣️ Say it in one line: A zod schema via zodResolver keeps all rules in one place and gives me the form's TypeScript type.

Q9

How do you build an edit form that loads data from the API? And dynamic rows?

5–8 yrs🔥 Very common
Show answer

🟢 In simple words: Load the data, then call reset(data) to fill the form. For 'add another row' sections, use useFieldArray.

Edit form: fetch with React Query, then call reset(data) when the data arrives (or render the form only after loading, passing defaultValues). reset also sets the "clean" state, so isDirty works correctly.

Dynamic rows (add another education entry, another document): use useFieldArray. Use field.id as the key, not the index.

Use useWatch instead of watch to read one field without re-rendering the whole form.

const { data } = useQuery({ queryKey: ["employee", id], queryFn: () => api.employee(id) });
const { control, register, reset } = useForm();
useEffect(() => { if (data) reset(data); }, [data, reset]);

const { fields, append, remove } = useFieldArray({ control, name: "education" });
fields.map((f, i) => (
  <div key={f.id}>
    <input {...register(`education.${i}.degree`)} />
    <button type="button" onClick={() => remove(i)}>Remove</button>
  </div>
));

🗣️ Say it in one line: reset(data) when the API data arrives, and useFieldArray with field.id keys for dynamic rows.

Practiceप्रैक्टिस

A common L2 task: design a big form for an enterprise app.

Mock task 1: Design a 5-step registration form with 60 fields, a 'save draft' button and file uploads.

Show a sample answer

One useForm for the whole wizard (or one per step, merged on submit), with a zod schema per step, using trigger(stepFields) before going to the next step. Save drafts to the API (debounced, or on 'Save draft'). Upload files separately to S3 using pre-signed URLs and store only the returned keys in the form. Use useFieldArray for repeating sections and Controller for date pickers. Warn on leaving with unsaved changes when isDirty is true.

Mock task 2: The URL /employees?page=3 loses the page after clicking a row and pressing Back. Why?

Show a sample answer

The page number was kept in useState, which resets on remount. Move it into useSearchParams so the URL holds it, and Back restores it.

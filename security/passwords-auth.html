Passwords, login and MFAPasswords, login और MFA

⏱️ 20 min read + practice20 मिनट पढ़ाई + प्रैक्टिस🛡️ Security🎯 Interview focusedइंटरव्यू के हिसाब से

In one line: Store slow, salted hashes (or let an identity provider do it), add MFA, and rate-limit every login and OTP endpoint.

Store a fingerprint, not the passwordPassword नहीं, उसका fingerprint रखिए

Beginnerशुरुआती

A hash turns a password into a fixed-length fingerprint that can't be turned back. At login, you hash what the user typed and compare fingerprints. If the database leaks, attackers get fingerprints, not passwords.

Hash password को एक तय लंबाई के fingerprint में बदल देता है जिसे वापस नहीं बदला जा सकता। Login पर user के टाइप किए password का hash बनाकर fingerprints मिलाते हैं। Database leak हो तो attackers को fingerprints मिलते हैं, passwords नहीं।

  • Salt: a random value added per user, so two people with the same password get different hashes, and ready-made tables of common passwords don't work.Salt: हर user के लिए जोड़ी गई random value, ताकि एक जैसे password वाले दो लोगों के hash अलग हों, और आम passwords की तैयार tables काम न करें।
  • Slow on purpose: use bcrypt, scrypt or argon2id, not MD5 or plain SHA-256. Slow hashing makes guessing billions of passwords too expensive.जानबूझकर धीमा: bcrypt, scrypt या argon2id इस्तेमाल कीजिए, MD5 या सिर्फ़ SHA-256 नहीं। धीमा hashing अरबों passwords guess करना बहुत महँगा बना देता है।
// Storing passwords safely: a slow, salted hash (scrypt), never the password itself.
import { scryptSync, randomBytes, timingSafeEqual } from "node:crypto";

function hashPassword(password) {
  const salt = randomBytes(16).toString("hex");          // different for every user
  const hash = scryptSync(password, salt, 64).toString("hex");
  return `${salt}:${hash}`;                                // store this in the database
}

function checkPassword(password, stored) {
  const [salt, hash] = stored.split(":");
  const attempt = scryptSync(password, salt, 64);
  return timingSafeEqual(attempt, Buffer.from(hash, "hex"));
}

const a = hashPassword("Chai@2026");
const b = hashPassword("Chai@2026");
console.log("Same password, same hash?", a === b);         // false, thanks to the salt
console.log("Correct password:", checkPassword("Chai@2026", a));
console.log("Wrong password:", checkPassword("chai@2026", a));

Even better for most apps: let an identity provider (Keycloak, Auth0, Cognito, Firebase Auth) handle passwords, so your app never touches them.

ज़्यादातर apps के लिए और भी अच्छा: passwords को identity provider (Keycloak, Auth0, Cognito, Firebase Auth) संभाले, ताकि आपकी app उन्हें छुए ही नहीं।

MFA and passkeysMFA और passkeys

Beginnerशुरुआती

Multi-factor authentication (MFA) asks for something you know (password) plus something you have (phone app code, security key) or are (fingerprint). A stolen password alone is then not enough.

Multi-factor authentication (MFA) आपसे कुछ जो आप जानते हैं (password) और कुछ जो आपके पास है (phone app code, security key) या आप हैं (fingerprint) माँगता है। तब सिर्फ़ चोरी हुआ password काफ़ी नहीं होता।

Login protections every app needsहर app के लिए ज़रूरी login सुरक्षा

Senior levelSenior level
  • Rate-limit and slow down repeated failed logins and OTP requests.बार-बार fail होने वाले logins और OTP requests पर rate limit और देरी।
  • Show the same message for "wrong email" and "wrong password", so attackers can't find valid accounts."ग़लत email" और "ग़लत password" के लिए एक जैसा message, ताकि attackers असली accounts न ढूँढ सकें।
  • Keep sessions in HttpOnly, Secure cookies, or keep access tokens short-lived and refresh them safely.Sessions को HttpOnly, Secure cookies में रखिए, या access tokens को कम समय का रखकर सुरक्षित तरीक़े से refresh कीजिए।
  • Make password-reset links single-use and short-lived.Password-reset links एक बार इस्तेमाल होने वाले और कम समय के हों।
  • Log logins and alert on unusual ones (new country, many failures).Logins log कीजिए और असामान्य वालों पर alert (नया देश, कई failures)।
⚠️ Common mistakesआम ग़लतियाँ
  • Storing passwords with MD5 or SHA-1, or encrypting them so they can be decrypted.Passwords को MD5 या SHA-1 से रखना, या ऐसे encrypt करना कि decrypt हो सकें।
  • Putting secrets or passwords inside a JWT payload. Anyone can read it.JWT payload में secrets या passwords डालना। उसे कोई भी पढ़ सकता है।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. Hash, don't encrypt, passwords: bcrypt, scrypt or argon2id with a salt.Passwords को hash कीजिए, encrypt नहीं: salt के साथ bcrypt, scrypt या argon2id।
  2. MFA stops most stolen-password attacks; passkeys are the strongest.MFA ज़्यादातर चोरी हुए password वाले attacks रोकता है; passkeys सबसे मज़बूत हैं।
  3. Same error message for wrong email or password; rate-limit logins.ग़लत email या password पर एक जैसा message; logins पर rate limit।

Practiceप्रैक्टिस

Exercise 1: An app stores passwords as sha256(password). The database leaks. What can attackers do, and what is the fix?Exercise 1: एक app passwords को sha256(password) के रूप में रखती है। Database leak हो जाता है। Attackers क्या कर सकते हैं, और इलाज क्या है?

Show a sample answerएक sample जवाब देखें

Without salts, the same password has the same hash, and fast SHA-256 lets attackers try billions of guesses per second, so most common passwords are cracked quickly. Fix: move to a salted slow hash (bcrypt, scrypt or argon2id). Re-hash each user's password at their next login, and ask everyone to reset if the leak is confirmed.

Salt के बिना एक जैसे password का एक जैसा hash होता है, और तेज़ SHA-256 से attackers हर second अरबों guesses आज़मा सकते हैं, इसलिए ज़्यादातर आम passwords जल्दी टूट जाते हैं। इलाज: salted धीमे hash (bcrypt, scrypt या argon2id) पर जाइए। हर user का password उसके अगले login पर re-hash कीजिए, और leak पक्का हो तो सबसे reset करवाइए।

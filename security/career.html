Career roadmap: certs, labs and bug bountyCareer roadmap: certifications, labs और bug bounty

The golden rule: only test systems you own, or where you have written permission (your own lab, practice sites made for hacking, or a company's official bug bounty program). Accessing someone else's account or system without permission is a crime under India's IT Act, even if you "only looked".

सुनहरा नियम: सिर्फ़ वही systems test कीजिए जो आपके अपने हैं, या जहाँ लिखित permission है (आपकी अपनी lab, hacking सीखने के लिए बनी practice sites, या किसी company का official bug bounty program)। बिना permission किसी और का account या system खोलना भारत के IT Act के तहत अपराध है, चाहे आपने "सिर्फ़ देखा" हो।

Prices and syllabuses change, so check each provider's official site before paying. Skills and a public portfolio (write-ups, reports, a GitHub with tools) matter as much as certificates.

Prices और syllabus बदलते रहते हैं, इसलिए पैसे देने से पहले हर provider की official site देखिए। Skills और public portfolio (write-ups, reports, tools वाला GitHub) certificates जितने ही मायने रखते हैं।

How bug bounty worksBug bounty कैसे काम करता है

Senior levelSenior level
  • Expect weeks or months before your first valid bug. Most findings at first are duplicates.पहले valid bug में हफ़्ते या महीने लग सकते हैं। शुरुआत में ज़्यादातर findings duplicate होती हैं।
  • Developers do well on access-control and business-logic bugs, because they know how apps are built.Developers access-control और business-logic bugs में अच्छा करते हैं, क्योंकि वो जानते हैं apps कैसे बनती हैं।
  • If you find a bug in an Indian site with no program, report it responsibly to the company or to CERT-In. Never ask for money in exchange for silence.अगर किसी भारतीय site में bug मिले जिसका program नहीं है, तो company या CERT-In को ज़िम्मेदारी से report कीजिए। चुप रहने के बदले कभी पैसे मत माँगिए।

Exercise 1: You are a Node.js developer with 4 years of experience. Write a 3-line plan to move into application security in 6 months.Exercise 1: आप 4 साल के अनुभव वाले Node.js developer हैं। 6 महीने में application security में जाने का 3-line plan लिखिए।

Show a sample answerएक sample जवाब देखें
  • Months 1–2: finish the PortSwigger labs on access control, injection, auth and SSRF; write short notes on GitHub.महीने 1–2: PortSwigger की access control, injection, auth और SSRF labs पूरी कीजिए; GitHub पर छोटे notes लिखिए।
  • Months 3–4: do a security review of your own projects, add fixes and tests, and offer to review security in your team's pull requests.महीने 3–4: अपने projects का security review कीजिए, fixes और tests जोड़िए, और team के pull requests में security review का offer दीजिए।
  • Months 5–6: pass Security+ or eJPT, submit bug bounty reports, and apply for AppSec or DevSecOps roles.महीने 5–6: Security+ या eJPT pass कीजिए, bug bounty reports भेजिए, और AppSec या DevSecOps roles के लिए apply कीजिए।

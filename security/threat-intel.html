What is threat intelligence?Threat intelligence क्या है?

Beginnerशुरुआती

Threat intelligence means collecting information about attackers, scams and leaks, and turning it into decisions: what to block, what to fix first, who to warn. It answers questions like:

Threat intelligence का मतलब है attackers, scams और leaks की जानकारी इकट्ठा करके उसे फ़ैसलों में बदलना: क्या block करें, पहले क्या ठीक करें, किसे सावधान करें। यह ऐसे सवालों के जवाब देती है:

  • Are our customers' or employees' passwords for sale anywhere?क्या हमारे customers या employees के passwords कहीं बिक रहे हैं?
  • Is a fake website pretending to be our brand?क्या कोई नक़ली website हमारे brand का नाटक कर रही है?
  • Which attack is hitting banks like ours this month, and are we protected?इस महीने हमारे जैसे banks पर कौन-सा attack हो रहा है, और क्या हम सुरक्षित हैं?

How professionals do it safelyProfessionals इसे सुरक्षित तरीक़े से कैसे करते हैं

  • With the employer's written approval and legal guidance.Employer की लिखित मंज़ूरी और legal guidance के साथ।
  • Mostly through specialist vendors' tools and data feeds, not by browsing personally.ज़्यादातर specialist vendors के tools और data feeds से, ख़ुद browse करके नहीं।
  • When direct access is needed: an isolated machine, no personal accounts, nothing downloaded or bought, and no talking to criminals.जब सीधे access चाहिए: अलग machine, कोई personal account नहीं, कुछ download या ख़रीदना नहीं, और अपराधियों से बात नहीं।
  • Findings go to the security team, the legal team and, when needed, to CERT-In or the police.जो मिले वो security team, legal team और ज़रूरत हो तो CERT-In या police को जाता है।

Never buy leaked data, "to check it" or for research. Buying it is illegal, funds criminals, and is often a scam itself.

Leaked data कभी मत ख़रीदिए, "check करने" या research के लिए भी नहीं। ख़रीदना ग़ैरक़ानूनी है, अपराधियों को पैसा देता है, और अक्सर ख़ुद scam होता है।

Here is real threat intelligence in code: check whether a password appears in known leaks using the free Pwned Passwords API. Only the first 5 characters of the password's hash are sent, so the password itself never leaves your computer. Save as pwned.mjs and run node pwned.mjs:

Code में असली threat intelligence: free Pwned Passwords API से check कीजिए कि कोई password जाने-माने leaks में है या नहीं। Password के hash के सिर्फ़ पहले 5 characters भेजे जाते हैं, इसलिए password ख़ुद आपके computer से बाहर नहीं जाता। pwned.mjs नाम से save कीजिए और node pwned.mjs चलाइए:

// Has this password appeared in a known data leak? Uses the free Pwned Passwords API.
// Only the first 5 characters of the password's SHA-1 hash are sent, never the password.
import { createHash } from "node:crypto";

async function timesLeaked(password) {
  const hash = createHash("sha1").update(password).digest("hex").toUpperCase();
  const prefix = hash.slice(0, 5);   // sent to the API
  const suffix = hash.slice(5);      // kept on your computer
  const res = await fetch(`https://api.pwnedpasswords.com/range/${prefix}`);
  const text = await res.text();     // hundreds of lines like "SUFFIX:COUNT"
  for (const line of text.split("\n")) {
    const [s, count] = line.trim().split(":");
    if (s === suffix) return Number(count);
  }
  return 0;
}

for (const pw of ["password123", "Chai@2026", "x7#Kp!q2Lm9$wR4zT"]) {
  const n = await timesLeaked(pw);
  console.log(`${pw}: ${n > 0 ? `found in leaks ${n.toLocaleString("en-IN")} times` : "not found in known leaks"}`);
}

Output from a real run on 30 October 2026 (the numbers grow as new leaks are added):

30 अक्टूबर 2026 के एक असली run का output (नए leaks जुड़ने से numbers बढ़ते रहते हैं):

password123: found in leaks 22,66,543 times
Chai@2026: not found in known leaks
x7#Kp!q2Lm9$wR4zT: not found in known leaks

Developers can use this at sign-up and password change: "This password has appeared in a data leak. Please choose another." This exact check is a real security improvement you can add to your app this week.

Developers इसे sign-up और password बदलने पर इस्तेमाल कर सकते हैं: "यह password एक data leak में आ चुका है। कृपया दूसरा चुनिए।" यही check एक असली security सुधार है जो आप इसी हफ़्ते अपनी app में जोड़ सकते हैं।

A career in threat intelligenceThreat intelligence में career

Senior levelSenior level

This is usually not a first job. Most people come from a SOC analyst, fraud, or application security role. Useful skills:

यह आमतौर पर पहली job नहीं होती। ज़्यादातर लोग SOC analyst, fraud, या application security role से आते हैं। काम की skills:

  • Security basics, networking and Linux (see the career roadmap).Security basics, networking और Linux (career roadmap देखिए)।
  • Research and clear writing: a good analyst turns messy information into a 1-page brief a manager can act on.Research और साफ़ लिखना: अच्छा analyst उलझी जानकारी को 1 page की brief में बदलता है जिस पर manager कार्रवाई कर सके।
  • Scripting (Python or Node.js) to collect and filter data automatically.Data अपने आप इकट्ठा और filter करने के लिए scripting (Python या Node.js)।
  • Knowing MITRE ATT&CK, and reading Indian and global security advisories regularly.MITRE ATT&CK की जानकारी, और भारतीय व global security advisories नियमित पढ़ना।
⚠️ Common mistakesआम ग़लतियाँ
  • Exploring the dark web alone "to learn". It exposes you to malware, scams and legal trouble, and teaches little."सीखने के लिए" अकेले dark web घूमना। इससे malware, scams और क़ानूनी परेशानी का ख़तरा है, और सीख कम मिलती है।
  • Collecting lots of data without a question to answer. Start with "what decision will this help?"बिना किसी सवाल के ढेर सारा data इकट्ठा करना। शुरुआत कीजिए "इससे कौन-सा फ़ैसला होगा?" से।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. Collect → filter → analyse → act → report.इकट्ठा → filter → जाँच → कार्रवाई → report।
  2. Dark web monitoring looks for leaked credentials, data dumps, access sales and brand abuse.Dark web monitoring leaked credentials, data dumps, access की बिक्री और brand के ग़लत इस्तेमाल को ढूँढती है।
  3. Use legal sources: Have I Been Pwned, CERT-In, MITRE ATT&CK, vendor tools. Never buy leaked data.क़ानूनी sources इस्तेमाल कीजिए: Have I Been Pwned, CERT-In, MITRE ATT&CK, vendor tools। Leaked data कभी मत ख़रीदिए।

Practiceप्रैक्टिस

Exercise 1: Your company's monitoring tool reports: "120 employee email and password pairs found in a leak." What do you do, in order?Exercise 1: आपकी company का monitoring tool बताता है: "एक leak में 120 employees के email और password मिले।" आप क्रम से क्या करेंगे?

Show a sample answerएक sample जवाब देखें
  • Check which accounts are still active, and whether the passwords look current (without logging in to any account).देखिए कौन-से accounts अभी active हैं, और क्या passwords मौजूदा लगते हैं (किसी account में login किए बिना)।
  • Force password resets for those accounts and make sure MFA is on.उन accounts के password reset करवाइए और पक्का कीजिए कि MFA चालू है।
  • Look at login logs for suspicious sign-ins since the leak date.Leak की तारीख़ से संदिग्ध sign-ins के लिए login logs देखिए।
  • Find the source (a third-party site breach, malware on a laptop) and write a short report for management.Source ढूँढिए (किसी third-party site का breach, laptop पर malware) और management के लिए छोटी report लिखिए।

Exercise 2: Try it on yourself: check your own email address on Have I Been Pwned. If it appears, what should you change?Exercise 2: ख़ुद पर आज़माइए: Have I Been Pwned पर अपना email check कीजिए। अगर दिखे, तो क्या बदलना चाहिए?

Show a sample answerएक sample जवाब देखें

Change the password on the leaked site and on every other site where you used the same password, turn on MFA (an authenticator app is best), and start using a password manager so every site gets a different password.

Leak वाली site पर और हर उस site पर जहाँ वही password इस्तेमाल किया था, password बदलिए, MFA चालू कीजिए (authenticator app सबसे अच्छा), और password manager इस्तेमाल करना शुरू कीजिए ताकि हर site का password अलग हो।

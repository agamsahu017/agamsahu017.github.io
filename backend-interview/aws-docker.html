AWS S3AWS S3

Q1

How do you let users upload files to S3? Why pre-signed URLs?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Your API gives the browser a short-lived permission slip, and the browser uploads the file straight to S3.

🖼️ Picture it

Pre-signed URL flow:

  • The frontend asks your API: "I want to upload photo.jpg, image/jpeg, 2 MB".
  • The API checks permissions, the file type and the size, decides the key (users/42/photo-uuid.jpg), and returns a pre-signed PUT URL valid for a few minutes.
  • The browser uploads directly to S3.
  • The frontend tells the API "done" with the key; the API saves the key in the database.

Why: big files don't pass through your Node.js server (no memory or bandwidth load), the bucket stays private, and the URL works only for that key, for a short time.

import { PutObjectCommand, S3Client } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";
import { randomUUID } from "node:crypto";

const s3 = new S3Client({ region: "ap-south-1" }); // Mumbai
const ALLOWED = ["image/jpeg", "image/png", "application/pdf"];

export async function createUploadUrl(userId: number, contentType: string) {
  if (!ALLOWED.includes(contentType)) throw new Error("File type not allowed");
  const key = `users/${userId}/${randomUUID()}`;
  const url = await getSignedUrl(
    s3,
    new PutObjectCommand({ Bucket: process.env.BUCKET, Key: key, ContentType: contentType }),
    { expiresIn: 300 }, // 5 minutes
  );
  return { url, key };
}

🗣️ Say it in one line: The API validates and returns a short-lived pre-signed PUT URL; the browser uploads straight to a private bucket.

Q2

How do users download private files? Should the bucket be public?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: Keep buckets private. For downloads, give a link that works for only a few minutes.

Keep buckets private (Block Public Access on). For a download, the API checks the user may see the file, then returns a pre-signed GET URL valid for a few minutes. For public assets like a website's images, serve them through CloudFront.

Store only the key in the database, not a full URL. You can then change buckets, add a CDN, or re-sign URLs anytime.

🗣️ Say it in one line: Private bucket, permission check, then a short-lived pre-signed GET URL; the DB stores only the key.

Q3

How does your app get AWS credentials safely? How do you handle big uploads?

5–8 yrs
Show answer

🟢 In simple words: On AWS, the app gets temporary permissions from its role; no keys in code. Big files upload in parts.

Credentials: never put access keys in code or images. On AWS, use IAM roles (an ECS task role, an EC2 instance profile, or IRSA on EKS); the SDK picks them up automatically. Give least privilege: only s3:PutObject and s3:GetObject on that bucket's prefix.

Big files (over about 100 MB, or on unreliable networks): use multipart upload. The file goes in parts (5 MB minimum each, except the last), parts upload in parallel and are retried individually, and S3 joins them at the end. Add a lifecycle rule to clean up incomplete multipart uploads.

🗣️ Say it in one line: IAM roles with least privilege instead of keys, and multipart upload for big files.

Q4

Docker image vs container? Why use Docker?

3–5 yrs🔥 Very common
Show answer

🟢 In simple words: An image is a packed lunchbox (app + everything it needs). A container is that lunchbox being eaten (running).

An image is a read-only package: your app, Node.js, dependencies and config, built from a Dockerfile. A container is a running instance of an image. You can run 10 containers from one image.

Why: "it works on my machine" goes away, since dev, QA and prod run the same image. Startup is fast, it's easy to scale and roll back, and services like Postgres, Redis and Keycloak start locally with one command.

💡 Easy example: An image is a recipe printed in a book; a container is the dish cooked from it. You can cook the same dish ten times.

🗣️ Say it in one line: An image is the packaged app; a container is a running copy of it, the same everywhere.

Q5

Write a production Dockerfile for a NestJS app.

5–8 yrs🔥 Very common
Show answer

🟢 In simple words: Build in one stage, then copy only the finished app into a small, clean final image.

🖼️ Picture it

Use a multi-stage build: build with dev dependencies, then copy only the compiled dist and production dependencies into a small final image. Run as a non-root user, and copy package*.json first so the dependency layer is cached between builds.

# ---- build stage ----
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build && npm prune --omit=dev

# ---- runtime stage ----
FROM node:22-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/dist ./dist
COPY package*.json ./
USER node
EXPOSE 3000
CMD ["node", "dist/main.js"]

🗣️ Say it in one line: Multi-stage build, cached dependency layer, only dist and prod dependencies, non-root user.

↪️ Follow-up: Why node dist/main.js and not npm run start? So that node is the main process and receives SIGTERM directly for graceful shutdown; npm can get in the way of signals.

Q6

How do you handle config and secrets in containers?

5–8 yrs🔥 Very common
Show answer

🟢 In simple words: Settings come from environment variables at run time; real secrets come from a secrets manager, never from the image.

  • Never bake secrets into the image or commit .env files to git. Anyone with the image can read them.
  • Pass config as environment variables at runtime. In NestJS, use @nestjs/config and validate the variables at startup, so a missing DB_HOST fails immediately and clearly.
  • Store real secrets in AWS Secrets Manager / SSM Parameter Store (or Kubernetes secrets), injected into the task or pod.
  • Use separate values per environment (dev, QA, UAT, prod), and rotate them.

🗣️ Say it in one line: Runtime env variables validated at startup, real secrets from a secrets manager, nothing baked into images.

Q7

What are health checks? What should /health check?

5–8 yrs
Show answer

🟢 In simple words: Health checks are a doctor's check-up: liveness asks 'are you alive?', readiness asks 'can you take work now?'.

The load balancer or orchestrator calls a health endpoint to decide whether to send traffic to a container or restart it.

  • Liveness: is the process alive and not stuck? Keep it simple; don't check the DB here, or a DB blip restarts every pod.
  • Readiness: can it serve traffic now? Check the DB and Redis connections.

@nestjs/terminus provides ready-made indicators. Also log to stdout as JSON, and let the platform collect the logs (CloudWatch, ELK, Loki).

🗣️ Say it in one line: Liveness keeps it simple; readiness checks dependencies; logs go to stdout as JSON.

Q8

Describe a CI/CD pipeline for a backend service.

5–8 yrs
Show answer

🟢 In simple words: Every change is checked automatically, packed into an image, and deployed step by step, with a quick way back.

🖼️ Picture it

On every pull request: install → lint → type check → unit tests → build. On merge to main:

  • build the Docker image, tagged with the git commit SHA, and push it to a registry (ECR),
  • run migrations,
  • deploy to dev/QA automatically, and to UAT/prod with an approval,
  • use a rolling or blue-green deploy with health checks,
  • run smoke tests, and roll back automatically if errors go up.

Tools: GitHub Actions, GitLab CI, Jenkins or Azure DevOps; ECS or Kubernetes to run it.

🗣️ Say it in one line: PR checks, an immutable image tagged with the commit, migrations, staged deploys with health checks and quick rollback.

Mock task 2: Users upload Aadhaar and PAN documents. What do you take care of?

Show a sample answer

Private bucket with encryption (SSE-S3 or KMS), pre-signed URLs with short expiry, a file type and size check (and scanning the content if possible), random keys (not the Aadhaar number in the file name), access checks and audit logs for every view, masking the numbers in the UI and logs, a retention policy, and following data protection rules (India's DPDP Act).

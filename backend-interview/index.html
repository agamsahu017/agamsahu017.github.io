How interviews usually work in Delhi NCR

For 3–10 years of experience, service companies (like TCS, Infosys, Wipro, Tech Mahindra, Cognizant and Accenture) and product companies in Noida, Gurugram and Delhi usually follow a pattern like this. Many rounds are on video calls; some companies run weekend hiring drives.

RoundWhat happensHow to prepare
Recruiter / HR callNotice period, current and expected CTC, location (Noida, Gurugram, Delhi), office or hybrid, stack match.Keep exact numbers ready. Be honest: it's checked later.
Online test (sometimes)MCQs on Node.js, SQL and REST, plus 1–2 coding problems or SQL queries. More common in bulk or weekend hiring drives.Revise Node.js core and the SQL queries.
Technical round 1 (L1)Concepts and live coding: event loop output questions, an API in NestJS, SQL queries, a guard or a DTO.Do the mock tasks on each page out loud, with screen sharing.
Technical round 2 (L2) / client roundYour project's architecture, scenarios (slow API, double booking, retries, auth), and a design discussion for 6+ years. Some service-company projects add a round with the client.Prepare a 2-minute architecture story with one hard problem and numbers.
Managerial roundIncidents, estimates, deadlines, conflicts, leading juniors, working with QA and DevOps.Use STAR answers from the senior rounds module.
HR roundWhy switch, notice period, salary discussion, documents and background verification.Research the salary range first and give a range with reasons.

Every company, project and year is different. This is the common pattern we see in Noida, Gurugram and Delhi hiring for 3–10 years of experience, not an official process of any company. Kodivo is not linked to any company named here.

How to use these pages

  • Watch it step by step: diagrams have a ▶ Play button. Each step lights up with a one-line explanation, like a 1-minute video. Use Next and Back to go at your own pace.
  • Try first: read the question, answer out loud, then open the answer. Use "Show all answers" only for revision.
  • Say it in one line: every answer has a one-liner. Start with it in the interview, then explain.
  • Tested code: the Node.js output questions and SQL queries on these pages were run to confirm the results, and the NestJS, TypeORM, BullMQ, Keycloak and S3 examples were type-checked against the real libraries.
  • Use your project: after each answer, add "In my project, we used this for..." That is what makes an experienced answer.
  • Frontend too? Full-stack roles get React questions as well; see the Frontend Interview series.

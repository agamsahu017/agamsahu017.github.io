Backend Interview: hard words, simply explained

97 words used in the answers, each in one or two simple lines. On the question pages, these words have a dotted underline; tap them to see the meaning.

Node.js

Thread
A worker that runs code. Node.js runs your JavaScript on one main thread.
Non-blocking I/O
Starting slow work (DB, files) and moving on instead of waiting for it.
I/O
Input/output: reading or writing files, network or database.
Event loop
The manager that keeps running ready callbacks on Node's one main thread.
Blocking
Code that keeps the main thread busy so nothing else can run.
libuv
The C library inside Node.js that handles the event loop and the thread pool.
Thread pool
A small team of helper threads (4 by default) for files, crypto and compression.
Callback
A function handed over to be called when something finishes.
Microtask
A small urgent job (like a promise callback) that runs before the next phase.
Stream
Data processed piece by piece instead of all at once.
Backpressure
Slowing the reader down when the writer can't keep up.
Heap snapshot
A photo of everything in memory at one moment, used to find leaks.
Memory leak
Memory that keeps growing because it's never released.
SIGTERM
A polite 'please stop' signal sent before a container is shut down.
Graceful shutdown
Finishing current work and closing connections before exiting.

Deployment

Container
A running, packaged copy of your app with everything it needs.
Orchestrator
A system like Kubernetes or ECS that starts, stops and restarts containers.

API design

Resource
A thing your API manages, like an employee or an order.
Stateless
The server doesn't remember you between requests; each request carries what's needed.
Idempotent
Doing it twice gives the same result as doing it once.
Payload
The data inside a request, response or token.
Pagination
Returning a big list in small pages.
Rate limiting
Allowing only a certain number of requests per minute.
Webhook
Another system calling your URL to tell you something happened.

NestJS

Dependency injection
The framework hands a class the tools it needs instead of the class creating them.
Provider
Anything Nest can create and inject, usually a service.
Singleton
Only one shared instance for the whole app.
Decorator
An @label on a class or method that adds behaviour, like @Get() or @Roles().
Middleware
Code that runs on every request before routing, like logging.
Guard
A checkpoint that decides if a request may continue.
Pipe
Checks and converts incoming data before it reaches the handler.
DTO
Data Transfer Object: a class describing the allowed shape of request data.
Exception filter
Catches thrown errors and builds the error response.
Metadata
Extra labels attached to code, read later (for example by a guard).
Mock
A pretend version of a dependency, used in tests.

Databases

Index
A sorted lookup structure that lets the database jump to rows quickly.
Sequential scan
Reading every row of a table, one by one.
Transaction
A group of changes that all succeed or all fail together.
ACID
Atomic, Consistent, Isolated, Durable: the promises of a safe transaction.
Isolation level
How much transactions running at the same time can see of each other.
MVCC
Multi-Version Concurrency Control: readers see a snapshot, so they don't block writers.
Deadlock
Two transactions waiting for each other forever.
Window function
A calculation across related rows (like rank) that keeps each row.
Connection pool
A set of open DB connections shared and reused by requests.
ORM
Object-Relational Mapper: lets you use classes instead of writing SQL by hand.
Entity
A class that maps to a database table.
Foreign key
A column pointing to a row in another table.
N+1 problem
One query for a list, then one more query for every row.
Migration
A versioned script that changes the database structure safely.
Optimistic locking
Using a version number to detect if someone else changed a row first.
Read replica
A read-only copy of the database for reports and heavy reads.
Replication lag
How far behind the copy (replica) is from the main database.
Schema
The planned structure of your data: tables, columns and types.
Sharding
Splitting data across many database servers.

Redis and queues

TTL
Time To Live: how long a cached value is kept before it expires.
Cache stampede
Many requests rebuilding the same expired cache at once.
Distributed lock
A lock shared by all copies of a service, so only one does a job.
Queue
A waiting line of jobs to be done in the background.
Worker
A process that picks jobs from a queue and does them.
Exponential backoff
Waiting longer after each failure before retrying: 2 s, 4 s, 8 s…
Dead letter queue
A place for jobs that failed every retry, kept for checking.
At-least-once
A job is never lost, but it might run more than once.

Auth and security

Authentication
Checking who you are.
Authorization
Checking what you are allowed to do.
JWT
JSON Web Token: a signed pass with user details that anyone can read but nobody can change.
JWKS
The public keys a login server publishes, used to check token signatures.
Claims
The facts inside a token, like user id, roles and expiry.
OAuth2
A standard for letting apps get access tokens safely.
OIDC
OpenID Connect: adds 'who is the user' (login) on top of OAuth2.
PKCE
A safety check that protects the login code exchange in browser and mobile apps.
Realm
A separate space in Keycloak with its own users and roles.
RBAC
Role-Based Access Control: what you can do depends on your role.
IDOR
A bug where changing an id in the URL shows someone else's data.
Salt
Random data added before hashing so the same password gives different hashes.
Password hash
A one-way fingerprint of data; you can't turn it back into the original.
SQL injection
An attack where user input is run as part of a SQL query.

Cloud

Pre-signed URL
A temporary link that allows one upload or download from a private bucket.
Bucket
A top-level folder in S3 where files are stored.
IAM role
AWS permissions given to a service, without storing passwords or keys.
Least privilege
Giving only the exact permissions needed, nothing more.
Multipart upload
Uploading a big file in parts that S3 joins together.
CDN
A network of servers near users that serves files fast.
Docker image
A packaged, read-only copy of your app and everything it needs.
CI/CD
Automatic checks on every change (CI) and automatic deploys (CD).
Rollback
Going back to the previous working version.

System design

Load balancer
Spreads incoming requests across several servers.
Microservices
Splitting one app into many small services that deploy separately.
Monolith
One app that is built and deployed as a single unit.
Circuit breaker
Stops calling a failing service for a while, so failures don't spread.
Outbox pattern
Saving an event in the same DB transaction, then sending it reliably.
Observability
Being able to see what's happening inside a running system.
p95 latency
95% of requests are faster than this time.
Post-mortem
A write-up after an incident: what happened and how to prevent it.

Interview

STAR method
Situation, Task, Action, Result: a simple way to tell a work story.
CTC
Cost To Company: your total yearly salary package.
Notice buyout
The new company pays your old company so you can leave before the notice period ends.
BGV
Background verification: checks of your past jobs, salary and documents.

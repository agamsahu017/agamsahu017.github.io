First, a real-life exampleपहले, एक असली ज़िंदगी का उदाहरण

Imagine you want to find a friend's number in your phone. There are three ways:

मान लीजिए आपको फ़ोन में किसी दोस्त का नंबर ढूँढना है। तीन तरीक़े हैं:

  • Favourites: the number is pinned at the top. You find it in 1 step, however many contacts you have.Favourites: नंबर सबसे ऊपर pinned है। Contacts चाहे कितने भी हों, 1 step में मिल जाता है।
  • Search by name: contacts are sorted, so you jump to the right letter and keep cutting the list in half. Very few steps.नाम से search: contacts sorted हैं, तो आप सही अक्षर पर पहुँचते हैं और list को आधा-आधा करते जाते हैं। बहुत कम steps।
  • Scroll one by one: with 1,000 contacts, you may need 1,000 steps.एक-एक करके scroll: 1,000 contacts हों तो 1,000 steps भी लग सकते हैं।

Big-O tells us how the number of steps grows when the input grows. It does not measure seconds. It measures the growth.

Big-O बताता है कि input बढ़ने पर steps की गिनती कैसे बढ़ती है। यह seconds नहीं नापता। यह बढ़ने की रफ़्तार नापता है।

Interviewers ask about Big-O in almost every coding round, because it shows whether your solution will still work when there are millions of users.

लगभग हर coding round में Big-O पूछा जाता है, क्योंकि इससे पता चलता है कि करोड़ों users होने पर भी आपका solution चलेगा या नहीं।

How to find the Big-O of any codeकिसी भी code का Big-O कैसे निकालें

Rule 1: One loop over n items = O(n)Rule 1: n items पर एक loop = O(n)

function printAll(arr) {
  for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]); // runs n times
  }
}
// Time: O(n)

Rule 2: Nested loops multiplyRule 2: Nested loops गुणा होते हैं

function printPairs(arr) {
  for (let i = 0; i < arr.length; i++) {      // n times
    for (let j = 0; j < arr.length; j++) {    // n times for each i
      console.log(arr[i], arr[j]);
    }
  }
}
// Time: O(n * n) = O(n²)

Rule 3: Loops one after another add upRule 3: एक के बाद एक loops जुड़ते हैं

function twoLoops(arr) {
  for (const x of arr) console.log(x);  // O(n)
  for (const x of arr) console.log(x);  // O(n)
}
// Time: O(n + n) = O(2n) = O(n)

Rule 4: Drop constants and smaller termsRule 4: Constants और छोटे terms हटा दो

  • O(2n) becomes O(n). O(500) becomes O(1).O(2n) बन जाता है O(n)। O(500) बन जाता है O(1)।
  • O(n² + n) becomes O(n²), because n² grows much faster than n.O(n² + n) बन जाता है O(n²), क्योंकि n² बहुत तेज़ी से बढ़ता है।

Rule 5: Halving each step = O(log n)Rule 5: हर step में आधा = O(log n)

function countHalvings(n) {
  let steps = 0;
  while (n > 1) {
    n = Math.floor(n / 2); // cut in half
    steps++;
  }
  return steps;
}
// n = 1,000 needs only about 10 steps. Time: O(log n)

Only 9 steps for 1,000. For 10 lakh it would be about 20. That's the power of O(log n).

1,000 के लिए सिर्फ़ 9 steps। 10 लाख के लिए लगभग 20। यही O(log n) की ताक़त है।

Rule 6: Different inputs get different lettersRule 6: अलग inputs के लिए अलग अक्षर

function printBoth(a, b) {
  for (const x of a) {
    for (const y of b) console.log(x, y);
  }
}
// Time: O(a * b), not O(n²)

Hidden loops in JavaScript: includes(), indexOf(), slice(), splice(), shift() and the spread [...arr] are all O(n). A loop that calls arr.includes() inside is O(n²).

JavaScript के छिपे हुए loops: includes(), indexOf(), slice(), splice(), shift() और spread [...arr] सब O(n) हैं। अगर loop के अंदर arr.includes() चलाया, तो वो O(n²) हो गया।

Space complexity: how much extra memory?Space complexity: कितनी extra memory?

Space complexity counts the extra memory your code creates, not the input itself.

Space complexity उस extra memory को गिनती है जो आपका code बनाता है, input को नहीं।

// O(1) extra space: only a few variables
function sum(arr) {
  let total = 0;
  for (const x of arr) total += x;
  return total;
}

// O(n) extra space: a new array as big as the input
function doubled(arr) {
  const result = [];
  for (const x of arr) result.push(x * 2);
  return result;
}

Recursion also uses space: each call waits on the call stack. A recursion that goes n levels deep uses O(n) space.

Recursion भी space लेता है: हर call call stack पर इंतज़ार करता है। n levels गहरी recursion O(n) space लेती है।

How to talk about Big-O in an interviewInterview में Big-O के बारे में कैसे बोलें

  • Always give both time and space complexity, without being asked.बिना पूछे, हमेशा time और space दोनों बताइए।
  • Start with the brute force solution and its Big-O, then improve it.पहले brute force solution और उसका Big-O बताइए, फिर उसे बेहतर कीजिए।
  • Explain why: "we visit each element once" is better than just saying "O(n)".क्यों बताइए: सिर्फ़ "O(n)" कहने से बेहतर है "हम हर element को एक बार देखते हैं"।
  • Big-O usually means the worst case. Mention best or average case only if it matters.Big-O आमतौर पर worst case होता है। Best या average case तभी बताइए जब ज़रूरी हो।

🎤 Say it like this: "My first idea is two nested loops, which is O(n²) time. I can improve it with a hash map, so I visit each element only once. That makes it O(n) time and O(n) extra space."

🎤 ऐसे बोलिए: "My first idea is two nested loops, which is O(n²) time. I can improve it with a hash map, so I visit each element only once. That makes it O(n) time and O(n) extra space." (Interview अंग्रेज़ी में हो तो यही लाइन बोलें।)

⚠️ Common mistakesआम ग़लतियाँ
  • Thinking Big-O measures seconds. It measures how the work grows with input size.यह सोचना कि Big-O seconds नापता है। यह नापता है कि input बढ़ने पर काम कैसे बढ़ता है।
  • Calling two separate loops O(n²). One after another is O(n + n) = O(n). Only nested loops multiply.दो अलग-अलग loops को O(n²) कहना। एक के बाद एक हों तो O(n + n) = O(n)। सिर्फ़ nested loops गुणा होते हैं।
  • Missing hidden loops like includes() or shift() inside a loop.Loop के अंदर includes() या shift() जैसे छिपे loops को न पहचानना।
  • Giving only time complexity and forgetting space complexity.सिर्फ़ time complexity बताना और space complexity भूल जाना।

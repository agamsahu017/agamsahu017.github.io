Extra: Blockchain Basics (just enough for interviews)

Why this file: your LinkedIn (Chetu) mentions ERC-20 tokens, Coinbase Wallet, Web3.js and basic smart contracts. Interviewers may ask 2–3 questions to check it's real. Revise this in 1–2 hours. Don't go deeper unless you target a Web3 company.

One-line summary

Blockchain = a shared ledger copied on many computers that nobody can secretly edit → smart contracts = code stored on the blockchain that runs automatically → tokens (ERC-20 = identical coins, ERC-721 = unique NFTs) are built with smart contracts → wallets (MetaMask, Coinbase Wallet) hold your keys and sign transactions → Web3.js / Ethers.js let your JS app talk to the blockchain.

1. What is a blockchain?

A ledger (record book) shared across thousands of computers. Every new set of transactions is a block, and each block stores the hash of the previous block, forming a chain.

  • Analogy: a society maintenance register that every member has a photocopy of. If one person changes their copy, it won't match everyone else's, so the fake is caught.
  • If someone changes an old block, its hash changes, the chain breaks, and the network rejects it → immutable.

🎤 "A blockchain is a distributed, append-only ledger. Each block contains the previous block's hash, so changing history breaks the chain, and the network agrees on the valid chain through consensus."

2. Key properties

  • Decentralized: no single owner (no bank in the middle)
  • Immutable: past records can't be changed
  • Transparent: anyone can view transactions (e.g. on Etherscan)
  • Trustless: you trust the code and maths, not a middleman

3. Consensus: how everyone agrees

  • Proof of Work (PoW): miners solve a hard maths puzzle; the winner adds the block. Very secure, uses huge electricity (Bitcoin).
  • Proof of Stake (PoS): validators lock ("stake") their coins; they're chosen to add blocks and lose coins if they cheat. Far less energy. Ethereum moved to PoS in 2022 ("The Merge").

4. Bitcoin vs Ethereum

Bitcoin Ethereum
Digital money only A "world computer": money + smart contracts
Can't run apps Runs apps (DeFi, NFTs, tokens)
PoW PoS

5. Smart contract

Code stored on the blockchain that runs automatically when conditions are met. Once deployed, it can't be changed (unless designed to be upgradeable).

  • Analogy: a vending machine: put in money + choose item → item comes out. No shopkeeper needed.
  • Written in Solidity (Ethereum's language, looks a bit like JavaScript/TypeScript).
  • Runs on the EVM (Ethereum Virtual Machine).
// very basic example
contract Counter {
    uint public count;
    function increment() public { count += 1; }
}

🎤 "A smart contract is a program deployed on the blockchain that executes automatically. In my project, tokens representing real-estate shares were ERC-20 smart contracts."

6. Gas

The fee you pay to run a transaction or contract function on Ethereum (paid in ETH). Every write to the blockchain costs gas; reading is free.

  • Complex code = more gas. That's why smart contracts are kept small and simple.

7. Tokens: ERC-20 vs ERC-721 (NFT) ⭐ most asked

ERC-20 ERC-721 (NFT)
Fungible: every token is identical (like ₹10 notes) Non-fungible: each token is unique (like a property deed or a painting)
Used for: currencies, shares, fractional real estate Used for: art, game items, collectibles (ORE Forge game items)
Main functions: totalSupply, balanceOf, transfer, approve, transferFrom, allowance Main functions: ownerOf, transferFrom, safeTransferFrom, tokenURI

Connect to your projects:

  • Salcedo (real estate): a property is split into, say, 1,000 ERC-20 tokens. Buying 10 tokens = owning 1% of the property. Total token value = property value.
  • ORE System (NFT): each in-game item (a sword, a skin) is a unique ERC-721 NFT that players can trade.

ERC-1155 (bonus): one contract that holds both fungible and non-fungible tokens, popular in games.

8. Wallet, public key, private key

  • Wallet (MetaMask, Coinbase Wallet): an app that holds your keys and signs transactions.
  • Public key / address = like your bank account number. Share it freely.
  • Private key / seed phrase = like your ATM PIN + password. Never share it; whoever has it owns the funds. The wallet doesn't "store coins": the coins live on the blockchain, the wallet holds the keys.

9. How your Coinbase Wallet integration works (be ready to explain)

  1. User clicks "Connect Wallet" → the app asks Coinbase Wallet for permission → you get the user's address.
  2. App creates a transaction (e.g. pay X ETH to buy tokens, or call the contract's buy function).
  3. The wallet pops up, the user reviews it and signs (your app never sees the private key).
  4. Transaction is sent to the network → you get a transaction hash → wait for confirmation.
  5. Backend checks the transaction status (on-chain) before updating your database / showing "purchase successful".

🎤 "I integrated Coinbase Wallet with Web3.js: connect wallet, get the user's address, build the transaction, let the wallet sign it, then confirm it on-chain before updating our database."

10. Web3.js / Ethers.js

JavaScript libraries that let your frontend/backend talk to Ethereum: read balances, call contract functions, send transactions.

  • To call a contract you need its address + ABI (a JSON describing its functions, like a Swagger file for the contract).
  • Ethers.js is more popular today; Web3.js is older (you used this one).

11. Other common terms

  • Testnet (Sepolia): a free practice blockchain for testing, with fake ETH.
  • Etherscan: a website to view any transaction, address or contract.
  • dApp: decentralized app = normal frontend + smart contracts as the backend.
  • DeFi: banking-like services (loans, trading) run by smart contracts.
  • Oracle (e.g. Chainlink): brings outside data (prices, weather) into smart contracts, since contracts can't call APIs themselves.
  • Layer 2 (Polygon, Arbitrum): faster, cheaper networks built on top of Ethereum.
  • Tokenization: turning a real-world asset (property, gold) into tokens.

12. Downsides (shows maturity)

  • Slow and costly compared to a normal database (gas fees, confirmation time)
  • Bugs in smart contracts are permanent and can lose money (hacks happen)
  • Regulation is unclear in many countries (India: 30% tax + 1% TDS on crypto)
  • Most apps don't need a blockchain. A normal database is better when you trust one owner.

🎤 "I'd use blockchain only when multiple parties who don't trust each other need a shared, tamper-proof record. Otherwise a normal database is faster, cheaper and simpler." (Interviewers love this answer.)

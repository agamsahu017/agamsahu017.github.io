Level 4: How LLMs Work (Interview Theory)

You will not build models, but interviewers ask these to check your depth. Goal: explain each one in 2 or 3 clear sentences.

In one line

A Transformer reads all tokens together and uses attention to decide which words matter to each other → it is pre-trained on huge text to guess the next token → fine-tuned on good question-answer examples → improved with RLHF so it is helpful and safe → parameters are what it learned → quantization makes it smaller and cheaper → open-weight models you run yourself, closed models you use through an API.

1. Transformer

The design behind almost all modern LLMs (from Google's 2017 paper "Attention Is All You Need").

  • Older models (RNNs) read text one word at a time, like reading with a finger. They were slow and forgot early words.
  • A Transformer looks at all tokens at once. So training is faster, and it handles long text better.
  • Chat models like GPT and Claude write one token at a time, and each new token depends on everything before it ("decoder-only").

🎤 "A Transformer reads all tokens at the same time and uses attention to link them. Chat models like GPT and Claude are Transformers that write one token at a time."

2. Attention (self-attention)

How the model decides which other words matter for understanding each word.

"The broker called the client because HE was late."
   → "he" looks strongly at "broker" (or "client"), weakly at "called".
"She sat on the bank of the river" vs "She put money in the bank"
   → "bank" looks at "river" (river bank) vs "money" (money bank).
  • Each word gets a score with every other word: high score = "this matters for my meaning".
  • Multi-head attention: many attention "views" at the same time (one follows grammar, one follows meaning, and so on).
  • Positional encoding: because all words are read together, the model adds position numbers so it knows the word order.

🎤 "Self-attention lets each token look at every other token, so the model understands words from their context, like what 'he' or 'bank' means."

Why it matters to you: every token is compared with every other token, so cost grows fast with longer text. That is why long prompts are slower and cost more.

3. Parameters

The numbers (weights) the model learned in training: its "knowledge and skill".

  • "7B model" = 7 billion parameters. More parameters usually means smarter, but also slower and costlier to run.
  • Example: parameters are like connections in a brain; training adjusts them.

4. How an LLM is built: 3 stages

Stage What happens Example
1. Pre-training Reads a huge amount of text and learns to guess the next token. The costliest stage. A child who read the whole library: knows a lot, but does not know how to behave in an interview
2. Fine-tuning (instruction tuning) Trained on examples of good question → answer pairs Coaching: "When someone asks this, answer like this"
3. Alignment (RLHF and similar) People compare answers; the model learns to prefer helpful, honest, safe ones A mentor saying: "This answer is better than that one"

RLHF (Reinforcement Learning from Human Feedback)

  1. The model writes a few answers to the same question.
  2. People rank them from best to worst.
  3. A reward model learns what people like.
  4. The LLM is trained to write answers that the reward model scores high.

There are newer methods too (like DPO, and Anthropic's Constitutional AI, which uses written rules plus AI feedback), but the idea is the same: make the model give answers people actually want.

🎤 "LLMs first learn to guess the next token from huge text, then learn from good question-answer examples, then learn from human ratings (like RLHF), so they are helpful and safe, not just fluent."

5. Fine-tuning (as a developer)

Training an existing model more on your own examples.

  • Full fine-tuning: change all parameters. Costly, needs big GPUs.
  • LoRA: train only small add-on parts and keep the rest frozen. Much cheaper. Most teams do this.
  • When to fine-tune: to fix a style, format or special behaviour (always reply in a strict JSON format, a brand's tone, sorting texts into fixed groups).
  • When NOT to: to add facts that change. Use RAG for that (see Level 2).

🎤 "I try a good prompt first, then RAG for facts, and fine-tune only for a fixed behaviour or format, usually with LoRA to keep the cost low."

Order to remember: Prompt → RAG → Fine-tune (cheapest to costliest).

6. Quantization

Storing the model's numbers with fewer bits (16-bit → 8-bit or 4-bit).

  • ✅ Smaller, faster, cheaper: runs on smaller GPUs or even laptops
  • ❌ A little quality loss
  • Example: saving a photo as JPEG instead of RAW. Much smaller, and it looks almost the same.

7. Open-weight vs closed models

Closed (API) Open-weight (run it yourself)
Examples Claude, GPT, Gemini Llama, Mistral, Qwen, Gemma
How you use it Call an API Download it and run it on your own servers
✅ Good Best quality, no servers to manage, quick start Data stays with you, full control, can fine-tune, cheaper at very large scale
❌ Bad Pay per token, data goes to the provider You manage GPUs, scaling and updates
Best for Most startups and small business apps (like Kodivo) Strict privacy (hospitals, banks), very large volume

🎤 "I would start with an API model for speed and quality. I would move to an open-weight model only when data privacy, cost at large scale or deep changes make the extra work worth it."

8. Multimodal

Models that understand more than text: images, audio, PDFs, video.

  • Kodivo examples: read a photo of a bill (for CA firms), understand a WhatsApp voice note order (for wholesalers), read a property brochure PDF (for real estate).

9. Speed basics (bonus)

  • The answer is written token by token, so long answers take longer. That is why we stream answers (show them as they are written).
  • Time to first token = how fast the user sees the answer start. This matters more to users than the total time.
  • Ways to cut cost and time: shorter prompts, smaller models for easy tasks, caching repeated prompts, and sending only the useful RAG pieces.

Interview questions (answer out loud)

  1. What is a Transformer, and why did it replace RNNs?
  2. Explain self-attention with an example.
  3. What are the stages of training an LLM?
  4. What is RLHF, and why is it needed?
  5. Prompt vs RAG vs fine-tuning: how do you choose?
  6. What is LoRA?
  7. What is quantization, and what do you lose?
  8. When would you choose an open-weight model over an API model?
  9. How would you cut the time and cost of an LLM feature?

Quiz

  1. "Bank" means river bank in one sentence and money bank in another. What helps the model tell them apart?
  2. A client wants the bot to always reply in their brand's exact tone and format. The facts don't change. RAG or fine-tuning?
  3. A hospital says patient data cannot leave their servers. API model or open-weight model? Why?

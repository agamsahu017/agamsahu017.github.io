Level 4: How LLMs Work (Interview Theory)

You won't build models, but interviewers ask these to check depth. Aim: explain each in 2–3 clear sentences.

One-line summary

A Transformer reads all tokens together and uses attention to decide which words matter to each other → it's pre-trained on huge text to predict the next token → fine-tuned on instruction examples → aligned with RLHF so it's helpful and safe → parameters are what it learned → quantization makes it smaller and cheaper → open-weight models you host yourself, closed models you call by API.

1. Transformer

The architecture behind almost all modern LLMs (from Google's 2017 paper "Attention Is All You Need").

  • Older models (RNNs) read text one word at a time, like reading with a finger: slow, and they forget early words.
  • A Transformer looks at all the tokens at once (in parallel). That makes training fast, and it handles long text better.
  • GPT-style chat models use the decoder-only variant: they generate text one token at a time, each new token based on everything before it.

🎤 "A Transformer processes all tokens in parallel and uses self-attention to model relationships between them. LLMs like GPT and Claude are decoder-only Transformers that generate one token at a time."

2. Attention (self-attention)

How the model decides which other words matter when understanding each word.

"The broker called the client because HE was late."
   → "he" pays strong attention to "broker" (or "client"), weak attention to "called".
"Bank ke kinare baithe" vs "Bank mein paise jama kiye"
   → "bank" attends to "kinare" (river bank) vs "paise" (money bank).
  • Each word gets a score against every other word: high score = "this matters for my meaning".
  • Multi-head attention: several attention "views" in parallel (one tracks grammar, another meaning, another references).
  • Positional encoding: since all words are read together, the model adds position info so it knows word order.

🎤 "Self-attention lets each token weigh every other token in the context, so the model captures meaning from context, like resolving what 'he' or 'bank' refers to."

Why it matters to you: attention compares every token with every other token, so cost grows quickly with context length. That's why long prompts are slower and costlier.

3. Parameters

The numbers (weights) the model learned during training: its "knowledge and skill".

  • "7B model" = 7 billion parameters. More parameters usually means more capable, but also slower and more expensive to run.
  • Analogy: parameters are the brain's connections; training adjusts them.

4. How an LLM is built: the 3 stages

Stage What happens Analogy
1. Pre-training Reads a huge amount of text and learns to predict the next token. Most expensive stage. A child reading the whole library: knows a lot, but doesn't know how to behave in an interview
2. Fine-tuning (SFT / instruction tuning) Trained on examples of good question → answer pairs Coaching: "When someone asks this, answer like this"
3. Alignment (RLHF and similar) Humans compare answers; the model learns to prefer helpful, honest, safe ones A mentor giving feedback: "This answer is better than that one"

RLHF (Reinforcement Learning from Human Feedback)

  1. The model writes several answers to the same prompt.
  2. Humans rank them (best → worst).
  3. A reward model learns to predict what humans prefer.
  4. The LLM is trained to produce answers the reward model scores highly.

Newer alternatives exist (e.g. DPO, and Anthropic's Constitutional AI, which uses written principles plus AI feedback), but the idea is the same: align the model with what people actually want.

🎤 "LLMs are pre-trained on large text corpora with next-token prediction, then instruction-tuned on curated examples, then aligned using human preference feedback such as RLHF, so they're helpful and safe rather than just fluent."

5. Fine-tuning (as a developer)

Training an existing model further on your own examples.

  • Full fine-tuning: update all parameters. Expensive, needs big GPUs.
  • LoRA / PEFT: train only small add-on layers ("adapters") and freeze the rest. Much cheaper, and this is what most teams do.
  • When to fine-tune: to fix a style, format or specialised behaviour (e.g. always reply in a strict JSON schema, a brand tone, a domain-specific classification).
  • When NOT to: to add knowledge that changes. Use RAG for that (see Level 2).

🎤 "I'd try prompt engineering first, then RAG for knowledge, and fine-tune only for consistent behaviour or format, usually with LoRA to keep costs low."

The order to remember: Prompt → RAG → Fine-tune (cheapest to most expensive).

6. Quantization

Storing the model's numbers with less precision (e.g. 16-bit → 8-bit or 4-bit).

  • ✅ Smaller, faster, cheaper: can run on smaller GPUs or even laptops
  • ❌ Slight quality loss
  • Analogy: compressing a photo from RAW to JPEG. Much smaller, and it looks almost the same.

7. Open-weight vs closed models

Closed (API) Open-weight (self-hosted)
Examples Claude, GPT, Gemini Llama, Mistral, Qwen, Gemma
How you use it Call an API Download and run on your own servers
✅ Pros Best quality, no infrastructure, fast to start Data stays with you, full control, can fine-tune, cost control at large scale
❌ Cons Per-token cost, data goes to the provider You manage GPUs, scaling and updates
Best for Most startups and SMB apps (like Kodivo) Strict data privacy (hospitals, banks), very high volume

🎤 "I'd start with a closed API for speed and quality, and consider open-weight models when data residency, cost at scale or deep customisation justify the operational overhead."

8. Multimodal

Models that understand more than text: images, audio, PDFs, video.

  • Kodivo examples: read a photo of a bill (for CA firms), understand a WhatsApp voice note order (wholesalers), read a property brochure PDF (real estate).

9. Latency basics (bonus)

  • Output is generated token by token, so long answers take longer. That's why we stream responses.
  • Time to first token = how fast the user sees the response start. It matters more for UX than total time.
  • Ways to cut cost and latency: shorter prompts, smaller models for simple tasks, caching repeated prompts, and sending only relevant RAG chunks.

  2. Explain self-attention with an example.
  3. What are the stages of training an LLM?
  4. What is RLHF, and why is it needed?
  5. Prompt engineering vs RAG vs fine-tuning: how do you choose?
  6. What is LoRA?
  7. What is quantization, and what's the trade-off?
  8. When would you choose an open-weight model over an API model?
  9. How would you reduce latency and cost in an LLM feature?

Quiz

  1. "Bank" means river bank in one sentence and money bank in another. Which mechanism helps the model tell them apart?
  2. A client wants the bot to always reply in their brand's exact tone and format. Knowledge doesn't change. RAG or fine-tuning?
  3. A hospital says patient data can't leave their servers. Closed API or open-weight model? Why?

Level 3: Tool Calling, AI Agents and MCP ⭐

The problem

An LLM alone can only talk. It cannot check a database, book an appointment, send a WhatsApp message or even know today's date. Tool calling gives it hands. An agent uses those hands step by step to finish a goal.

In one line

Tool calling = the LLM asks your code to run a function → an agent = an LLM in a loop that keeps picking tools until the goal is done → MCP = one standard plug to connect tools to any AI app.

1. Tool calling (function calling)

You tell the LLM which functions you have. When it needs one, it replies with "call this function with these inputs" (as JSON). Your code runs it and sends the result back. Then the LLM writes the final answer.

Tools you give the LLM:
  getAvailableSlots(date)
  bookSiteVisit(name, phone, propertyId, slot)

User: "I want to see the 3BHK in Sector 150 tomorrow"
LLM → { tool: "getAvailableSlots", args: { date: "2026-10-19" } }   ← the LLM only ASKS
Your code → runs the database query → ["11:00", "16:00"]            ← YOUR code runs it
LLM → "Tomorrow at 11 AM or 4 PM. Which time works for you?"

Key point: the model never runs anything itself. It only asks. Your backend decides and runs it. That is where you add checks and permissions.

Example: a hotel guest calls reception: "Send a pizza to room 204." The receptionist (LLM) only passes the order; the kitchen (your code) decides if it can make it and actually cooks it.

🎤 "With tool calling, the model sends back a request to run one of my functions. My app runs it and returns the result. The model decides what to call; my code decides whether and how it runs."

2. AI agent

An LLM running in a loop: think → act (call a tool) → look at the result → repeat until the goal is done.

Goal: "Check this lead and book a site visit"

Loop 1: Think: budget not known        → Act: ask the user's budget  → Result: "1.5 Cr"
Loop 2: Think: any matching property?  → Act: searchProperties(...)  → Result: 2 options
Loop 3: Think: need a time slot        → Act: getAvailableSlots()    → Result: 11:00, 16:00
Loop 4: Think: user chose 4 PM         → Act: bookSiteVisit(...)     → Result: booked ✅
Loop 5: Think: tell the broker         → Act: notifyBroker(...)      → Done

Real example: Claude Code is an agent. It reads files, runs commands, checks the output and decides the next step by itself. Everyday version: a travel agent who first checks flights, then picks a hotel that fits the flight, then books a cab.

🎤 "An agent is an LLM that plans and does a task in many steps. It calls tools in a loop and uses each result to choose the next step, until the goal is done."

3. Chatbot vs workflow vs agent

Chatbot Workflow Agent
What it does Answers questions Fixed steps that you write (step 1 → 2 → 3) Chooses the steps itself
Flexible? Low Medium High
Easy to predict? High High Lower
Example FAQ bot "New lead → send message → add to CRM" "Check this lead and book a visit, however it takes"

Senior tip: don't use an agent when a workflow is enough. Workflows are cheaper, faster and easier to fix. Use agents only when the steps really change each time.

Example: the milkman takes the same route every day (workflow). An ambulance driver picks a new route each time based on traffic (agent).

4. Memory

  • Short-term: the current chat (inside the context window).
  • Long-term: facts saved across chats (stored in your database, found again with RAG). For example: "This lead wanted a 3BHK under 1.5 Cr last week."

Example: short-term = what you remember during a phone call. Long-term = the shopkeeper's diary of regular customers ("Sharma ji always takes Amul butter").

5. Multi-agent

Several agents, each with its own job, tools and prompt, working together. Example: Qualifier agent (asks questions) → Property agent (searches listings) → Scheduler agent (books visits). Useful for big systems, but it costs more and is harder to manage. Start with one agent.

Example: a hospital: the reception desk, the doctor and the billing counter each do one job and pass the patient along.

6. MCP (Model Context Protocol)

An open standard (made by Anthropic in 2024) for connecting AI apps to tools and data.

  • Before MCP: every AI app needed its own connection code for every tool.
  • With MCP: build an MCP server once (for example "Kodivo CRM"), and any AI app that supports MCP (Claude, code editors, agents) can use it.
  • Example: USB-C for AI. One plug, many devices.

🎤 "MCP is an open standard for connecting AI apps to tools and data. You build a tool once as an MCP server, and any MCP app can use it."

7. Safety checks (needed in a live app)

Agents can make mistakes, so in a live app:

  • Check tool inputs (is the phone number valid? does the slot exist?)
  • Permissions: the agent can read listings but cannot delete them
  • Human approval for risky actions (refunds, payments, bulk messages)
  • Step limit and timeout so the loop cannot run forever (and waste money)
  • Log every tool call, for fixing bugs and for audits
  • Evals: test the agent on sample chats before every release

Example: a new driver. You give them a company car (access), a route limit (step limit), a fuel card with a spending cap (permissions), a GPS log (logging), and big trips need the manager's OK (human approval).

🎤 "In a live app I would check tool inputs, give only the access needed, ask a human before actions that can't be undone, limit the steps, log every tool call, and run evals."

Level 3: Tool Calling, AI Agents और MCP ⭐

समस्या

अकेला LLM सिर्फ़ बात कर सकता है। यह database check नहीं कर सकता, appointment book नहीं कर सकता, WhatsApp message नहीं भेज सकता, यहाँ तक कि आज की तारीख भी नहीं जानता। Tool calling इसे हाथ देता है। Agent इन हाथों से एक-एक step करके goal पूरा करता है।

एक line में

Tool calling = LLM आपके code से कोई function चलाने को कहता है → agent = loop में चलता LLM जो goal पूरा होने तक tools चुनता रहता है → MCP = tools को किसी भी AI app से जोड़ने का एक standard plug।

1. Tool calling (function calling)

आप LLM को बताते हो कि आपके पास कौन से functions हैं। जब उसे किसी की ज़रूरत होती है, वह जवाब देता है "यह function इन inputs के साथ चलाओ" (JSON में)। उसे आपका code चलाता है और result वापस भेजता है। फिर LLM final जवाब लिखता है।

LLM को दिए गए tools:
  getAvailableSlots(date)
  bookSiteVisit(name, phone, propertyId, slot)

User: "मुझे कल Sector 150 वाला 3BHK देखना है"
LLM → { tool: "getAvailableSlots", args: { date: "2026-10-19" } }   ← LLM सिर्फ़ माँगता है
आपका code → database query चलाता है → ["11:00", "16:00"]            ← चलाता आपका code है
LLM → "कल सुबह 11 बजे या शाम 4 बजे। आपको कौन सा समय ठीक रहेगा?"

मुख्य बात: model खुद कभी कुछ नहीं चलाता। वह सिर्फ़ माँगता है। चलाना है या नहीं, यह आपका backend तय करता है। Checks और permissions यहीं लगाते हो।

उदाहरण: hotel का मेहमान reception पर फ़ोन करता है: "Room 204 में pizza भेज दो।" Receptionist (LLM) बस order आगे बढ़ाती है; बन सकता है या नहीं और असल में बनाना, यह kitchen (आपका code) करता है।

🎤 "With tool calling, the model sends back a request to run one of my functions. My app runs it and returns the result. The model decides what to call; my code decides whether and how it runs."

2. AI agent

Loop में चलता LLM: सोचो → काम करो (tool call) → result देखो → फिर से, जब तक goal पूरा न हो।

Goal: "इस lead को check करो और site visit book करो"

Loop 1: सोचो: budget नहीं पता          → काम: user से budget पूछो    → Result: "1.5 Cr"
Loop 2: सोचो: कोई matching property?   → काम: searchProperties(...)  → Result: 2 options
Loop 3: सोचो: time slot चाहिए          → काम: getAvailableSlots()    → Result: 11:00, 16:00
Loop 4: सोचो: user ने 4 बजे चुना        → काम: bookSiteVisit(...)     → Result: booked ✅
Loop 5: सोचो: broker को बताओ           → काम: notifyBroker(...)      → Done

असली उदाहरण: Claude Code एक agent है। यह files पढ़ता है, commands चलाता है, output देखता है और अगला step खुद तय करता है। रोज़मर्रा का उदाहरण: travel agent जो पहले flight देखता है, फिर उसके हिसाब से hotel, फिर cab।

🎤 "An agent is an LLM that plans and does a task in many steps. It calls tools in a loop and uses each result to choose the next step, until the goal is done."

3. Chatbot vs workflow vs agent

ChatbotWorkflowAgent

Flexible?कममध्यमज़्यादा

Senior tip: जहाँ workflow से काम चल जाए, वहाँ agent मत लगाओ। Workflows सस्ते, तेज़ और ठीक करने में आसान होते हैं। Agent तभी जब steps सच में हर बार बदलते हों।

उदाहरण: दूधवाला रोज़ एक ही रास्ते से जाता है (workflow)। Ambulance driver हर बार traffic देख कर रास्ता चुनता है (agent)।

4. Memory

  • Short-term: अभी की chat (context window के अंदर)।
  • Long-term: chats के पार याद रखे गए facts (आपके database में, RAG से दोबारा निकाले गए)। जैसे: "इस lead को पिछले हफ़्ते 1.5 Cr से कम का 3BHK चाहिए था।"

उदाहरण: short-term = phone call के दौरान याद रहने वाली बात। Long-term = दुकानदार की पक्के customers वाली diary ("शर्मा जी हमेशा Amul butter लेते हैं")।

5. Multi-agent

कई agents, हर एक का अपना काम, tools और prompt, मिलकर काम करते हुए। उदाहरण: Qualifier agent (सवाल पूछता है) → Property agent (listings ढूँढता है) → Scheduler agent (visits book करता है)। बड़े systems के लिए काम का, पर खर्च ज़्यादा और संभालना मुश्किल। शुरुआत एक agent से करो।

उदाहरण: अस्पताल: reception, डॉक्टर और billing counter, हर कोई एक काम करता है और मरीज़ को आगे भेजता है।

6. MCP (Model Context Protocol)

AI apps को tools और data से जोड़ने का एक open standard (Anthropic ने 2024 में बनाया)।

  • MCP से पहले: हर AI app को हर tool के लिए अपना अलग connection code चाहिए था।
  • MCP के साथ: एक बार MCP server बनाओ (जैसे "Kodivo CRM"), और MCP support करने वाला कोई भी AI app (Claude, code editors, agents) उसे इस्तेमाल कर सकता है।
  • उदाहरण: AI के लिए USB-C। एक plug, कई devices।

🎤 "MCP is an open standard for connecting AI apps to tools and data. You build a tool once as an MCP server, and any MCP app can use it."

7. Safety checks (live app में ज़रूरी)

Agents गलती कर सकते हैं, इसलिए live app में:

  • Tool inputs check करो (phone number सही है? slot मौजूद है?)
  • Permissions: agent listings पढ़ सकता है पर delete नहीं कर सकता
  • Risky कामों (refund, payment, bulk messages) के लिए इंसान की approval
  • Step limit और timeout ताकि loop हमेशा न चलता रहे (और पैसा न बहाए)
  • हर tool call का log, bugs ठीक करने और audit के लिए
  • Evals: हर release से पहले sample chats पर agent को test करो

उदाहरण: नया driver। उसे company की गाड़ी (access), रास्ते की सीमा (step limit), खर्च की सीमा वाला fuel card (permissions), GPS log (logging) देते हो, और लंबी trip के लिए manager की हाँ ज़रूरी (human approval)।

🎤 "In a live app I would check tool inputs, give only the access needed, ask a human before actions that can't be undone, limit the steps, log every tool call, and run evals."

AI Interview Prep

Private notes. For a senior full stack job that also has AI work (LLMs, RAG, tool calling, testing AI).

1. Topics and what to say

TopicWhat to explain
Structured outputAsk the model to reply in JSON with fixed keys and types. Check the reply with a schema library (like zod). If it fails, try once more and send the error back to the model. If it fails again, use a safe default.
Tool callingThe model asks to call a function and gives the inputs. Your code runs the function and sends back the result. Give each tool strict inputs and only the access it needs. Ask a human before risky actions.
LLM basicsTokens (small pieces of text), context window (how much text the model can see at once), transformer and attention (basic idea), pre-training on huge text, fine-tuning, RLHF (learning from human ratings), temperature (how random the answer is), hallucination (confident but wrong answers).
Quantization, distillation, SLMQuantization stores the model's numbers with fewer bits, so it is smaller and faster, with a little quality loss. Distillation trains a small model to copy a big one. An SLM (small language model) is cheap and can run on your own machine.
Running in productionCost (model size, prompt length, caching). Speed (stream the answer, use a smaller model for easy tasks). Reliability (timeouts, retries, backup model). Monitoring (tokens used, errors, quality score).
Evals and guardrailsEvals: a list of real questions with the expected behaviour, checked by keywords, a scoring guide, or another model as judge. Guardrails check what goes in and what comes out. Prompt injection: keep your rules separate from user text, give little access, check the output.
RAGCut documents into small parts (chunks), turn each part into numbers (embeddings), store them in pgvector. For a question, find the closest parts and tell the model to answer only from them. Set a minimum match score and show the sources.
Agents and MCPAn agent has a goal, some tools and a loop: plan, act, look at the result, repeat. MCP (Model Context Protocol) is one standard way to connect tools and data to AI apps.

2. Questions with short answers

Q: RAG or fine-tuning for company documents?

RAG. Company documents change often. RAG gives the model the facts at the time of the question and can show the source. Fine-tuning changes how the model writes (style, format), not which facts it remembers. Order to try: good prompt first, RAG for knowledge, fine-tuning only for style or format.

Q: How do you reduce hallucination?

Give the model the right information (RAG). Tell it to answer only from that information and to say "I don't know" if the answer is not there. Ask for sources. Use a low temperature for facts. Measure it with an eval set.

Q: How do you know your AI feature works well?

I make a test set of 30 to 50 real questions with the expected behaviour. I check answers with keywords first, then a scoring guide, and use an AI judge only for open answers (and I check the judge too). I run the tests after every prompt or model change and track the score.

Q: How do you stop users from tricking the AI (prompt injection)?

Keep system rules separate from user text and documents. Treat document text as data, never as orders. Give the model only the tools it needs. Ask a human before sensitive actions. Check the output before using it. Add attack examples to the test set.

Q: How do you keep the cost low?

Use the smallest model that passes the tests. Keep prompts short. Cache repeated prompts (prompt caching). Limit the answer length (max_tokens). Stream answers. Track cost per request and per user.

Q: How do you get reliable JSON from a model?

Ask for JSON with exact keys, use structured output or strict tool schemas, check every reply, retry once with the error, and keep a safe fallback. Never use the output without checking it.

Q: Explain tool calling with an example.

User asks: "Where is my order 123?" The model replies with a tool call: find_order with orderId 123. My code checks the database and sends the status back as JSON. The model then writes the final answer. The model never runs code itself.

Q: What happens inside a transformer, in simple words?

Text is cut into tokens, and each token becomes a list of numbers. Attention lets each token look at the other tokens and decide which ones matter. Many layers build up the meaning, and the model guesses the next token. It learns by doing this on huge amounts of text, then gets extra training to follow instructions (and RLHF).

Q: What is RLHF?

Reinforcement Learning from Human Feedback. People rank the model's answers. A second model (reward model) learns what people like. Then the main model is trained to give answers that score higher. This makes it more helpful and safer.

Q: What is quantization? Why does it matter?

Storing the model's numbers with fewer bits (8-bit or 4-bit instead of 16-bit). It uses less memory, costs less and runs faster, with a small quality loss. That is how big models fit on smaller GPUs.

Q: What is distillation?

A small "student" model is trained to copy the answers of a big "teacher" model. The student is cheaper and faster, and good enough for one task.

Q: Design a document Q&A system for 1 lakh documents.

Adding documents: upload to S3. A queue (BullMQ) sends jobs to workers that cut and embed the documents. Store parts and vectors in PostgreSQL with pgvector (HNSW index). Save extra info: customer (tenant), date, source.
Answering: check the cache, embed the question, filter by customer, find the top matches, re-rank if needed, build a prompt with sources, stream the model's answer, and log tokens and time.
Quality: test set, thumbs up/down buttons, and track how often it says "no answer".
Security: filter by customer in every query, hide personal data, limit requests per user.

Q: Build a support bot that can look up orders and give refunds.

Give it tools: find_order (read), check_refund_policy (read), create_refund (write). The write tool needs a human to approve it, or a strict rule (amount limit, only eligible orders). Log every tool call. Test cases where the bot must say no.

Q: What is an agent, and when should you NOT use one?

An agent plans and calls tools in a loop until the goal is done. Do not use one for simple one-step jobs like sorting or summarising. One AI call with a fixed flow is cheaper, faster and easier to test.

Q: What is MCP?

Model Context Protocol: an open standard for connecting AI apps to tools and data. One MCP server (for example for a database or GitHub) works with many AI apps.

4. Practice checklist

  • Explain one AI feature you built in 2 minutes: problem, design, result.
  • Draw the RAG flow from memory.
  • Explain how you would test an AI feature.
  • Answer: "What will you do if the model gives a wrong answer in production?"

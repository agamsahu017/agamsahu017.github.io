Web1 vs Web2 vs Web3

Private notes in easy English. Enough for 2 or 3 interview questions about Web3. Reading time: about 1 hour.

1. The three webs in one table

On a phone, swipe the table sideways →

Easy way to remember: Web1 = a newspaper (you only read). Web2 = a shopping mall (you can do a lot, but the mall owner sets the rules). Web3 = a village market everyone runs together (no single owner, but slower and less safe).

"Web1 was read-only. Web2 lets users create content, but big platforms own the data. Web3 tries to let users own their data and money using blockchains and wallets, with no central company in the middle."

2. What is a blockchain?

A record book (ledger) that is copied on thousands of computers. New transactions are grouped into a block. Each block keeps the hash (a fingerprint) of the block before it, so they form a chain.

  • Example: a society register where every member has a photocopy. If one person changes their copy, it no longer matches the others, so everyone knows it is fake.
  • If someone changes an old block, its fingerprint changes and the chain breaks. The network rejects it. That is why it is called immutable (cannot be changed).

"A blockchain is a shared record that can only be added to. Each block holds the previous block's hash, so changing old data breaks the chain. The computers in the network agree on the correct chain using consensus."

3. Four key words

  • Decentralized: no single owner, no bank in the middle.
  • Immutable: old records cannot be changed.
  • Transparent: anyone can see the transactions (for example on Etherscan).
  • Trustless: you trust the code and maths, not a middleman.

4. How everyone agrees (consensus)

  • Proof of Work (PoW): computers (miners) race to solve a hard maths puzzle. The winner adds the next block. Very safe, but uses a lot of electricity. Bitcoin uses this.
  • Proof of Stake (PoS): people lock up their coins (stake). The network picks one of them to add the next block. If they cheat, they lose coins. Uses far less electricity. Ethereum moved to PoS in 2022 ("The Merge").

6. Smart contract

A small program saved on the blockchain that runs by itself when its conditions are met. After it is saved (deployed), it cannot be changed, unless it was built to be upgradeable.

  • Example: a vending machine. Put in money, press a button, and the item comes out. No shopkeeper needed.
  • Written in Solidity (looks a bit like JavaScript). Runs on the EVM (Ethereum Virtual Machine).
// a very small contract
contract Counter {
    uint public count;
    function increment() public { count += 1; }
}

"A smart contract is a program on the blockchain that runs automatically. In my project, the tokens for real-estate shares were ERC-20 smart contracts."

7. Gas

The fee you pay (in ETH) to save anything on Ethereum or to run a contract function that changes data. Reading data is free. More complex code costs more gas, so contracts are kept small.

8. Tokens: ERC-20 vs ERC-721 (NFT) ⭐ most asked

ERC-20ERC-721 (NFT)
All tokens are the same, like ₹10 notesEach token is unique, like a property paper or a painting
Used for: coins, shares, part-ownership of propertyUsed for: art, game items, collectibles (ORE game items)
Main functions: totalSupply, balanceOf, transfer, approve, transferFrom, allowanceMain functions: ownerOf, transferFrom, safeTransferFrom, tokenURI

Link it to your projects:

  • Salcedo (real estate): one property is split into, say, 1,000 ERC-20 tokens. Buying 10 tokens = owning 1% of the property.
  • ORE System (NFT): each game item (a sword, a skin) is a unique ERC-721 NFT that players can trade.

Bonus, ERC-1155: one contract that can hold both kinds of tokens. Popular in games.

9. Wallet, public key, private key

  • Wallet (MetaMask, Coinbase Wallet): an app that keeps your keys and signs (approves) transactions.
  • Public key / address: like a bank account number. Safe to share.
  • Private key / seed phrase: like your ATM PIN and password together. Never share it. Whoever has it controls the money.
  • The wallet does not hold the coins. The coins live on the blockchain; the wallet only holds the keys.

10. How my Coinbase Wallet work worked (be ready to explain)

  1. User clicks "Connect Wallet". The app asks Coinbase Wallet for permission and gets the user's address.
  2. The app builds a transaction (for example: pay some ETH to buy tokens, or call the contract's buy function).
  3. The wallet pops up. The user checks it and signs. My app never sees the private key.
  4. The transaction goes to the network. We get a transaction hash and wait for confirmation.
  5. The backend checks the transaction on the blockchain before updating our database and showing "Purchase successful".

"I connected Coinbase Wallet using Web3.js: connect the wallet, get the address, build the transaction, let the wallet sign it, then confirm it on the blockchain before updating our database."

11. Web3.js and Ethers.js

JavaScript libraries that let your app talk to Ethereum: read balances, call contract functions, send transactions. To call a contract you need its address and its ABI (a JSON list of its functions, like a Swagger file). Ethers.js is more popular now. I used Web3.js.

12. Other words you may hear

  • Testnet (Sepolia): a free practice blockchain with fake ETH.
  • Etherscan: a website to look up any transaction, address or contract.
  • dApp: a normal frontend + smart contracts as the backend.
  • DeFi: bank-like services (loans, trading) run by smart contracts.
  • Oracle (like Chainlink): brings outside data (prices, weather) into contracts, because contracts cannot call APIs.
  • Layer 2 (Polygon, Arbitrum): faster and cheaper networks built on top of Ethereum.
  • Tokenization: turning a real thing (property, gold) into tokens.

13. Problems with Web3 (shows you think clearly)

  • Slower and costlier than a normal database (gas fees, waiting for confirmation).
  • A bug in a smart contract is permanent and can lose money. Hacks happen.
  • Laws are unclear in many countries. In India, crypto profit has 30% tax + 1% TDS.
  • Most apps do not need a blockchain. A normal database is better when one owner is trusted.

"I would use a blockchain only when many parties who don't trust each other need one shared record that nobody can change. Otherwise a normal database is faster, cheaper and simpler."

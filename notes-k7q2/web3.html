Web1 vs Web2 vs Web3

Private notes in easy English. Enough for 2 or 3 interview questions about Web3. Reading time: about 1 hour.

1. The three webs in one table

On a phone, swipe the table sideways →

Web1 (about 1990–2004)Web2 (about 2004–now)Web3 (new)
In one lineReadRead + writeRead + write + own
What you doRead simple pages made by a few peoplePost, comment, share, buy, upload videosUse apps where you hold your own money, data and items in a wallet
Who controls itThe site ownerBig companies (Google, Meta, Amazon)No single owner: a network of computers (blockchain)
Where data is keptThe site's own serverThe company's servers and databasesOn the blockchain, copied on many computers
LoginMostly noneEmail + password, or "Login with Google"Connect a wallet (like MetaMask)
How money is madeBanner adsAds using your data, subscriptionsTokens, fees paid in crypto
ExamplesOld news sites, Yahoo pagesFacebook, Instagram, YouTube, AmazonBitcoin, Ethereum, Uniswap, OpenSea (NFTs)
Main problemNot interactiveCompanies own your data and can block youSlow, costly fees, scams, unclear laws
Easy way to remember: Web1 = a newspaper (you only read). Web2 = a shopping mall (you can do a lot, but the mall owner sets the rules). Web3 = a village market everyone runs together (no single owner, but slower and less safe).

"Web1 was read-only. Web2 lets users create content, but big platforms own the data. Web3 tries to let users own their data and money using blockchains and wallets, with no central company in the middle."

2. What is a blockchain?

A record book (ledger) that is copied on thousands of computers. New transactions are grouped into a block. Each block keeps the hash (a fingerprint) of the block before it, so they form a chain.

  • Example: a society register where every member has a photocopy. If one person changes their copy, it no longer matches the others, so everyone knows it is fake.
  • If someone changes an old block, its fingerprint changes and the chain breaks. The network rejects it. That is why it is called immutable (cannot be changed).

"A blockchain is a shared record that can only be added to. Each block holds the previous block's hash, so changing old data breaks the chain. The computers in the network agree on the correct chain using consensus."

3. Four key words

  • Decentralized: no single owner, no bank in the middle.
  • Immutable: old records cannot be changed.
  • Transparent: anyone can see the transactions (for example on Etherscan).
  • Trustless: you trust the code and maths, not a middleman.

Example: UPI vs cash in a chit fund. In a chit fund you trust one organiser to keep the money honestly. On a blockchain, every member holds the same account book, so nobody has to trust one person.

4. How everyone agrees (consensus)

  • Proof of Work (PoW): computers (miners) race to solve a hard maths puzzle. The winner adds the next block. Very safe, but uses a lot of electricity. Bitcoin uses this.
  • Proof of Stake (PoS): people lock up their coins (stake). The network picks one of them to add the next block. If they cheat, they lose coins. Uses far less electricity. Ethereum moved to PoS in 2022 ("The Merge").

Example: PoW = a race in which whoever runs fastest (spends the most electricity) wins the right to write. PoS = a security deposit for a rented flat: you lock money, and if you damage things you lose the deposit.

5. Bitcoin vs Ethereum

BitcoinEthereum
Only digital moneyMoney + programs (smart contracts)
Cannot run appsRuns apps (DeFi, NFTs, tokens)
Proof of WorkProof of Stake

Example: Bitcoin is like digital gold: you hold it and send it. Ethereum is like a smartphone: you can also install apps on it.

6. Smart contract

A small program saved on the blockchain that runs by itself when its conditions are met. After it is saved (deployed), it cannot be changed, unless it was built to be upgradeable.

  • Example: a vending machine. Put in money, press a button, and the item comes out. No shopkeeper needed.
  • Written in Solidity (looks a bit like JavaScript). Runs on the EVM (Ethereum Virtual Machine).
// a very small contract
contract Counter {
    uint public count;
    function increment() public { count += 1; }
}

"A smart contract is a program on the blockchain that runs automatically. In my project, the tokens for real-estate shares were ERC-20 smart contracts."

7. Gas

The fee you pay (in ETH) to save anything on Ethereum or to run a contract function that changes data. Reading data is free. More complex code costs more gas, so contracts are kept small.

Example: a registry office. Reading old records in the register is free, but registering a new property deed costs a stamp fee, and a bigger deed costs more.

8. Tokens: ERC-20 vs ERC-721 (NFT) ⭐ most asked

ERC-20ERC-721 (NFT)
All tokens are the same, like ₹10 notesEach token is unique, like a property paper or a painting
Used for: coins, shares, part-ownership of propertyUsed for: art, game items, collectibles (ORE game items)
Main functions: totalSupply, balanceOf, transfer, approve, transferFrom, allowanceMain functions: ownerOf, transferFrom, safeTransferFrom, tokenURI

Link it to your projects:

  • Salcedo (real estate): one property is split into, say, 1,000 ERC-20 tokens. Buying 10 tokens = owning 1% of the property.
  • ORE System (NFT): each game item (a sword, a skin) is a unique ERC-721 NFT that players can trade.

Bonus, ERC-1155: one contract that can hold both kinds of tokens. Popular in games.

9. Wallet, public key, private key

  • Wallet (MetaMask, Coinbase Wallet): an app that keeps your keys and signs (approves) transactions.
  • Public key / address: like a bank account number. Safe to share.
  • Private key / seed phrase: like your ATM PIN and password together. Never share it. Whoever has it controls the money.
  • The wallet does not hold the coins. The coins live on the blockchain; the wallet only holds the keys.

10. How my Coinbase Wallet work worked (be ready to explain)

  1. User clicks "Connect Wallet". The app asks Coinbase Wallet for permission and gets the user's address.
  2. The app builds a transaction (for example: pay some ETH to buy tokens, or call the contract's buy function).
  3. The wallet pops up. The user checks it and signs. My app never sees the private key.
  4. The transaction goes to the network. We get a transaction hash and wait for confirmation.
  5. The backend checks the transaction on the blockchain before updating our database and showing "Purchase successful".

"I connected Coinbase Wallet using Web3.js: connect the wallet, get the address, build the transaction, let the wallet sign it, then confirm it on the blockchain before updating our database."

11. Web3.js and Ethers.js

JavaScript libraries that let your app talk to Ethereum: read balances, call contract functions, send transactions. To call a contract you need its address and its ABI (a JSON list of its functions, like a Swagger file). Ethers.js is more popular now. I used Web3.js.

Example: like axios for a REST API, but for the blockchain. The ABI is the menu card: it tells you which dishes (functions) you can order.

12. Other words you may hear

  • Testnet (Sepolia): a free practice blockchain with fake ETH.
  • Etherscan: a website to look up any transaction, address or contract.
  • dApp: a normal frontend + smart contracts as the backend.
  • DeFi: bank-like services (loans, trading) run by smart contracts.
  • Oracle (like Chainlink): brings outside data (prices, weather) into contracts, because contracts cannot call APIs.
  • Layer 2 (Polygon, Arbitrum): faster and cheaper networks built on top of Ethereum.
  • Tokenization: turning a real thing (property, gold) into tokens.

13. Problems with Web3 (shows you think clearly)

  • Slower and costlier than a normal database (gas fees, waiting for confirmation).
  • A bug in a smart contract is permanent and can lose money. Hacks happen.
  • Laws are unclear in many countries. In India, crypto profit has 30% tax + 1% TDS.
  • Most apps do not need a blockchain. A normal database is better when one owner is trusted.

"I would use a blockchain only when many parties who don't trust each other need one shared record that nobody can change. Otherwise a normal database is faster, cheaper and simpler."

2. Blockchain क्या है?

एक हिसाब की किताब (ledger) जिसकी copy हज़ारों computers पर है। नए transactions को मिलाकर एक block बनता है। हर block अपने से पहले वाले block का hash (एक तरह का fingerprint) रखता है, इसलिए वे एक chain बना लेते हैं।

  • उदाहरण: society का register जिसकी photocopy हर सदस्य के पास है। अगर कोई अपनी copy बदल दे, तो वह बाकी copies से match नहीं करेगी, और सबको पता चल जाएगा कि वह नकली है।
  • अगर कोई पुराना block बदले, तो उसका fingerprint बदल जाता है और chain टूट जाती है। Network उसे reject कर देता है। इसीलिए इसे immutable (बदला न जा सके) कहते हैं।

"A blockchain is a shared record that can only be added to. Each block holds the previous block's hash, so changing old data breaks the chain. The computers in the network agree on the correct chain using consensus."

3. चार ज़रूरी शब्द

  • Decentralized: कोई एक मालिक नहीं, बीच में कोई bank नहीं।
  • Immutable: पुराने records बदले नहीं जा सकते।
  • Transparent: कोई भी transactions देख सकता है (जैसे Etherscan पर)।
  • Trustless: आप किसी बिचौलिए पर नहीं, code और गणित पर भरोसा करते हो।

उदाहरण: मोहल्ले की कमेटी (chit fund) में पैसा एक organiser के भरोसे रहता है। Blockchain में हर सदस्य के पास वही हिसाब की किताब है, इसलिए किसी एक इंसान पर भरोसा करने की ज़रूरत नहीं।

4. सब सहमत कैसे होते हैं (consensus)

  • Proof of Work (PoW): computers (miners) एक मुश्किल गणित की पहेली सुलझाने की दौड़ लगाते हैं। जीतने वाला अगला block जोड़ता है। बहुत सुरक्षित, पर बिजली बहुत लगती है। Bitcoin यही इस्तेमाल करता है।
  • Proof of Stake (PoS): लोग अपने coins lock (stake) करते हैं। Network उनमें से किसी एक को अगला block जोड़ने के लिए चुनता है। धोखा दिया तो coins गए। बिजली बहुत कम लगती है। Ethereum 2022 में PoS पर आ गया ("The Merge")।

उदाहरण: PoW = दौड़: जो सबसे तेज़ भागे (सबसे ज़्यादा बिजली खर्च करे) वही लिखने का हक़ जीते। PoS = किराए के flat का security deposit: पैसा जमा रखो, नुकसान किया तो deposit कटेगा।

5. Bitcoin vs Ethereum

BitcoinEthereum
सिर्फ़ digital पैसापैसा + programs (smart contracts)
Apps नहीं चला सकताApps चलाता है (DeFi, NFTs, tokens)

उदाहरण: Bitcoin = digital सोना: रखो और भेजो। Ethereum = smartphone: इस पर apps भी install कर सकते हो।

6. Smart contract

Blockchain पर रखा एक छोटा program जो शर्तें पूरी होते ही अपने आप चलता है। एक बार save (deploy) होने के बाद बदला नहीं जा सकता, जब तक उसे upgradeable न बनाया गया हो।

  • उदाहरण: vending machine। पैसे डालो, button दबाओ, सामान बाहर। दुकानदार की ज़रूरत नहीं।
  • Solidity में लिखा जाता है (थोड़ा JavaScript जैसा)। EVM (Ethereum Virtual Machine) पर चलता है।
// एक बहुत छोटा contract
contract Counter {
    uint public count;
    function increment() public { count += 1; }
}

"A smart contract is a program on the blockchain that runs automatically. In my project, the tokens for real-estate shares were ERC-20 smart contracts."

7. Gas

Ethereum पर कुछ भी save करने या data बदलने वाला contract function चलाने के लिए दी जाने वाली fee (ETH में)। Data पढ़ना free है। Code जितना complex, gas उतनी ज़्यादा, इसलिए contracts छोटे रखे जाते हैं।

उदाहरण: रजिस्ट्री office। पुराने records देखना free है, पर नई property की registry पर stamp fee लगती है, और बड़े deed पर ज़्यादा।

ERC-20ERC-721 (NFT)
सारे tokens एक जैसे, जैसे ₹10 के नोटहर token अलग (unique), जैसे property के कागज़ या कोई painting
इस्तेमाल: coins, shares, property में हिस्सेदारीइस्तेमाल: art, game items, collectibles (ORE game items)

अपने projects से जोड़ो:

  • Salcedo (real estate): एक property को, मान लो, 1,000 ERC-20 tokens में बाँटा। 10 tokens खरीदे = property के 1% के मालिक।
  • ORE System (NFT): हर game item (तलवार, skin) एक unique ERC-721 NFT है जिसे players trade कर सकते हैं।

Bonus, ERC-1155: एक contract जो दोनों तरह के tokens रख सकता है। Games में popular।

9. Wallet, public key, private key

  • Wallet (MetaMask, Coinbase Wallet): एक app जो आपकी keys रखता है और transactions sign (approve) करता है।
  • Public key / address: bank account number जैसा। Share करना safe है।
  • Private key / seed phrase: ATM PIN और password दोनों एक साथ। कभी share मत करो। जिसके पास यह है, पैसा उसका।
  • Wallet में coins नहीं होते। Coins blockchain पर रहते हैं; wallet सिर्फ़ keys रखता है।

10. मेरा Coinbase Wallet वाला काम कैसे चलता था (समझाने को तैयार रहो)

  1. User "Connect Wallet" दबाता है। App Coinbase Wallet से permission माँगता है और user का address लेता है।
  2. App एक transaction बनाता है (जैसे tokens खरीदने के लिए कुछ ETH देना, या contract का buy function call करना)।
  3. Wallet pop-up खुलता है। User check करके sign करता है। मेरे app को private key कभी नहीं दिखती।
  4. Transaction network पर जाता है। हमें एक transaction hash मिलता है और हम confirmation का इंतज़ार करते हैं।
  5. Backend blockchain पर transaction check करता है, फिर हमारा database update करके "Purchase successful" दिखाता है।

"I connected Coinbase Wallet using Web3.js: connect the wallet, get the address, build the transaction, let the wallet sign it, then confirm it on the blockchain before updating our database."

11. Web3.js और Ethers.js

JavaScript libraries जिनसे आपका app Ethereum से बात करता है: balance पढ़ना, contract functions call करना, transactions भेजना। Contract call करने के लिए उसका address और ABI (उसके functions की JSON list, Swagger file जैसी) चाहिए। आजकल Ethers.js ज़्यादा popular है। मैंने Web3.js इस्तेमाल किया।

उदाहरण: REST API के लिए जैसे axios, वैसे ही blockchain के लिए ये libraries। ABI = menu card: बताता है कौन सी dishes (functions) order कर सकते हो।

12. और शब्द जो सुनने को मिल सकते हैं

  • Testnet (Sepolia): practice के लिए free blockchain, नकली ETH के साथ।
  • Etherscan: कोई भी transaction, address या contract देखने की website।
  • dApp: normal frontend + backend के रूप में smart contracts।
  • DeFi: bank जैसी services (loan, trading) जो smart contracts चलाते हैं।
  • Oracle (जैसे Chainlink): बाहर का data (prices, मौसम) contracts तक लाता है, क्योंकि contracts खुद API call नहीं कर सकते।
  • Layer 2 (Polygon, Arbitrum): Ethereum के ऊपर बने तेज़ और सस्ते networks।
  • Tokenization: असली चीज़ (property, सोना) को tokens में बदलना।

13. Web3 की कमियाँ (इससे दिखता है कि आप साफ़ सोचते हो)

  • Normal database से धीमा और महँगा (gas fees, confirmation का इंतज़ार)।
  • Smart contract का bug हमेशा के लिए रहता है और पैसा डूब सकता है। Hacks होते हैं।
  • कई देशों में कानून साफ़ नहीं। India में crypto के मुनाफ़े पर 30% tax + 1% TDS।
  • ज़्यादातर apps को blockchain की ज़रूरत नहीं। जब एक भरोसेमंद मालिक हो, तो normal database बेहतर है।

"I would use a blockchain only when many parties who don't trust each other need one shared record that nobody can change. Otherwise a normal database is faster, cheaper and simpler."

3. Interview questions with easy answers

Node.js and NestJS (backend)

Q: How does the Node.js event loop work?
Node runs your JavaScript on one thread. Slow work like files and network calls is handed to the system (libuv). When that work is done, its callback waits in a queue and runs when the thread is free. Promise callbacks and nextTick (called microtasks) run first, before the next item in the queue.

Q: How do you organise a NestJS module?
One module per feature. Inside: a controller (handles HTTP), a service (business logic), DTOs (shape of input, checked with class-validator) and repositories (database). Shared services are exported. Settings are loaded with forRootAsync.

Q: Guards vs interceptors vs pipes?
Guards say yes or no to a request (login, roles). Pipes check and convert input. Interceptors run before and after the handler (logging, changing the response). Exception filters turn errors into a clean response.

Q: How do you stop charging a customer twice when a request is retried?
Use an idempotency key: a unique ID saved in the database. If the same key comes again, return the saved result instead of charging again. For payment webhooks, check the signature and update the database inside a transaction.

Q: How do you find a memory leak?
Watch memory (heapUsed) over time. Take two heap snapshots with --inspect, compare them, and find what keeps growing (caches, event listeners, timers). Remove those references.

React and Next.js (frontend)

Q: useMemo vs useCallback vs React.memo?
useMemo saves a calculated value. useCallback saves a function so it stays the same between renders. React.memo stops a child from re-rendering when its props did not change. Use them only when something is really slow.

Q: Why does a React component re-render?
Its state changed, its props changed, or its parent re-rendered. Use stable keys in lists, and keep state in the lowest component that needs it.

Q: Server vs Client Components in Next.js?
Server Components are the default. They send no JavaScript to the browser and can read data directly. Add "use client" when you need state, clicks or browser features. You can pass a server component into a client component as children.

Q: How does caching work in the App Router?
fetch results are saved (cached). Use revalidate to refresh after some time, cache: "no-store" for always-fresh data, and revalidateTag or revalidatePath to refresh after data changes.

Q: What is an error boundary? What does it not catch?
A component that catches errors while its children render, and shows a fallback screen. It does not catch errors in click handlers, async code, or in itself.

PostgreSQL and data

Q: How do you find a slow query?
Run EXPLAIN ANALYZE. Look for a full table scan (Seq Scan) on a big table, and add the right index. In an index on many columns, the order of columns matters.

Q: Offset vs keyset pagination?
Offset (skip N rows) is simple but gets slow on later pages. Keyset (WHERE id > last_id ORDER BY id LIMIT n) stays fast and does not skip or repeat rows.

Q: What is the N+1 problem?
One query to get a list, then one more query for each row. Fix it with a join, or load all the rows you need in one batch query.

System design (follow these steps)

1) Ask what the system must do and how big it is (users, requests per second, data size). 2) Draw the main boxes: app, API, database, cache, queue, workers. 3) Walk through the main flow. 4) Explain the tables and indexes. 5) Explain how it grows, what happens when something fails, and retries. 6) Explain monitoring and security.

Practice: URL shortener; notification service (email, SMS, WhatsApp); export a report of 10 lakh rows; hotel booking without double booking; rate limiter.

Behaviour questions (prepare 4 stories)

Prepare: (1) a hard production bug you fixed, (2) a disagreement with a teammate and how you solved it, (3) a tight deadline you met, (4) a project you led or a person you guided. Tell each story as Situation, Task, Action, Result (STAR), and end with a number.

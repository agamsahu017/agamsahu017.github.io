OOPS: the 4 pillars and interview questionsOOPS: 4 pillars और interview सवाल

In one line: OOPS organises code as objects made from classes, using 4 ideas: hide details (encapsulation, abstraction), reuse (inheritance), and one name with many behaviours (polymorphism).

एक लाइन में: OOPS code को classes से बने objects की तरह सजाता है, 4 ideas के साथ: details छिपाओ (encapsulation, abstraction), दोबारा इस्तेमाल करो (inheritance), और एक नाम, कई व्यवहार (polymorphism)।

Class and objectClass और object

Beginnerशुरुआती

A class is a blueprint, like the design of a car. An object is a real car built from that design, with its own colour and number. Examples here are in Java, because most campus interviews use it; the ideas are the same in C++, Python and JavaScript.

Class एक नक़्शा है, जैसे car का design। Object उस design से बनी असली car है, अपने रंग और number के साथ। यहाँ examples Java में हैं, क्योंकि ज़्यादातर campus interviews में वही चलती है; ideas C++, Python और JavaScript में भी यही हैं।

class Car {
    String color;            // data (fields)
    int speed;

    Car(String color) {      // constructor: runs when the object is created
        this.color = color;
        this.speed = 0;
    }

    void accelerate() {      // behaviour (method)
        speed += 10;
    }
}

Car myCar = new Car("Red");  // an object
myCar.accelerate();          // speed is now 10

Encapsulation in codeCode में encapsulation

class BankAccount {
    private double balance;              // hidden from outside

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
        balance += amount;
    }

    public double getBalance() {         // read-only access
        return balance;
    }
}

Inheritance and polymorphism in codeCode में inheritance और polymorphism

class Payment {
    void pay(double amount) { System.out.println("Paying " + amount); }
}

class UpiPayment extends Payment {          // inheritance: UpiPayment is a Payment
    @Override
    void pay(double amount) { System.out.println("UPI payment of " + amount); }
}

class CardPayment extends Payment {
    @Override
    void pay(double amount) { System.out.println("Card payment of " + amount); }
}

Payment p = new UpiPayment();   // parent type, child object
p.pay(500);                      // prints "UPI payment of 500": decided at runtime

Quick answers to common OOPS questionsआम OOPS सवालों के छोटे जवाब

QuestionसवालShort answerछोटा जवाब
Can we override a static method?क्या static method override हो सकता है?No. A child can declare a static method with the same name, but that hides it; it isn't overriding.नहीं। Child उसी नाम का static method बना सकता है, पर वो उसे छिपाता है; यह overriding नहीं है।
Can a constructor be private?क्या constructor private हो सकता है?Yes, for example in the Singleton pattern, so only the class can create its object.हाँ, जैसे Singleton pattern में, ताकि सिर्फ़ class ही अपना object बना सके।
Why doesn't Java allow multiple inheritance of classes?Java classes का multiple inheritance क्यों नहीं देती?To avoid the "diamond problem" (two parents with the same method). Interfaces give the benefit safely."Diamond problem" से बचने के लिए (दो parents में एक ही method)। Interfaces यह फ़ायदा सुरक्षित तरीक़े से देते हैं।
Composition vs inheritance?Composition vs inheritance?Inheritance = "is-a"; composition = "has-a" (a Car has an Engine). Prefer composition when unsure: it's more flexible.Inheritance = "is-a"; composition = "has-a" (Car के पास Engine है)। पक्का न हो तो composition चुनिए: यह ज़्यादा flexible है।

⚠️ Common mistakesआम ग़लतियाँ
  • Defining abstraction and encapsulation the same way. Encapsulation hides data; abstraction hides complexity.Abstraction और encapsulation को एक जैसा बताना। Encapsulation data छिपाता है; abstraction उलझन छिपाता है।
  • Saying overloading is runtime polymorphism. It's compile time; overriding is runtime.Overloading को runtime polymorphism कहना। यह compile time है; overriding runtime।
  • Only giving textbook definitions. Add one real example for each answer.सिर्फ़ किताबी परिभाषा देना। हर जवाब के साथ एक असली उदाहरण जोड़िए।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. 4 pillars: encapsulation (hide data), abstraction (hide complexity), inheritance (reuse), polymorphism (one name, many forms).4 pillars: encapsulation (data छिपाना), abstraction (उलझन छिपाना), inheritance (दोबारा इस्तेमाल), polymorphism (एक नाम, कई रूप)।
  2. Overloading = same class, different parameters, compile time. Overriding = child re-writes parent, runtime.Overloading = एक class, अलग parameters, compile time। Overriding = child parent को दोबारा लिखता है, runtime।
  3. Abstract class: one parent, shared code. Interface: a contract, many allowed.Abstract class: एक parent, shared code। Interface: एक contract, कई allowed।

Practiceप्रैक्टिस

Exercise 1: Design classes for shapes: Circle, Rectangle and Square must all give their area. Which OOPS ideas do you use?Exercise 1: Shapes की classes design कीजिए: Circle, Rectangle और Square सबको अपना area देना है। कौन-से OOPS ideas इस्तेमाल करेंगे?

Show a sample answerएक sample जवाब देखें
abstract class Shape {                // abstraction: every shape has an area
    abstract double area();
}

class Circle extends Shape {          // inheritance
    private final double r;           // encapsulation
    Circle(double r) { this.r = r; }
    double area() { return Math.PI * r * r; }
}

class Rectangle extends Shape {
    private final double w, h;
    Rectangle(double w, double h) { this.w = w; this.h = h; }
    double area() { return w * h; }
}

class Square extends Rectangle {
    Square(double side) { super(side, side); }
}

Shape[] shapes = { new Circle(1), new Rectangle(2, 3), new Square(4) };
for (Shape s : shapes) System.out.println(s.area());   // polymorphism

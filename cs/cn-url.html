What happens when you type a URLURL type करने पर क्या होता है

⏱️ 20 min read + practice20 मिनट पढ़ाई + प्रैक्टिस📚 CS Fundamentals🎯 Interview focusedइंटरव्यू के हिसाब से

In one line: Your browser finds the server's address (DNS), connects to it (TCP), secures the line (TLS), asks for the page (HTTP), and draws what comes back.

एक लाइन में: आपका browser server का address ढूँढता है (DNS), उससे जुड़ता है (TCP), line सुरक्षित करता है (TLS), page माँगता है (HTTP), और जो आता है उसे दिखाता है।

You type www.example.com and press Enter…आप www.example.com लिखकर Enter दबाते हैं…

Think of sending a courier to a friend's shop: you look up the address (DNS), call to make sure the shop is open (TCP), check it's really their shop (TLS), place the order (request), they pack it (server), it arrives (response), and you unpack it (rendering).

किसी दोस्त की दुकान पर courier भेजने की सोचिए: address ढूँढते हैं (DNS), फ़ोन करके पक्का करते हैं कि दुकान खुली है (TCP), जाँचते हैं कि दुकान सच में उन्हीं की है (TLS), order देते हैं (request), वो pack करते हैं (server), सामान आता है (response), और आप खोलते हैं (rendering)।

Step 1: DNS, finding the addressStep 1: DNS, address ढूँढना

Beginnerशुरुआती

Computers talk using IP addresses, not names. DNS turns www.example.com into an IP address. It checks in this order, stopping as soon as it finds the answer:

Computers नामों से नहीं, IP addresses से बात करते हैं। DNS www.example.com को IP address में बदलता है। यह इस क्रम में देखता है, और जवाब मिलते ही रुक जाता है:

  1. Browser cache: did I look this up recently?Browser cache: क्या मैंने हाल में यह देखा था?
  2. Operating system cache (and the hosts file).Operating system cache (और hosts file)।
  3. DNS resolver, usually your internet provider's or a public one like 8.8.8.8.DNS resolver, आमतौर पर आपके internet provider का या 8.8.8.8 जैसा public।
  4. If the resolver doesn't know, it asks the root server → the .com server → the domain's own authoritative server, which gives the final IP.Resolver को न पता हो, तो वो root server → .com server → domain के अपने authoritative server से पूछता है, जो आख़िरी IP देता है।

The answer is cached for a while (its TTL), so the next visit is faster.

जवाब कुछ देर के लिए cache होता है (उसका TTL), इसलिए अगली बार तेज़ होता है।

Steps 2–3: TCP connection and TLS securitySteps 2–3: TCP connection और TLS security

Beginnerशुरुआती

TCP 3-way handshake: before sending data, the browser and server agree to talk. Like a phone call: "Hello?" "Hello, I can hear you" "Great, let's talk".

TCP 3-way handshake: data भेजने से पहले browser और server बात करने पर राज़ी होते हैं। Phone call की तरह: "Hello?" "Hello, आवाज़ आ रही है" "बढ़िया, बात करते हैं"।

TLS handshake (for HTTPS): the server shows a certificate proving it really is example.com. Both sides then agree on secret keys, so nobody in between (like public Wi-Fi) can read or change the data. HTTPS uses port 443; plain HTTP uses port 80.

TLS handshake (HTTPS के लिए): server एक certificate दिखाता है जो साबित करता है कि वो सच में example.com है। फिर दोनों secret keys पर राज़ी होते हैं, ताकि बीच में कोई (जैसे public Wi-Fi) data पढ़ या बदल न सके। HTTPS port 443 इस्तेमाल करता है; सादा HTTP port 80।

  • 4. Request: the browser sends a GET request with headers, like the cookie that keeps you logged in.4. Request: browser headers के साथ GET request भेजता है, जैसे cookie जिससे आप logged in रहते हैं।
  • 5. Server: a load balancer passes it to an app server, which may read a cache or database and builds the HTML.5. Server: load balancer इसे app server तक भेजता है, जो cache या database पढ़कर HTML बनाता है।
  • 6. Response: status code (like 200 OK), headers and the HTML.6. Response: status code (जैसे 200 OK), headers और HTML।
  • 7. Rendering: the browser reads the HTML into a DOM tree, downloads CSS, JS and images (more requests), applies styles, lays out the page and paints it. JavaScript then makes it interactive.7. Rendering: browser HTML को DOM tree में पढ़ता है, CSS, JS और images download करता है (और requests), styles लगाता है, page का layout बनाता है और उसे paint करता है। फिर JavaScript उसे interactive बनाती है।

How to answer in an interviewInterview में जवाब कैसे दें

🎤 Fresher answer (1 minute): "The browser first resolves the domain to an IP using DNS, checking caches and then DNS servers. It opens a TCP connection with a 3-way handshake, and for HTTPS does a TLS handshake to verify the certificate and encrypt the connection. It sends an HTTP GET request; the server processes it and returns a response with a status code and HTML. The browser parses the HTML, fetches CSS, JS and images, builds the DOM, and renders the page."

🎤 Fresher जवाब (1 मिनट): "The browser first resolves the domain to an IP using DNS, checking caches and then DNS servers. It opens a TCP connection with a 3-way handshake, and for HTTPS does a TLS handshake to verify the certificate and encrypt the connection. It sends an HTTP GET request; the server processes it and returns a response with a status code and HTML. The browser parses the HTML, fetches CSS, JS and images, builds the DOM, and renders the page."

Add these for a senior-level answerSenior level जवाब में ये जोड़िए Senior levelSenior level

  • CDN: static files often come from a nearby CDN, not the origin server.CDN: static files अक्सर origin server नहीं, पास के CDN से आती हैं।
  • Connection reuse: keep-alive and HTTP/2 send many requests over one connection; HTTP/3 runs over QUIC (on UDP) for faster setup.Connection reuse: keep-alive और HTTP/2 एक connection पर कई requests भेजते हैं; HTTP/3 तेज़ setup के लिए QUIC (UDP पर) चलता है।
  • Behind the server: load balancer, app servers, cache, database, and where each could be slow.Server के पीछे: load balancer, app servers, cache, database, और कौन कहाँ धीमा हो सकता है।
  • Performance: DNS caching, TLS session resumption, compression, and render-blocking CSS/JS.Performance: DNS caching, TLS session resumption, compression, और render रोकने वाली CSS/JS।
⚠️ Common mistakesआम ग़लतियाँ
  • Skipping DNS and starting from "the request goes to the server".DNS छोड़कर "request server पर जाती है" से शुरू करना।
  • Mixing up TCP handshake (connection) and TLS handshake (security).TCP handshake (connection) और TLS handshake (security) में गड़बड़।
  • Forgetting that the browser makes many more requests for CSS, JS and images.भूल जाना कि browser CSS, JS और images के लिए कई और requests करता है।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. DNS → TCP → TLS → HTTP request → server → response → render.DNS → TCP → TLS → HTTP request → server → response → render।
  2. TCP handshake = SYN, SYN-ACK, ACK. TLS = certificate + encryption.TCP handshake = SYN, SYN-ACK, ACK। TLS = certificate + encryption।
  3. Seniors add CDN, HTTP/2 and 3, load balancers and performance.Seniors CDN, HTTP/2 और 3, load balancers और performance जोड़ते हैं।

  • DNS caching: the first visit needed a full DNS lookup; later visits use the cached IP.DNS caching: पहली बार पूरा DNS lookup लगा; बाद में cached IP इस्तेमाल हुआ।

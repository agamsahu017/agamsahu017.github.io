Embeddings and semantic searchEmbeddings और semantic search

⏱️ 25 min read + practice25 मिनट पढ़ाई + प्रैक्टिस🤖 AI🎯 Interview focusedइंटरव्यू के हिसाब से

In one line: An embedding turns a sentence into a list of numbers, so sentences with similar meaning end up with similar numbers.

Meaning as numbersमतलब, numbers के रूप में

Think of a map. Lucknow and Kanpur are close; Lucknow and London are far. An embedding puts every sentence on a "meaning map": sentences that mean similar things land close together, even if they use different words or languages.

एक map सोचिए। लखनऊ और कानपुर पास हैं; लखनऊ और London दूर। Embedding हर sentence को एक "मतलब के map" पर रखता है: मिलते-जुलते मतलब वाले sentences पास-पास आते हैं, भले ही शब्द या भाषा अलग हो।

"Clinic fees kitni hai?"        → [0.12, -0.53, 0.88, ...]
"What is the consultation charge?" → [0.11, -0.50, 0.85, ...]   ← very close
"Aaj mausam kaisa hai?"          → [-0.70, 0.31, -0.10, ...]  ← far away

Real embeddings have hundreds or thousands of numbers. You don't read them yourself: you compare them.

असली embeddings में सैकड़ों या हज़ारों numbers होते हैं। आप उन्हें ख़ुद नहीं पढ़ते: आप उनकी तुलना करते हैं।

Cosine similarity: how close are two meanings?Cosine similarity: दो मतलब कितने पास हैं?

Cosine similarity gives a score: close to 1 means very similar meaning, close to 0 means unrelated. Below, each sentence has a tiny hand-made 3-number embedding so you can see the idea. Pick a question and watch which sentences come out on top.

Cosine similarity एक score देती है: 1 के पास मतलब बहुत मिलता-जुलता, 0 के पास मतलब कोई संबंध नहीं। नीचे हर sentence का हाथ से बना छोटा 3-number embedding है ताकि idea दिखे। एक सवाल चुनिए और देखिए कौन-से sentences सबसे ऊपर आते हैं।

Try it: search by meaningख़ुद देखें: मतलब से search
Notice: in this hand-made example, "Kitna paisa lagega?" matches the fee sentences even though no word is the same. That's the idea of semantic search.ध्यान दीजिए: इस हाथ से बने उदाहरण में "Kitna paisa lagega?" fee वाले sentences से मिलता है, जबकि एक भी शब्द एक जैसा नहीं। यही semantic search का idea है।
// Cosine similarity between two vectors
function cosine(a, b) {
  let dot = 0, lenA = 0, lenB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    lenA += a[i] * a[i];
    lenB += b[i] * b[i];
  }
  return dot / (Math.sqrt(lenA) * Math.sqrt(lenB));
}

Many real systems use both (hybrid search): keywords for exact matches like order IDs, and embeddings for meaning.

कई असली systems दोनों इस्तेमाल करते हैं (hybrid search): order ID जैसे exact matches के लिए keywords, और मतलब के लिए embeddings।

Semantic search in JavaScriptJavaScript में semantic search

Senior levelSenior level

You need an embedding model. You can call an embedding API from a provider, or run a small open model on your own computer for free. This example runs a multilingual model locally (it downloads about 120 MB the first time), so Hindi and English questions both work.

आपको एक embedding model चाहिए। आप किसी provider की embedding API call कर सकते हैं, या अपने computer पर एक छोटा open model मुफ़्त में चला सकते हैं। यह उदाहरण एक multilingual model local चलाता है (पहली बार लगभग 120 MB download होता है), इसलिए Hindi और English दोनों सवाल चलते हैं।

// npm install @huggingface/transformers
import { pipeline } from "@huggingface/transformers";

const extractor = await pipeline("feature-extraction", "Xenova/paraphrase-multilingual-MiniLM-L12-v2");
const embed = async (texts) =>
  (await extractor(texts, { pooling: "mean", normalize: true })).tolist();

const docs = [
  "Fees: you pay the doctor ₹500 for each visit (consultation charges).",
  "The clinic is open 9 AM to 9 PM, Monday to Saturday.",
  "Free parking is available behind the building.",
];
const docVectors = await embed(docs);

// With normalized vectors, cosine similarity is just the dot product.
const dot = (a, b) => a.reduce((sum, x, i) => sum + x * b[i], 0);

async function search(question) {
  const [q] = await embed([question]);
  return docs
    .map((text, i) => ({ text, score: dot(q, docVectors[i]) }))
    .sort((a, b) => b.score - a.score);
}

console.log(await search("डॉक्टर की फीस कितनी है?")); // the fee sentence comes first

Tested tip: this small free model understands English and Hindi (Devanagari) well, but Hinglish typed in English letters, like "Kitna paisa lagega?", matches less reliably. Write your documents clearly, including the words people actually use ("fees", "charges"), test with real user questions, and try a stronger embedding model if your users type Hinglish.

Test किया हुआ tip: यह छोटा free model English और Hindi (देवनागरी) अच्छे से समझता है, पर English अक्षरों में लिखी Hinglish, जैसे "Kitna paisa lagega?", कम भरोसे से मिलती है। Documents साफ़ लिखिए, उनमें वो शब्द रखिए जो लोग सच में बोलते हैं ("fees", "charges"), असली users के सवालों से test कीजिए, और users Hinglish लिखते हों तो बेहतर embedding model आज़माइए।

For thousands of documents, store the vectors in a vector database such as pgvector (PostgreSQL), so the search stays fast. That's the next module: RAG.

हज़ारों documents के लिए vectors को vector database में रखिए, जैसे pgvector (PostgreSQL), ताकि search तेज़ रहे। यही अगला module है: RAG।

⚠️ Common mistakesआम ग़लतियाँ
  • Comparing embeddings made by two different models. Always use the same model for documents and questions.दो अलग models से बने embeddings की तुलना करना। Documents और सवालों के लिए हमेशा एक ही model इस्तेमाल कीजिए।
  • Embedding a whole 50-page PDF as one vector. Split it into chunks first.पूरे 50 पेज के PDF का एक ही vector बनाना। पहले उसे chunks में बाँटिए।
  • Treating the similarity score as certainty. Set a minimum score and test with real questions.Similarity score को पक्की बात मानना। एक minimum score रखिए और असली सवालों से test कीजिए।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. Similar meaning = similar numbers, even with different words or languages.मिलता-जुलता मतलब = मिलते-जुलते numbers, भले शब्द या भाषा अलग हो।
  2. Cosine similarity near 1 = very similar, near 0 = unrelated.Cosine similarity 1 के पास = बहुत मिलता-जुलता, 0 के पास = कोई संबंध नहीं।
  3. Use the same embedding model for documents and questions.Documents और सवालों के लिए एक ही embedding model इस्तेमाल कीजिए।

Show a sample answerएक sample जवाब देखें
  • Once: create an embedding for each of the 500 FAQs and store them.एक बार: 500 FAQs में से हर एक का embedding बनाकर रखिए।

Fine-tuning vs RAG vs promptingFine-tuning vs RAG vs prompting

⏱️ 16 min read + practice16 मिनट पढ़ाई + प्रैक्टिस🤖 AI🎯 Interview focusedइंटरव्यू के हिसाब से

In one line: Prompting changes the request, RAG adds your facts at query time, and fine-tuning trains a style or skill into the weights; use prompting and RAG first (especially for facts) and fine-tune last.

एक लाइन में: Prompting request बदलता है, RAG query के समय आपके facts जोड़ता है, और fine-tuning किसी style या skill को weights में train करता है; पहले prompting और RAG (ख़ासकर facts के लिए), fine-tuning आख़िर में।

Three ways to make an LLM betterLLM को बेहतर बनाने के तीन तरीक़े

Beginnerशुरुआती

When the default answer isn't good enough, you have three tools, from cheapest to heaviest.

जब डिफ़ॉल्ट जवाब काफ़ी न हो, आपके पास तीन tools हैं, सबसे सस्ते से सबसे भारी तक।

Easy picture: prompting = giving instructions to a smart worker; RAG = handing them the right reference file to read; fine-tuning = sending them on a training course so a new habit sticks.

आसान तस्वीर: prompting = समझदार worker को निर्देश देना; RAG = उन्हें पढ़ने के लिए सही reference file देना; fine-tuning = उन्हें training course पर भेजना ताकि नई आदत पक्की हो जाए।

What each one really doesहर एक असल में क्या करता है

Beginnerशुरुआती

1. Prompting — change what you ask1. Prompting — आप क्या पूछते हैं वह बदलिए

Improve the instructions, add a system prompt, or show 2–3 examples (few-shot). No training at all, and you see the change instantly. Always try this first.

निर्देश सुधारिए, system prompt जोड़िए, या 2–3 examples दिखाइए (few-shot)। कोई training नहीं, और बदलाव तुरंत दिखता है। हमेशा पहले यही आज़माइए।

2. RAG — give it the right facts2. RAG — उसे सही facts दीजिए

Retrieve the relevant chunks from your own data (with embeddings and a vector database) and add them to the prompt, so the model answers from facts it never memorised. You can update the knowledge any time by changing the data, and it reduces hallucination. See the RAG module.

अपने data से सही chunks निकालिए (embeddings और vector database से) और उन्हें prompt में जोड़िए, ताकि model उन facts से जवाब दे जो उसने कभी याद नहीं किए। data बदलकर जानकारी कभी भी update कर सकते हैं, और यह hallucination कम करता है। RAG module देखिए।

3. Fine-tuning — teach a new habit3. Fine-tuning — नई आदत सिखाइए

Take an already-trained model and train it a little more on your example pairs (input → ideal output). This changes the weights, so the new style, format or skill is baked in. It needs a dataset and compute, but LoRA makes it cheap by training a small add-on instead of the whole model.

पहले से trained model लेकर उसे अपने example pairs पर थोड़ा और train कीजिए (input → सही output)। इससे weights बदलते हैं, तो नई style, format या skill पक्की हो जाती है। इसके लिए dataset और compute चाहिए, पर LoRA पूरे model की जगह एक छोटा add-on train करके इसे सस्ता बना देता है।

The big idea: fine-tuning changes how the model answers (style, format, behaviour), not what facts it reliably knows. To add facts, use RAG, not fine-tuning.

बड़ी बात: fine-tuning बदलता है कि model कैसे जवाब देता है (style, format, behaviour), यह नहीं कि वह कौन से facts पक्के जानता है। Facts जोड़ने के लिए RAG इस्तेमाल कीजिए, fine-tuning नहीं।

Real systems often combine them: a good prompt, plus RAG for facts, and fine-tuning only if the style still isn't right or you want to shrink a long prompt to cut cost. Fine-tune last, because prompting and RAG solve most problems with far less effort.

असली systems अक्सर इन्हें मिलाते हैं: अच्छा prompt, साथ में facts के लिए RAG, और fine-tuning सिर्फ़ तब जब style फिर भी ठीक न हो या लंबे prompt को छोटा करके cost घटानी हो। Fine-tuning आख़िर में, क्योंकि prompting और RAG ज़्यादातर समस्याएँ बहुत कम मेहनत में हल कर देते हैं।

Pre-training, self-supervised and RLHFPre-training, self-supervised और RLHF

Senior levelSenior level

Interviewers often connect fine-tuning to how a model is built:

Interviewers अक्सर fine-tuning को इस से जोड़ते हैं कि model बनता कैसे है:

  • Pre-training: the model first learns language by predicting the next token on a huge pile of text. This is self-supervised — the data labels itself, because the next word is the correct answer. No humans label it.Pre-training: model पहले text के विशाल ढेर पर अगला token predict करके भाषा सीखता है। यह self-supervised है — data ख़ुद को label करता है, क्योंकि अगला शब्द ही सही जवाब है। कोई इंसान label नहीं करता।
  • Instruction-tuning + RLHF: then it is trained to follow instructions and be helpful and safe. RLHF (Reinforcement Learning from Human Feedback) uses human ratings to reward better answers.Instruction-tuning + RLHF: फिर इसे निर्देश मानने और helpful व safe होने के लिए train किया जाता है। RLHF (Reinforcement Learning from Human Feedback) बेहतर जवाबों को reward देने के लिए इंसानी ratings इस्तेमाल करता है।
  • Your fine-tuning is a small extra step on top of all that — not training from scratch.आपका fine-tuning इन सबके ऊपर एक छोटा सा extra step है — शून्य से training नहीं।

So "fine-tuning" never means building a model from zero. You take a model that already knows language and nudge it a little toward your examples.

तो "fine-tuning" का मतलब कभी शून्य से model बनाना नहीं। आप पहले से भाषा जानने वाला model लेकर उसे अपने examples की ओर थोड़ा मोड़ते हैं।

Mistakes to avoidबचने लायक ग़लतियाँ

Senior levelSenior level
⚠️ Common mistakesआम ग़लतियाँ
  • "Fine-tune to add knowledge." Usually wrong: RAG is cheaper and fresher for facts, and a fine-tuned model can still make facts up."Knowledge जोड़ने के लिए fine-tune करो।" आम तौर पर ग़लत: facts के लिए RAG सस्ता और ताज़ा है, और fine-tuned model फिर भी facts गढ़ सकता है।
  • Jumping to fine-tuning first. Try prompting and RAG first; they solve most problems with far less effort and cost.सीधे fine-tuning पर कूदना। पहले prompting और RAG आज़माइए; वे ज़्यादातर समस्याएँ बहुत कम मेहनत और cost में हल कर देते हैं।
  • Thinking fine-tuning updates in real time. It is a batch training job; RAG updates instantly when you change the data.यह सोचना कि fine-tuning real time में update होता है। यह एक batch training काम है; RAG तो data बदलते ही तुरंत update हो जाता है।

📌 Remember these 5 thingsये 5 बातें याद रखिए
  1. Prompting = change the request; cheapest; try first.Prompting = request बदलना; सबसे सस्ता; पहले आज़माइए।
  2. RAG = add your facts at query time; best for fresh or private knowledge.RAG = query के समय अपने facts जोड़ना; ताज़ा या private जानकारी के लिए सबसे अच्छा।
  3. Fine-tuning = train a style/skill into the weights; needs data + compute; LoRA makes it cheap.Fine-tuning = style/skill को weights में train करना; data + compute चाहिए; LoRA इसे सस्ता करता है।
  4. For facts use RAG, not fine-tuning. Fine-tuning changes how it answers, not what it knows.Facts के लिए RAG, fine-tuning नहीं। Fine-tuning बदलता है कैसे जवाब दे, यह नहीं कि क्या जानता है।
  5. Pre-training is self-supervised; RLHF uses human feedback; your fine-tuning sits on top.Pre-training self-supervised है; RLHF इंसानी feedback लेता है; आपका fine-tuning उसके ऊपर है।

Practiceप्रैक्टिस

Exercise 1: A company wants its support bot to answer from its latest product manuals, which change every month. Prompting, RAG or fine-tuning?Exercise 1: एक company चाहती है उसका support bot उसके latest product manuals से जवाब दे, जो हर महीने बदलते हैं। Prompting, RAG या fine-tuning?

Show a sample answerएक sample जवाब देखें

RAG. The knowledge is private and changes often, so you store the manuals in a vector database and retrieve the right parts at query time. You update answers simply by updating the documents, with no retraining. Fine-tuning would bake in facts that go stale and is far more work.

RAG। जानकारी private है और अक्सर बदलती है, तो manuals को vector database में रखिए और query के समय सही हिस्से निकालिए। जवाब बस documents update करके बदल जाते हैं, बिना दोबारा training। Fine-tuning पुराने पड़ने वाले facts को पक्का कर देगा और कहीं ज़्यादा मेहनत है।

Exercise 2: You need the model to always reply in a strict JSON shape with the same tone, no matter the prompt. Which approach fits best, and what would you try first?Exercise 2: आपको चाहिए कि model हमेशा एक सख़्त JSON shape में, एक ही tone में जवाब दे, prompt चाहे जो हो। कौन सा तरीक़ा सबसे सही है, और पहले क्या आज़माएँगे?

Show a sample answerएक sample जवाब देखें

Try prompting first: a clear system prompt plus a few examples often gets reliable JSON and tone. If it still drifts across many prompts, fine-tuning is a good fit, because a consistent format and tone is exactly the "how it answers" that fine-tuning bakes in. This is a style/format need, not a facts need, so RAG would not help.

पहले prompting आज़माइए: साफ़ system prompt और कुछ examples अक्सर भरोसेमंद JSON और tone दे देते हैं। अगर कई prompts में फिर भी बिगड़े, तो fine-tuning सही है, क्योंकि एक जैसी format और tone वही "कैसे जवाब दे" है जो fine-tuning पक्का करता है। यह style/format की ज़रूरत है, facts की नहीं, तो RAG मदद नहीं करेगा।

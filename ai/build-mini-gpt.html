What does it mean to "build an LLM"?"LLM बनाने" का मतलब क्या है?

Beginnerशुरुआती

Every LLM starts as a base model: a program that has read a huge amount of text and learned one skill, guessing the next piece of text. Fine-tuning then turns it into a helpful assistant.

हर LLM एक base model के रूप में शुरू होता है: एक program जिसने बहुत सारा text पढ़कर एक ही हुनर सीखा है, अगला टुकड़ा अंदाज़ा लगाना। फिर fine-tuning उसे एक मददगार assistant बनाती है।

Train a tiny language model, right nowअभी एक छोटा language model train कीजिए

Beginnerशुरुआती

The simplest language model looks at one letter and guesses the next one. To train it, we just count: in our training names, which letter comes after which? To generate, we pick the next letter using those counts, again and again.

सबसे simple language model एक अक्षर देखकर अगला अंदाज़ा लगाता है। इसे train करने के लिए हम बस गिनते हैं: हमारे training नामों में कौन-सा अक्षर किसके बाद आता है? Generate करने के लिए उन्हीं गिनतियों से अगला अक्षर चुनते हैं, बार-बार।

Try it: train on names, then generate new onesख़ुद देखें: नामों पर train कीजिए, फिर नए नाम बनवाइए
Change the names (try cities or dishes), train again, and generate.नाम बदलिए (शहर या पकवान आज़माइए), फिर से train कीजिए, और generate कीजिए।

The same model in plain JavaScript. Save it as mini-gpt.js and run node mini-gpt.js:

यही model simple JavaScript में। इसे mini-gpt.js नाम से save कीजिए और node mini-gpt.js चलाइए:

// A tiny character-level language model (a "bigram" model).
const names = ["aarav", "aditi", "ananya", "arjun", "diya", "ishaan", "kabir", "kavya", "meera",
  "neha", "priya", "rahul", "riya", "rohan", "saanvi", "sneha", "tanvi", "vihaan"];

// 1. Training: count which letter comes after which. "." marks the start and end of a name.
const counts = {};
for (const name of names) {
  const chars = [".", ...name, "."];
  for (let i = 0; i < chars.length - 1; i++) {
    const a = chars[i], b = chars[i + 1];
    counts[a] ??= {};
    counts[a][b] = (counts[a][b] ?? 0) + 1;
  }
}
console.log("Letters after 'v':", counts["v"]);

// 2. Generating: pick the next letter in proportion to how often it was seen.
function nextChar(prev) {
  const options = Object.entries(counts[prev]);
  const total = options.reduce((sum, [, c]) => sum + c, 0);
  let r = Math.random() * total;
  for (const [ch, c] of options) {
    r -= c;
    if (r < 0) return ch;
  }
  return ".";
}

function generateName() {
  let name = "", ch = ".";
  while (true) {
    ch = nextChar(ch);
    if (ch === "." || name.length >= 10) break;
    name += ch;
  }
  return name;
}

for (let i = 0; i < 5; i++) console.log(generateName());

Training = turning examples into numbers (here, the counts). Generating = using those numbers to pick the next piece, one step at a time. GPT does exactly this, with much smarter numbers.

Training = examples को numbers में बदलना (यहाँ, गिनतियाँ)। Generating = उन numbers से अगला टुकड़ा चुनना, एक-एक step। GPT बिल्कुल यही करता है, बहुत ज़्यादा समझदार numbers के साथ।

How real models learn: guess, check, nudgeअसली models कैसे सीखते हैं: अंदाज़ा, जाँच, सुधार

Beginnerशुरुआती

Counting works for one letter, but not for long sentences. Real models instead have parameters (numbers) that start random. Training repeats three steps millions of times:

एक अक्षर के लिए गिनती काम करती है, पर लंबे वाक्यों के लिए नहीं। असली models में parameters (numbers) होते हैं जो random शुरू होते हैं। Training तीन steps को लाखों बार दोहराती है:

The smallest possible example: a model with just 2 parameters (w and b) learns the rule y = 2x + 1 only from 4 examples. Press the buttons and watch the error fall:

सबसे छोटा example: सिर्फ़ 2 parameters (w और b) वाला model सिर्फ़ 4 examples से y = 2x + 1 का नियम सीखता है। Buttons दबाइए और ग़लती घटती देखिए:

Try it: watch a model learnख़ुद देखें: model को सीखते देखिए
Examples: x = 1, 2, 3, 4 → y = 3, 5, 7, 9. The model is never told the rule.Examples: x = 1, 2, 3, 4 → y = 3, 5, 7, 9। Model को नियम कभी नहीं बताया जाता।
// How training really works: learn y = 2x + 1 just from examples.
const data = [[1, 3], [2, 5], [3, 7], [4, 9]]; // (x, y) pairs
let w = 0, b = 0;   // the model's two parameters, starting at 0
const lr = 0.05;    // learning rate: how big each correction is

for (let step = 1; step <= 1000; step++) {
  let dw = 0, db = 0, loss = 0;
  for (const [x, y] of data) {
    const guess = w * x + b;  // the model's prediction
    const error = guess - y;  // how wrong it is
    loss += error * error;
    dw += 2 * error * x;      // which way to nudge w
    db += 2 * error;          // which way to nudge b
  }
  w -= (lr * dw) / data.length; // nudge both to reduce the error
  b -= (lr * db) / data.length;
  if ([1, 10, 100, 1000].includes(step)) {
    console.log(`step ${step}: w=${w.toFixed(3)} b=${b.toFixed(3)} loss=${(loss / data.length).toFixed(4)}`);
  }
}

An LLM is the same idea at a huge scale: instead of 2 parameters, it has billions, and instead of "guess y", the task is "guess the next token". That's why training needs so much data, so many GPUs and so much money.

LLM भी यही idea है, बहुत बड़े पैमाने पर: 2 parameters की जगह अरबों, और "y का अंदाज़ा" की जगह "अगले token का अंदाज़ा"। इसीलिए training में इतना data, इतने GPUs और इतना पैसा लगता है।

From our tiny model to GPTहमारे छोटे model से GPT तक

Senior levelSenior level

Our model only sees one letter, so it can't learn that "Ish" usually becomes "Ishaan". GPT fixes this with a few big ideas:

हमारा model सिर्फ़ एक अक्षर देखता है, इसलिए वो नहीं सीख सकता कि "Ish" अक्सर "Ishaan" बनता है। GPT इसे कुछ बड़े ideas से ठीक करता है:

Attention in one line: in "Priya gave Rahul her book because she was leaving", attention helps the model link "she" to "Priya", not to "Rahul" or "book".

Attention एक line में: "Priya gave Rahul her book because she was leaving" में attention model को "she" को "Priya" से जोड़ने में मदद करता है, "Rahul" या "book" से नहीं।

You don't need to code attention yourself to understand it. The plan below uses ready-made code that you read and run.

Attention समझने के लिए उसे ख़ुद code करना ज़रूरी नहीं। नीचे का plan तैयार code इस्तेमाल करता है जिसे आप पढ़ते और चलाते हैं।

Most useful for work: fine-tune insteadकाम के लिए सबसे उपयोगी: fine-tuning

Building from zero teaches you how LLMs work. For a real product, it's smarter to fine-tune a strong open model (like Llama, Qwen or Gemma) on your own examples, for example Hindi support replies for a business. Techniques like LoRA make this possible on a free Colab GPU for small models. See Hugging Face and Unsloth tutorials, and first check our fine-tuning vs RAG vs prompting module, because often RAG or better prompts are enough.

Zero से बनाना सिखाता है कि LLMs कैसे काम करते हैं। असली product के लिए किसी अच्छे open model (जैसे Llama, Qwen या Gemma) को अपने examples पर fine-tune करना ज़्यादा समझदारी है, जैसे किसी business के Hindi support जवाब। LoRA जैसी techniques से छोटे models के लिए यह free Colab GPU पर भी हो जाता है। Hugging Face और Unsloth के tutorials देखिए, और पहले हमारा fine-tuning vs RAG vs prompting module पढ़िए, क्योंकि अक्सर RAG या बेहतर prompts ही काफ़ी होते हैं।

⚠️ Common mistakesआम ग़लतियाँ
  • Trying to build a ChatGPT competitor alone. Build small to learn; fine-tune for products.अकेले ChatGPT जैसा बनाने की कोशिश। सीखने के लिए छोटा बनाइए; products के लिए fine-tune कीजिए।
  • Renting expensive GPUs before the small version works on your laptop or Colab.छोटा version laptop या Colab पर चलने से पहले ही महँगे GPUs किराए पर लेना।
  • Training on other people's private data. Use your own text or openly licensed datasets.दूसरों के private data पर train करना। अपना text या openly licensed datasets इस्तेमाल कीजिए।
📌 Remember these 4 thingsये 4 बातें याद रखिए
  1. A base model only predicts the next token; fine-tuning makes it an assistant.Base model सिर्फ़ अगला token predict करता है; fine-tuning उसे assistant बनाती है।
  2. Training = guess → measure the error → nudge the parameters, repeated millions of times.Training = अंदाज़ा → ग़लती नापना → parameters खिसकाना, लाखों बार।
  3. GPT adds tokens, a long context, attention and many layers to the same idea.GPT इसी idea में tokens, लंबा context, attention और कई layers जोड़ता है।
  4. Learn with nanoGPT and nanochat; for products, fine-tune an open model or use RAG.nanoGPT और nanochat से सीखिए; products के लिए open model fine-tune कीजिए या RAG इस्तेमाल कीजिए।

Exercise 2: A company wants an AI that answers customer questions in Hindi about its products. Should it build its own base model?Exercise 2: एक company अपने products के बारे में Hindi में customer सवालों के जवाब देने वाला AI चाहती है। क्या उसे अपना base model बनाना चाहिए?

Show a sample answerएक sample जवाब देखें

No. Building a base model costs a fortune and gives a weak result. Start with an existing strong model plus RAG over the product documents. If the tone or format still isn't right, fine-tune an open model on a few hundred good example answers.

नहीं। Base model बनाना बहुत महँगा है और नतीजा कमज़ोर आता है। पहले किसी मौजूदा अच्छे model के साथ product documents पर RAG से शुरू कीजिए। अगर tone या format फिर भी ठीक न हो, तो किसी open model को कुछ सौ अच्छे example जवाबों पर fine-tune कीजिए।

LLM vs chatbot vs AI agentLLM vs chatbot vs AI agent

Beginnerशुरुआती

Agentic AI in one example. A chatbot answers: "Here is how to find a cheap flight." An agent does the job: you say "Book the cheapest flight to Mumbai tomorrow." It searches flights, compares prices, checks your budget, books the best one, and tells you the result. It plans the steps itself and keeps going until the job is done.

एक उदाहरण से Agentic AI। Chatbot जवाब देता है: "सस्ती flight ढूँढने का तरीक़ा यह है।" Agent काम करता है: आप बोलते हैं "कल के लिए मुंबई की सबसे सस्ती flight book करो।" वह flights search करता है, price compare करता है, budget देखता है, सबसे अच्छी book करता है, और नतीजा बताता है। Steps वह ख़ुद plan करता है और काम पूरा होने तक चलता रहता है।

Three things make it an agent: (1) a goal, not just a question; (2) tools it can use, like search, a database or an API; (3) a loop: plan, act, look at the result, decide the next step. For risky actions (paying money, deleting data), a good agent asks a human first.

तीन बातें इसे agent बनाती हैं: (1) एक goal, सिर्फ़ सवाल नहीं; (2) tools जो वह इस्तेमाल कर सके, जैसे search, database या API; (3) एक loop: plan करो, काम करो, नतीजा देखो, अगला step तय करो। जोखिम वाले काम (पैसे देना, data मिटाना) के लिए अच्छा agent पहले इंसान से पूछता है।

Remember: a chatbot tells you. An agent does the work.

Real examples of agentsAgents के असली examples

Coding agent (example): You say: "The forgot-password link does not work. Find the bug, fix it and run the tests." The agent reads the project files, finds that the link points to /reset-password but the server uses /password/reset, fixes the route, runs the tests, fixes any new error, and reports: "Fixed the route, 12 tests pass, these files changed." You review the changes before anything is merged. Examples: Claude Code, Cursor agent mode, GitHub Copilot agent mode.

Coding agent (उदाहरण): आप बोलते हैं: "forgot-password link काम नहीं कर रहा। bug ढूँढो, fix करो और tests चलाओ।" Agent project files पढ़ता है, देखता है कि link /reset-password पर जाता है पर server /password/reset इस्तेमाल करता है, route ठीक करता है, tests चलाता है, नई error हो तो उसे भी fix करता है, और बताता है: "Route ठीक किया, 12 tests pass हैं, ये files बदली गईं।" Merge से पहले आप changes review करते हैं। Examples: Claude Code, Cursor agent mode, GitHub Copilot agent mode।

Research agent (example): You say: "Compare WhatsApp appointment tools for small clinics in India, with prices and features, and give source links." The agent searches 10 to 15 sites, reads the pricing and feature pages, writes a comparison table, and marks anything it cannot find (like an exact price) as "not found" instead of guessing. You check the links, because prices change. Examples: Perplexity deep research, ChatGPT deep research, Gemini deep research.

Research agent (उदाहरण): आप बोलते हैं: "भारत में छोटे clinics के लिए WhatsApp appointment tools की तुलना करो, price और features के साथ, और source links दो।" Agent 10 से 15 sites search करता है, pricing और feature pages पढ़ता है, comparison table बनाता है, और जो चीज़ न मिले (जैसे exact price) उसे अंदाज़े से नहीं, "not found" लिखकर बताता है। Prices बदलते हैं, इसलिए links आप ख़ुद check करते हैं। Examples: Perplexity deep research, ChatGPT deep research, Gemini deep research।

What are tools? (real examples)Tools क्या हैं? (असली examples)

A tool is a function that your code offers to the AI. The AI does not run it itself. It asks, your code runs it, and the result goes back to the AI. Examples: get_weather(city) calls a weather API; web_search(query) calls a search API; find_order(orderId) reads your orders database; send_email(to, text) sends a real email, so it should always ask a human first.

Tool एक function है जो आपका code AI को देता है। AI उसे ख़ुद नहीं चलाता। वह माँगता है, आपका code उसे चलाता है, और नतीजा वापस AI को जाता है। Examples: get_weather(city) weather API call करता है; web_search(query) search API call करता है; find_order(orderId) आपके orders database से पढ़ता है; send_email(to, text) असली email भेजता है, इसलिए इसके लिए हमेशा पहले इंसान से पूछना चाहिए।

Real products like Claude Code, Cursor and Perplexity are agents with many tools built in: file reading, code editing, running tests, and web search.

Interviewers love these three words because many people mix them up. The difference is simple.

Interviewers को ये तीन शब्द पसंद हैं क्योंकि लोग इन्हें गड्ड-मड्ड कर देते हैं। फ़र्क़ आसान है।

The agent loopAgent loop

Beginnerशुरुआती

An agent runs a loop again and again until the goal is met:

Agent एक loop बार-बार चलाता है जब तक goal पूरा न हो:

  • 1. Goal in — you give a task, like "book the cheapest flight next Friday".1. Goal — आप काम देते हैं, जैसे "अगले शुक्रवार की सबसे सस्ती flight book करो"।
  • 2. Think / plan — the model reasons about the next step (often step by step).2. सोचो / plan — model अगले step के बारे में सोचता है (अक्सर step-by-step)।
  • 3. Act — it calls a tool: search, an API, a database, or run code.3. काम करो — यह कोई tool call करता है: search, API, database, या code चलाना।
  • 4. Observe — it reads the tool's result.4. देखो — tool का नतीजा पढ़ता है।
  • 5. Repeat — plan the next step with that result, until done, then give the final answer.5. दोहराओ — उस नतीजे से अगला step, काम पूरा होने तक, फिर आख़िरी जवाब।

Chain of Thought (CoT) = letting the model reason step by step before answering. It makes hard problems (maths, logic, planning) much more accurate. Reasoning models (like OpenAI's o-series, Claude with thinking, DeepSeek R1) are trained to do this thinking internally before they reply.

Chain of Thought (CoT) = जवाब देने से पहले model को step-by-step सोचने देना। इससे कठिन सवाल (maths, logic, planning) ज़्यादा सही होते हैं। Reasoning models (जैसे OpenAI की o-series, Claude thinking के साथ, DeepSeek R1) जवाब से पहले यह सोच ख़ुद अंदर करते हैं।

Memory and contextMemory और context

Short-term memory is the context window (what fits in this request). Long-term memory means saving notes or past steps in a file or database and pulling them back when needed. Context engineering is the new skill beyond prompt writing: deciding exactly what to put into the limited context each step — instructions, the right tools, retrieved facts and memory — so the agent stays focused and cheap.

Short-term memory context window है (जो इस request में समाता है)। Long-term memory यानी notes या पुराने steps को file/database में रखना और ज़रूरत पर वापस लाना। Context engineering prompt लिखने से आगे की नई skill है: हर step में limited context में ठीक क्या डालें — निर्देश, सही tools, निकाले गए facts और memory — ताकि agent focused और सस्ता रहे।

For risky actions (sending money, deleting data, emailing a customer) a good agent asks a human to approve first. This is human-in-the-loop, and interviewers like to hear it.

जोखिम वाले कामों (पैसे भेजना, data मिटाना, customer को email) के लिए अच्छा agent पहले किसी इंसान से मंज़ूरी माँगता है। इसे human-in-the-loop कहते हैं, और interviewers इसे सुनना पसंद करते हैं।

Tool calling and MCPTool calling और MCP

Senior levelSenior level

Tool calling (also called function calling) is how an agent acts. The LLM does not run code itself. Instead it outputs "call this tool with these arguments"; your code runs the tool and hands the result back. That is the bridge between a talking model and real actions.

Tool calling (function calling भी) से agent काम करता है। LLM ख़ुद code नहीं चलाता। बल्कि यह बताता है "इस tool को इन arguments के साथ call करो"; आपका code tool चलाकर नतीजा वापस देता है। यही बोलने वाले model और असली काम के बीच का पुल है।

MCP (Model Context Protocol) is an open standard (started by Anthropic in late 2024) that lets any AI app connect to tools and data in one common way — think of it as a USB-C port for AI. Instead of writing custom integration code for every app, you run an MCP server (for GitHub, a database, Slack, your files), and any MCP-aware app can use it straight away.

MCP (Model Context Protocol) एक open standard है (Anthropic ने late 2024 में शुरू किया) जो किसी भी AI app को tools और data से एक ही आम तरीक़े से जोड़ता है — इसे AI का USB-C port समझिए। हर app के लिए अलग integration code लिखने की जगह, आप एक MCP server चलाते हैं (GitHub, database, Slack, अपनी files के लिए), और कोई भी MCP-समझने वाली app उसे तुरंत use कर लेती है।

Why MCP matters in interviews: before MCP, every app wrote its own custom code for each tool (N apps × M tools = a mess). MCP makes a tool reusable across all apps that speak the protocol. Also note models are now multimodal (they handle text, images, audio and video), so agents can also "see" a screenshot or a chart, not just read text.

Interview में MCP क्यों अहम: MCP से पहले हर app हर tool के लिए अपना custom code लिखती थी (N apps × M tools = झंझट)। MCP एक tool को उन सभी apps में reusable बना देता है जो यह protocol बोलती हैं। यह भी याद रखिए कि models अब multimodal हैं (text, images, audio, video संभालते हैं), तो agents सिर्फ़ text ही नहीं, screenshot या chart भी "देख" सकते हैं।

⚠️ Common mistakesआम ग़लतियाँ
  • Calling every chatbot an "agent". An agent must take actions with tools, not just chat.हर chatbot को "agent" कहना। Agent को tools से काम करना होता है, सिर्फ़ बात नहीं।
  • Thinking an agent permanently "learns" from a task. It doesn't: it uses tools and context during that run. Lasting change needs training/fine-tuning or saved memory.यह सोचना कि agent किसी काम से हमेशा के लिए "सीख" जाता है। नहीं: वह उस run में tools और context इस्तेमाल करता है। स्थायी बदलाव के लिए training/fine-tuning या saved memory चाहिए।
  • Forgetting guardrails. Agents can loop forever or take wrong actions; add step limits, human approval and evals.Guardrails भूल जाना। Agents हमेशा loop कर सकते हैं या ग़लत काम; step limits, human approval और evals जोड़िए।

Exercise 1: An interviewer asks: "What's the difference between a chatbot and an AI agent?" Answer in two lines.Exercise 1: Interviewer पूछता है: "Chatbot और AI agent में क्या फ़र्क़ है?" दो line में जवाब दीजिए।

Show a sample answerएक sample जवाब देखें

A chatbot wraps an LLM so a user can have a conversation; it answers but does not take real actions. An AI agent is given a goal, tools and memory, so it plans steps and acts — calling APIs, running code, repeating in a loop — until the goal is done, often asking a human to approve risky steps.

Chatbot एक LLM को लपेटता है ताकि user बात कर सके; यह जवाब देता है पर असली काम नहीं करता। AI agent को goal, tools और memory मिलते हैं, तो यह steps plan करके काम करता है — API call, code चलाना, loop में दोहराना — जब तक goal पूरा न हो, और जोखिम वाले steps के लिए अक्सर इंसान से मंज़ूरी माँगता है।

Exercise 2: Your task: "read a 2-line support message and tag it as billing / technical / other." Should you build an agent or make one LLM call? Why?Exercise 2: आपका काम: "2-line support message पढ़कर उसे billing / technical / other tag करो।" Agent बनाएँ या एक LLM call? क्यों?

One LLM call is enough. It is a single-step task with no tools or decisions along the way, so an agent would only add cost, latency and failure points. Keep agents for multi-step jobs that need tools, like "find the order, check the refund policy, then issue the refund".

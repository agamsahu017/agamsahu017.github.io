RAG: AI that answers from your dataRAG: AI जो आपके data से जवाब दे

In one line: RAG = first find the right information from your own data, then give it to the AI with the question, so it answers from facts instead of guessing.

The problem RAG solvesRAG कौन-सी problem हल करता है

An LLM doesn't know your clinic's fees, your company's HR policy or yesterday's price list. Ask it, and it may guess. RAG (Retrieval-Augmented Generation) fixes this: first find the right information, then give it to the LLM together with the question.

LLM को आपके clinic की fees, आपकी company की HR policy या कल की price list नहीं पता। पूछेंगे, तो अंदाज़ा लगा सकता है। RAG (Retrieval-Augmented Generation) इसे ठीक करता है: पहले सही जानकारी ढूँढो, फिर सवाल के साथ LLM को दो।

Analogy: an open-book exam. The student (LLM) is smart, but instead of answering from memory, they first open the right page of the book (retrieval) and then write the answer (generation).

मिसाल: open-book exam। Student (LLM) होशियार है, पर याददाश्त से जवाब देने की जगह पहले किताब का सही पेज खोलता है (retrieval) और फिर जवाब लिखता है (generation)।

Step 1: a tiny RAG in one file (no database)Step 1: एक file में छोटा RAG (बिना database)

Beginnerशुरुआती

Let's build the smallest RAG that works. It keeps 5 clinic facts in a simple list, finds the right ones by meaning, and asks the AI to answer only from them. It uses the ai.js helper from the previous module.

चलिए सबसे छोटा RAG बनाते हैं जो चले। यह clinic की 5 बातें एक आसान list में रखता है, मतलब से सही बातें ढूँढता है, और AI से सिर्फ़ उन्हीं से जवाब देने को कहता है। यह पिछले module की ai.js helper इस्तेमाल करता है।

npm install @huggingface/transformers
// rag-simple.js  →  node --env-file=.env rag-simple.js
import { pipeline } from "@huggingface/transformers";
import { askAI } from "./ai.js";

// 1. Your knowledge. In a real app this comes from PDFs, a website or a database.
const facts = [
  "Fees: you pay the doctor ₹500 for each visit (consultation charges).",
  "Clinic timings: Monday to Saturday 9 AM to 9 PM. On Sunday the clinic is open 10 AM to 1 PM.",
  "Dr. Mehta, the child specialist (paediatrician), sits on Monday, Wednesday and Friday.",
  "Free parking is available behind the building.",
  "Book an appointment on WhatsApp at 98XXXXXXXX.",
];

// 2. A free embedding model that runs on your computer (downloads once, ~120 MB).
const extractor = await pipeline("feature-extraction", "Xenova/paraphrase-multilingual-MiniLM-L12-v2");
const embed = async (texts) => (await extractor(texts, { pooling: "mean", normalize: true })).tolist();
const factVectors = await embed(facts); // turn every fact into numbers, once

// 3. Retrieval: find the facts closest in meaning to the question.
const similarity = (a, b) => a.reduce((sum, x, i) => sum + x * b[i], 0);
async function findFacts(question) {
  const [q] = await embed([question]);
  return facts
    .map((text, i) => ({ text, score: similarity(q, factVectors[i]) }))
    .filter((f) => f.score > 0.3)          // ignore weak matches
    .sort((a, b) => b.score - a.score)
    .slice(0, 2);                          // keep the best 2
}

// 4. Generation: the AI answers using only the facts we found.
async function answer(question) {
  const found = await findFacts(question);
  const info = found.map((f) => "- " + f.text).join("\n") || "(nothing found)";
  return askAI(
    `Clinic information:\n${info}\n\nQuestion: ${question}`,
    "You are a clinic receptionist. Answer ONLY from the clinic information. " +
      "If the answer is not there, say you will confirm with the team. Reply in the user's language."
  );
}

console.log(await answer("Sunday ko clinic khula hai?"));
console.log(await answer("बच्चों के डॉक्टर कब बैठते हैं?"));
console.log(await answer("Do you do X-rays?")); // not in the facts, so it should say it will confirm

Run it and notice: the Hinglish and Hindi questions find the right English facts (by meaning, not words), and the X-ray question finds nothing, so the AI gives an honest "I'll confirm" instead of a made-up answer. That is RAG. (We tested these 3 questions with this exact model.)

चलाइए और देखिए: Hinglish और Hindi सवाल सही English facts ढूँढ लेते हैं (शब्दों से नहीं, मतलब से), और X-ray वाले सवाल पर कुछ नहीं मिलता, इसलिए AI बनावटी जवाब की जगह ईमानदार "confirm करके बताएँगे" कहता है। यही RAG है। (ये 3 सवाल हमने इसी model से test किए हैं।)

Step 2: the real version with a databaseStep 2: Database वाला असली version

Senior levelSenior level

A list in memory is fine for 5 facts. For thousands of chunks, store them in PostgreSQL with pgvector, so search stays fast. Same idea, bigger scale. This is how a real WhatsApp clinic bot is built.

5 बातों के लिए memory की list ठीक है। हज़ारों chunks के लिए उन्हें pgvector वाले PostgreSQL में रखिए, ताकि search तेज़ रहे। वही idea, बड़ा पैमाना। असली WhatsApp clinic bot ऐसे ही बनता है।

1. The table (run once)1. Table (एक बार चलाइए)

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE chunks (
  id        SERIAL PRIMARY KEY,
  source    TEXT NOT NULL,          -- which document it came from
  content   TEXT NOT NULL,          -- the chunk text
  embedding VECTOR(384) NOT NULL    -- 384 numbers for this embedding model
);

2. Retrieve the closest chunks2. सबसे पास के chunks निकालें

// rag-db.js  (npm install pg @huggingface/transformers; DATABASE_URL in .env)
import pg from "pg";
import { pipeline } from "@huggingface/transformers";
import { askAI } from "./ai.js";

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const extractor = await pipeline("feature-extraction", "Xenova/paraphrase-multilingual-MiniLM-L12-v2");
const embed = async (texts) => (await extractor(texts, { pooling: "mean", normalize: true })).tolist();

// <=> is pgvector's cosine distance (0 = same meaning), so similarity = 1 - distance
async function retrieve(question, limit = 4) {
  const [vector] = await embed([question]);
  const { rows } = await pool.query(
    `SELECT source, content, 1 - (embedding <=> $1) AS similarity
     FROM chunks ORDER BY embedding <=> $1 LIMIT $2`,
    [JSON.stringify(vector), limit],
  );
  return rows.filter((r) => r.similarity >= 0.35); // ignore weak matches
}

3. Answer from the chunks only3. सिर्फ़ chunks से जवाब

const SYSTEM = `You are the receptionist of CareWell Clinic.
Answer ONLY using the information inside <context>.
If the answer is not there, say you'll confirm with the team. Never guess.`;

async function answer(question) {
  const chunks = await retrieve(question);
  const context = chunks.length
    ? chunks.map((c) => `<chunk source="${c.source}">\n${c.content}\n</chunk>`).join("\n")
    : "(no relevant information found)";

  const text = await askAI(`<context>\n${context}\n</context>\n\nQuestion: ${question}`, SYSTEM);
  return `${text}\n\nSources: ${[...new Set(chunks.map((c) => c.source))].join(", ")}`;
}

console.log(await answer("What are the clinic timings on Sunday?"));
await pool.end(); // close the database connection so the script can exit

To fill the table, a separate "ingest" script splits your documents into chunks, embeds each chunk with the same embed function, and inserts the rows. Run it once, and again whenever documents change.

Table भरने के लिए एक अलग "ingest" script आपके documents को chunks में बाँटती है, हर chunk का उसी embed function से embedding बनाती है, और rows insert करती है। इसे एक बार चलाइए, और documents बदलने पर दोबारा।

🎤 "RAG retrieves relevant chunks using embeddings and vector search, adds them to the prompt as context, and the LLM answers grounded in that context. It reduces hallucination and keeps knowledge fresh without retraining. I'd use fine-tuning only to change style or format, not to add facts."

🎤 "RAG retrieves relevant chunks using embeddings and vector search, adds them to the prompt as context, and the LLM answers grounded in that context. It reduces hallucination and keeps knowledge fresh without retraining. I'd use fine-tuning only to change style or format, not to add facts."

⚠️ Common mistakesआम ग़लतियाँ
  • No minimum similarity, so unrelated chunks get passed in and confuse the answer.कोई minimum similarity नहीं, जिससे बेमेल chunks जाकर जवाब को उलझाते हैं।
  • No "answer only from context" rule, so the model fills gaps with guesses."सिर्फ़ context से जवाब" का नियम नहीं, जिससे model ख़ाली जगह अंदाज़ों से भरता है।
  • Mixing different customers' documents without a filter.बिना filter के अलग-अलग customers के documents मिला देना।
  • Never testing with real user questions.असली users के सवालों से कभी test न करना।
📌 Remember these 3 thingsये 3 बातें याद रखिए
  1. Two phases: indexing (chunk, embed, store) once, and answering (retrieve, then generate) for every question.दो phases: indexing (chunk, embed, store) एक बार, और answering (retrieve, फिर generate) हर सवाल पर।
  2. Tell the AI to answer only from the given information, and to say so when it's missing.AI से कहिए कि सिर्फ़ दी गई जानकारी से जवाब दे, और जानकारी न हो तो बता दे।
  3. RAG adds knowledge; fine-tuning changes style. Changing data → RAG.RAG जानकारी जोड़ता है; fine-tuning style बदलती है। बदलता data → RAG।

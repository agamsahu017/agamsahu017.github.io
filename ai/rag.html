The problem RAG solvesRAG कौन-सी problem हल करता है

An LLM doesn't know your clinic's fees, your company's HR policy or yesterday's price list. Ask it, and it may guess. RAG (Retrieval-Augmented Generation) fixes this: first find the right information, then give it to the LLM together with the question.

LLM को आपके clinic की fees, आपकी company की HR policy या कल की price list नहीं पता। पूछेंगे, तो अंदाज़ा लगा सकता है। RAG (Retrieval-Augmented Generation) इसे ठीक करता है: पहले सही जानकारी ढूँढो, फिर सवाल के साथ LLM को दो।

Analogy: an open-book exam. The student (LLM) is smart, but instead of answering from memory, they first open the right page of the book (retrieval) and then write the answer (generation).

मिसाल: open-book exam। Student (LLM) होशियार है, पर याददाश्त से जवाब देने की जगह पहले किताब का सही पेज खोलता है (retrieval) और फिर जवाब लिखता है (generation)।

RAG in JavaScriptJavaScript में RAG

Senior levelSenior level

This uses PostgreSQL with pgvector to store chunks, a local embedding model, and Claude to write the answer. It's the same design as a real WhatsApp clinic bot.

यह chunks रखने के लिए pgvector वाला PostgreSQL, एक local embedding model, और जवाब लिखने के लिए Claude इस्तेमाल करता है। यह वही design है जो एक असली WhatsApp clinic bot का होता है।

1. The table (run once)1. Table (एक बार चलाइए)

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE chunks (
  id        SERIAL PRIMARY KEY,
  source    TEXT NOT NULL,          -- which document it came from
  content   TEXT NOT NULL,          -- the chunk text
  embedding VECTOR(384) NOT NULL    -- 384 numbers for this embedding model
);

2. Retrieve the closest chunks2. सबसे पास के chunks निकालें

// <=> is pgvector's cosine distance (0 = same meaning), so similarity = 1 - distance
async function retrieve(question, limit = 4) {
  const [vector] = await embed([question]);
  const { rows } = await pool.query(
    `SELECT source, content, 1 - (embedding <=> $1) AS similarity
     FROM chunks ORDER BY embedding <=> $1 LIMIT $2`,
    [JSON.stringify(vector), limit],
  );
  return rows.filter((r) => r.similarity >= 0.35); // ignore weak matches
}

3. Answer from the chunks only3. सिर्फ़ chunks से जवाब

const SYSTEM = `You are the receptionist of CareWell Clinic.
Answer ONLY using the information inside <context>.
If the answer is not there, say you'll confirm with the team. Never guess.`;

async function answer(question) {
  const chunks = await retrieve(question);
  const context = chunks.length
    ? chunks.map((c) => `<chunk source="${c.source}">\n${c.content}\n</chunk>`).join("\n")
    : "(no relevant information found)";

  const response = await client.beta.messages.create({
    model: "claude-opus-5-5",
    max_tokens: 16000,
    system: SYSTEM,
    messages: [{ role: "user", content: `<context>\n${context}\n</context>\n\nQuestion: ${question}` }],
    betas: ["server-side-fallback-2026-07-01"],
    fallbacks: "default",
  });

  if (response.stop_reason === "refusal") return "Sorry, I can't help with that.";
  const text = response.content.filter((b) => b.type === "text").map((b) => b.text).join("");
  return `${text}\n\nSources: ${[...new Set(chunks.map((c) => c.source))].join(", ")}`;
}

🎤 "RAG retrieves relevant chunks using embeddings and vector search, adds them to the prompt as context, and the LLM answers grounded in that context. It reduces hallucination and keeps knowledge fresh without retraining. I'd use fine-tuning only to change style or format, not to add facts."

🎤 "RAG retrieves relevant chunks using embeddings and vector search, adds them to the prompt as context, and the LLM answers grounded in that context. It reduces hallucination and keeps knowledge fresh without retraining. I'd use fine-tuning only to change style or format, not to add facts."

⚠️ Common mistakesआम ग़लतियाँ
  • No minimum similarity, so unrelated chunks get passed in and confuse the answer.कोई minimum similarity नहीं, जिससे बेमेल chunks जाकर जवाब को उलझाते हैं।
  • No "answer only from context" rule, so the model fills gaps with guesses."सिर्फ़ context से जवाब" का नियम नहीं, जिससे model ख़ाली जगह अंदाज़ों से भरता है।
  • Mixing different customers' documents without a filter.बिना filter के अलग-अलग customers के documents मिला देना।
  • Never testing with real user questions.असली users के सवालों से कभी test न करना।

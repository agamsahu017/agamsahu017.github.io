HTTP: how client and server talkHTTP: client और server कैसे बात करते हैं

Every request has a method (what you want to do) and a URL (on what). Every response has a status code (how it went) and usually some data.

हर request में एक method (क्या करना है) और एक URL (किस पर) होता है। हर response में एक status code (कैसा रहा) और आमतौर पर कुछ data होता है।

आसान नियम: 2xx = सफल, 4xx = client की ग़लती, 5xx = server की ग़लती।

APIs and JSONAPIs और JSON

An API is the list of things your server lets others do. A REST API uses nouns in URLs and HTTP methods for actions. Data travels as JSON.

API उन कामों की list है जो आपका server दूसरों को करने देता है। REST API URLs में nouns और काम के लिए HTTP methods इस्तेमाल करती है। Data JSON में जाता है।

// A JSON response for GET /users/42
{
  "id": 42,
  "name": "Riya Sharma",
  "city": "Lucknow",
  "courses": ["DSA", "System Design"]
}

The client side: calling an API from JavaScriptClient side: JavaScript से API call करना

const res = await fetch("https://api.example.com/users/42");
if (res.status === 200) {
  const user = await res.json();
  console.log(user.name); // "Riya Sharma"
}

The server side: a tiny API in Node.js (Express)Server side: Node.js (Express) में छोटी API

const express = require("express");
const app = express();
app.use(express.json());

const users = new Map([[42, { id: 42, name: "Riya Sharma" }]]);

app.get("/users/:id", (req, res) => {
  const user = users.get(Number(req.params.id));
  if (!user) return res.status(404).json({ error: "User not found" });
  res.json(user);                       // 200 OK
});

app.post("/users", (req, res) => {
  if (!req.body.name) return res.status(400).json({ error: "name is required" });
  const id = users.size + 100;
  users.set(id, { id, name: req.body.name });
  res.status(201).json(users.get(id));  // 201 Created
});

app.listen(3000);

Databases in 2 minutes2 मिनट में databases

A database stores data safely, even if the server restarts. The most common kind stores data in tables, like an Excel sheet: each row is one record, each column is one field, and the primary key uniquely identifies a row.

Database data को सुरक्षित रखता है, भले ही server restart हो जाए। सबसे common तरह का database data को tables में रखता है, Excel sheet जैसा: हर row एक record, हर column एक field, और primary key हर row को अलग पहचान देती है।

Latency vs throughputLatency vs throughput

  • Latency = how long one request takes. Like how long one customer waits for food.Latency = एक request में कितना समय लगता है। जैसे एक ग्राहक खाने के लिए कितनी देर रुकता है।
  • Throughput = how many requests the system handles per second. Like how many customers the restaurant serves per hour.Throughput = system हर second कितनी requests संभालता है। जैसे restaurant एक घंटे में कितने ग्राहकों को खाना देता है।
  • Adding more cooks (servers) raises throughput. Pre-cooking popular dishes (caching) lowers latency.ज़्यादा cooks (servers) से throughput बढ़ता है। Popular dishes पहले से बनाकर रखने (caching) से latency घटती है।
⚠️ Common mistakesआम ग़लतियाँ
  • Thinking the database lives inside the browser. The client never talks to the database directly: it goes through the server.यह सोचना कि database browser के अंदर है। Client कभी सीधे database से बात नहीं करता: हमेशा server के ज़रिए।
  • Using GET to change data, like GET /deleteUser?id=5. Use DELETE or POST.Data बदलने के लिए GET इस्तेमाल करना, जैसे GET /deleteUser?id=5। DELETE या POST इस्तेमाल कीजिए।
  • Returning 200 for every response, even errors.हर response के लिए 200 लौटाना, errors के लिए भी।
  • Verbs in REST URLs, like /getOrders. Prefer GET /orders.REST URLs में verbs, जैसे /getOrders। GET /orders बेहतर है।

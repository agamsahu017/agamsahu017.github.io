ACID in one line: a transaction happens fully or not at all, data stays valid, parallel transactions don't mix, and saved data isn't lost. That's why money goes in SQL.

ACID एक लाइन में: transaction या तो पूरा होता है या बिल्कुल नहीं, data सही रहता है, साथ चल रहे transactions आपस में नहीं मिलते, और save हुआ data खोता नहीं। इसीलिए पैसे का data SQL में जाता है।

Indexes: the book indexIndexes: किताब का index

Without an index, finding a user by email means checking every row: O(n). An index works like the index at the back of a book: it jumps almost straight to the right rows, roughly O(log n).

Index के बिना email से user ढूँढने का मतलब है हर row देखना: O(n)। Index किताब के पीछे वाले index की तरह काम करता है: लगभग सीधे सही rows पर पहुँचता है, लगभग O(log n)।

-- Find a user by email quickly
CREATE INDEX idx_users_email ON users (email);

-- A composite index helps queries that filter by both columns, in this order
CREATE INDEX idx_orders_user_date ON orders (user_id, created_at);
  • Index the columns you filter, join or sort by often.उन columns पर index लगाइए जिनसे आप अक्सर filter, join या sort करते हैं।
  • Hidden cost: every insert and update must also update each index, so writes get slower and storage grows. Don't index everything.छिपी cost: हर insert और update में हर index भी बदलता है, इसलिए writes धीमे होते हैं और storage बढ़ता है। हर चीज़ पर index मत लगाइए।

Replication: copies for reads and safetyReplication: reads और safety के लिए copies

  • Primary handles all writes. Replicas copy it and serve reads.Primary सारे writes संभालता है। Replicas उसकी copy रखते हैं और reads देते हैं।
  • Great for read-heavy apps: add replicas to handle more reads.Read-heavy apps के लिए बढ़िया: ज़्यादा reads के लिए replicas जोड़िए।
  • If the primary fails, a replica can be promoted to primary (failover).Primary fail हो, तो किसी replica को primary बनाया जा सकता है (failover)।
  • Replication lag: replicas may be a little behind. A user who just updated their profile might see the old one. Fix: read your own recent writes from the primary.Replication lag: replicas थोड़ा पीछे हो सकते हैं। जिस user ने अभी profile बदली, उसे पुरानी दिख सकती है। हल: अपने ताज़ा writes primary से पढ़िए।

Sharding: splitting the dataSharding: data को बाँटना

Senior levelSenior level

When one database can't hold all the data or handle all the writes, split the data across several databases called shards. Each shard holds a part of the data.

जब एक database सारा data नहीं रख पाता या सारे writes नहीं संभाल पाता, तो data को कई databases में बाँटिए जिन्हें shards कहते हैं। हर shard में data का एक हिस्सा होता है।

  • Shard key decides where each row goes, for example user_id. Choose one that spreads data evenly.Shard key तय करती है कि हर row कहाँ जाएगी, जैसे user_id। ऐसी key चुनिए जो data को बराबर बाँटे।
  • Hot shard: a bad key (like "country") can put most traffic on one shard.Hot shard: ग़लत key (जैसे "country") से ज़्यादातर traffic एक ही shard पर आ सकता है।
  • Cross-shard queries and joins become slow and complex. Design so most queries hit one shard.Cross-shard queries और joins धीमे और मुश्किल हो जाते हैं। ऐसा design कीजिए कि ज़्यादातर queries एक ही shard पर जाएँ।
  • Simple % N makes adding shards painful, because most data must move. Consistent hashing reduces that movement.सीधा % N नए shards जोड़ना मुश्किल बनाता है, क्योंकि ज़्यादातर data खिसकाना पड़ता है। Consistent hashing यह खिसकाव कम करता है।

Sharding is a last step. First try indexes, caching and read replicas. Say this in interviews: it shows maturity.

Sharding आख़िरी क़दम है। पहले indexes, caching और read replicas आज़माइए। Interview में यह बोलिए: इससे maturity दिखती है।

⚠️ Common mistakesआम ग़लतियाँ
  • Choosing NoSQL "because it scales" for data that needs transactions, like payments.Payments जैसे transactions वाले data के लिए "scale होता है" कहकर NoSQL चुनना।
  • Jumping to sharding before indexes, caching and replicas.Indexes, caching और replicas से पहले sharding पर कूदना।
  • Forgetting replication lag when a user reads right after writing.Write के तुरंत बाद read करने पर replication lag भूल जाना।
  • Adding an index on every column.हर column पर index लगा देना।

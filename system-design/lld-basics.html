What happens in an LLD roundLLD round में क्या होता है

You get a problem like "Design a parking lot" or "Design Splitwise". You must find the classes, connect them, and often write working code in 60–90 minutes. Freshers are asked this a lot.

आपको "Parking lot design करो" या "Splitwise design करो" जैसा सवाल मिलता है। आपको classes ढूँढनी हैं, उन्हें जोड़ना है, और अक्सर 60–90 मिनट में चलने वाला code लिखना है। Freshers से यह बहुत पूछा जाता है।

  1. Clarify scope: which features are in, which are out.Scope साफ़ करो: कौन-से features अंदर, कौन-से बाहर।
  2. Find entities: the nouns become classes (ParkingLot, Floor, Spot, Vehicle, Ticket).Entities ढूँढो: nouns classes बनते हैं (ParkingLot, Floor, Spot, Vehicle, Ticket)।
  3. Relationships: has-a (a Floor has Spots) and is-a (a Car is a Vehicle).Relationships: has-a (Floor के पास Spots हैं) और is-a (Car एक Vehicle है)।
  4. Methods: the verbs become methods (park, unpark, calculateFee).Methods: verbs methods बनते हैं (park, unpark, calculateFee)।
  5. Code the core flow first, then add extras and patterns where they fit naturally.पहले मुख्य flow code करो, फिर extras और patterns जहाँ सही बैठें।

Classes and the 4 pillars of OOPClasses और OOP के 4 pillars

Beginnerशुरुआती

1. Encapsulation: hide the details1. Encapsulation: अंदर की बातें छिपाओ

Keep data private and allow changes only through methods. In JavaScript, # makes a field private.

Data को private रखो और बदलाव सिर्फ़ methods से होने दो। JavaScript में # किसी field को private बनाता है।

class BankAccount {
  #balance = 0;                       // private: can't be changed from outside

  deposit(amount) {
    if (amount <= 0) throw new Error("Amount must be positive");
    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const acc = new BankAccount();
acc.deposit(500);
console.log(acc.getBalance()); // 500
// acc.#balance = 1000000;     // SyntaxError: private field

2. Abstraction: show only what matters2. Abstraction: सिर्फ़ ज़रूरी चीज़ दिखाओ

A driver uses the steering wheel and pedals, not the engine's internals. Your class should offer simple methods like sendEmail(to, text) and hide the complex parts.

Driver steering और pedals इस्तेमाल करता है, engine के अंदर के पुर्ज़े नहीं। आपकी class को sendEmail(to, text) जैसे आसान methods देने चाहिए और मुश्किल हिस्से छिपाने चाहिए।

3. Inheritance: reuse with "is-a"3. Inheritance: "is-a" से दोबारा इस्तेमाल

class Vehicle {
  constructor(number) { this.number = number; }
  describe() { return `Vehicle ${this.number}`; }
}

class Car extends Vehicle {            // a Car IS A Vehicle
  wheels() { return 4; }
}

const car = new Car("UP32 AB 1234");
console.log(car.describe(), car.wheels()); // Vehicle UP32 AB 1234 4

4. Polymorphism: same method, different behaviour4. Polymorphism: एक method, अलग व्यवहार

class Shape { area() { return 0; } }
class Circle extends Shape {
  constructor(r) { super(); this.r = r; }
  area() { return Math.PI * this.r ** 2; }
}
class Square extends Shape {
  constructor(s) { super(); this.s = s; }
  area() { return this.s * this.s; }
}

for (const shape of [new Circle(1), new Square(2)]) {
  console.log(shape.area()); // each shape answers in its own way
}

SOLID principles, simplySOLID principles, आसान भाषा में

S: Single ResponsibilityS: Single Responsibility

A class should have one job, so it has one reason to change.

एक class का एक ही काम होना चाहिए, ताकि उसे बदलने की एक ही वजह हो।

// Bad: creating invoices AND sending emails AND saving files
class InvoiceService { create() {} sendEmail() {} saveToDisk() {} }

// Good: each class has one job
class InvoiceService { create(order) { /* build the invoice */ } }
class EmailService   { send(to, body) { /* send email */ } }
class InvoiceStorage { save(invoice) { /* save it */ } }

O: Open/ClosedO: Open/Closed

Open to add new behaviour, closed to editing old, tested code. Add a new class instead of another if.

नया व्यवहार जोड़ने के लिए खुला, पुराने tested code को बदलने के लिए बंद। एक और if की जगह नई class जोड़िए।

// Bad: every new payment method means editing this function
function pay(method, amount) {
  if (method === "upi") { /* ... */ }
  else if (method === "card") { /* ... */ }
}

// Good: add a new class; existing code doesn't change
class UpiPayment  { pay(amount) { console.log("UPI", amount); } }
class CardPayment { pay(amount) { console.log("Card", amount); } }
function checkout(paymentMethod, amount) { paymentMethod.pay(amount); }

checkout(new UpiPayment(), 499);

L: Liskov SubstitutionL: Liskov Substitution

A child class must work anywhere the parent works, without surprises. If Penguin extends Bird but fly() throws an error, code that expects any Bird to fly breaks. Fix: don't put fly() in Bird; use a separate FlyingBird.

Child class को हर उस जगह बिना गड़बड़ के चलना चाहिए जहाँ parent चलता है। अगर Penguin extends Bird पर fly() error दे, तो हर Bird से उड़ने की उम्मीद करने वाला code टूट जाता है। हल: fly() को Bird में मत रखिए; अलग FlyingBird बनाइए।

I: Interface SegregationI: Interface Segregation

Don't force a class to have methods it doesn't need. A simple printer shouldn't be forced to implement scan() and fax(). Keep contracts small and focused.

किसी class पर ऐसे methods मत थोपिए जिनकी उसे ज़रूरत नहीं। एक आसान printer से scan() और fax() बनवाना ग़लत है। Contracts छोटे और focused रखिए।

D: Dependency InversionD: Dependency Inversion

Depend on an abstraction passed in from outside, not on a concrete class created inside. This makes code easy to test and swap. NestJS does this with dependency injection.

अंदर बनाई गई concrete class पर नहीं, बाहर से दी गई abstraction पर निर्भर रहिए। इससे code test करना और बदलना आसान होता है। NestJS यही dependency injection से करता है।

// Bad: OrderService is stuck with one email provider
class OrderService {
  constructor() { this.mailer = new GmailMailer(); }
}

// Good: any mailer with a send() method can be passed in
class OrderService {
  constructor(mailer) { this.mailer = mailer; }
  placeOrder(order) {
    // ...save the order...
    this.mailer.send(order.email, "Order placed!");
  }
}

const service = new OrderService(new FakeMailer()); // easy to test

🎤 "I'll inject the payment gateway through the constructor, so switching providers or mocking it in tests needs no change to OrderService. That's dependency inversion."

🎤 "I'll inject the payment gateway through the constructor, so switching providers or mocking it in tests needs no change to OrderService. That's dependency inversion."

Composition over inheritanceInheritance की जगह composition

Senior levelSenior level

Inheritance chains get messy (FlyingSwimmingRobotDuck?). Often it's better for a class to have helpers than to be a subclass.

Inheritance की लंबी chains उलझ जाती हैं (FlyingSwimmingRobotDuck?)। अक्सर class का helpers रखना, subclass होने से बेहतर है।

class Engine { start() { return "engine on"; } }
class MusicSystem { play() { return "music on"; } }

class Car {
  constructor() {
    this.engine = new Engine();       // Car HAS an engine
    this.music = new MusicSystem();   // Car HAS a music system
  }
  drive() { return `${this.engine.start()}, ${this.music.play()}`; }
}
⚠️ Common mistakesआम ग़लतियाँ
  • Starting to code before listing the entities and their relationships.Entities और उनके relationships लिखे बिना code शुरू कर देना।
  • One giant class that does everything (a "God class").एक बड़ी class जो सब कुछ करे ("God class")।
  • Long if / else chains on type, instead of polymorphism.Polymorphism की जगह type पर लंबी if / else chains।
  • Forcing patterns in where they don't fit, just to show them off.दिखाने के लिए patterns ज़बरदस्ती वहाँ लगाना जहाँ वो फ़िट नहीं बैठते।
  • Public fields that anyone can change, like account.balance = -500.Public fields जिन्हें कोई भी बदल दे, जैसे account.balance = -500।

Practiceप्रैक्टिस

Exercise 1: Design the classes for a simple library system: members borrow and return books, with a fine for late returns. List the classes, their fields and their methods.Exercise 1: एक आसान library system की classes design कीजिए: members books लेते और लौटाते हैं, देर से लौटाने पर fine लगता है। Classes, उनके fields और methods लिखिए।

Show a sample answerएक sample जवाब देखें
class Book    { constructor(id, title, author) { this.id = id; this.title = title; this.author = author; this.available = true; } }
class Member  { constructor(id, name) { this.id = id; this.name = name; this.loans = []; } }
class Loan    { constructor(book, member, dueDate) { this.book = book; this.member = member; this.dueDate = dueDate; this.returnedAt = null; } }

class FinePolicy {                     // separate class: easy to change the rule later
  constructor(perDay = 10) { this.perDay = perDay; }
  calculate(loan) {
    const lateDays = Math.max(0, Math.ceil((loan.returnedAt - loan.dueDate) / 86400000));
    return lateDays * this.perDay;
  }
}

class Library {
  constructor(finePolicy) { this.books = new Map(); this.finePolicy = finePolicy; }
  addBook(book) { this.books.set(book.id, book); }
  borrow(bookId, member, days = 14) {
    const book = this.books.get(bookId);
    if (!book || !book.available) throw new Error("Book not available");
    book.available = false;
    const loan = new Loan(book, member, new Date(Date.now() + days * 86400000));
    member.loans.push(loan);
    return loan;
  }
  returnBook(loan) {
    loan.returnedAt = new Date();
    loan.book.available = true;
    return this.finePolicy.calculate(loan); // fine in rupees
  }
}

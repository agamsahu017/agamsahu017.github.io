Why cache?Cache क्यों?

Reading from memory is many times faster than reading from a database on disk, and it saves the database from repeated work. A cache keeps frequently used data in memory.

Memory से पढ़ना, disk वाले database से पढ़ने से कई गुना तेज़ है, और इससे database बार-बार एक ही काम करने से बचता है। Cache बार-बार इस्तेमाल होने वाला data memory में रखता है।

Analogy: a shopkeeper keeps the fast-selling items on the counter (cache) and everything else in the godown (database).

मिसाल: दुकानदार जल्दी बिकने वाला सामान counter पर (cache) रखता है और बाक़ी सब godown में (database)।

Cache-aside: the most common strategyCache-aside: सबसे common strategy

Beginnerशुरुआती 
async function getProduct(id) {
  const key = `product:${id}`;

  const cached = await redis.get(key);          // 1. try the cache
  if (cached) return JSON.parse(cached);        // hit: fast

  const product = await db.products.findById(id); // 2. miss: read the database
  await redis.set(key, JSON.stringify(product), "EX", 300); // 3. keep for 5 minutes
  return product;
}

async function updateProduct(id, data) {
  await db.products.update(id, data);
  await redis.del(`product:${id}`);           // invalidate, so nobody sees old data
}

TTL and eviction: what leaves the cacheTTL और eviction: cache से क्या हटता है

  • TTL (time to live): each item expires after a set time, like 5 minutes. Old data can't stay forever.TTL (time to live): हर item एक तय समय बाद expire होता है, जैसे 5 मिनट। पुराना data हमेशा नहीं रह सकता।
  • Eviction: memory is limited. When the cache is full, something must go. LRU (Least Recently Used) removes the item that hasn't been used for the longest time.Eviction: memory सीमित है। Cache भर जाए तो कुछ हटाना पड़ता है। LRU (Least Recently Used) वो item हटाता है जो सबसे लंबे समय से इस्तेमाल नहीं हुआ।

The hard parts of cachingCaching के मुश्किल हिस्से

Senior levelSenior level
  • Invalidation: when data changes, the cached copy is stale. Delete or update the key on every write, and use a TTL as a safety net.Invalidation: Data बदलने पर cached copy पुरानी हो जाती है। हर write पर key delete या update कीजिए, और safety के लिए TTL रखिए।
  • Cache stampede: a popular key expires and thousands of requests hit the database at once. Fix: let only one request rebuild it (a lock), or refresh before expiry, or add random jitter to TTLs.Cache stampede: एक popular key expire होती है और हज़ारों requests एक साथ database पर पहुँचती हैं। हल: सिर्फ़ एक request को rebuild करने दो (lock), या expiry से पहले refresh करो, या TTL में थोड़ा random फ़र्क़ डालो।
  • Hot key: one key (a celebrity's profile, a live match score) gets enormous traffic. Fix: keep copies on several cache nodes or a small in-app cache.Hot key: एक key (किसी celebrity की profile, live match score) पर भारी traffic आता है। हल: कई cache nodes पर copies रखो, या app के अंदर छोटा cache।
  • What not to cache: data that must always be exact at that moment, like a bank balance during a transfer.क्या cache न करें: वो data जो उसी पल बिल्कुल सही होना चाहिए, जैसे transfer के दौरान bank balance।

CDN: content near the userCDN: user के पास content

A CDN (Content Delivery Network) keeps copies of static files (images, videos, CSS, JS) on servers around the world. Users download from the nearest one: faster pages and much less load on your servers.

CDN (Content Delivery Network) static files (images, videos, CSS, JS) की copies दुनिया भर के servers पर रखता है। Users सबसे पास वाले से download करते हैं: तेज़ pages और आपके servers पर बहुत कम बोझ।

🎤 "Images and videos go to object storage like S3, served through a CDN. The database only stores the file URL, never the file itself."

🎤 "Images and videos go to object storage like S3, served through a CDN. The database only stores the file URL, never the file itself."

⚠️ Common mistakesआम ग़लतियाँ
  • Adding a cache without saying how it is invalidated.Cache लगाना पर यह न बताना कि invalidate कैसे होगा।
  • Caching everything, including data that must always be exact.सब कुछ cache करना, उस data को भी जो हमेशा सटीक होना चाहिए।
  • No TTL, so stale data stays forever after a missed invalidation.TTL न रखना, जिससे invalidation छूटने पर पुराना data हमेशा रहता है।
  • Serving images from the app server instead of a CDN.Images को CDN की जगह app server से serve करना।

Practiceप्रैक्टिस

Exercise 1: A news website's homepage is opened 50 lakh times a day, and editors update it about every 10 minutes. Design the caching.Exercise 1: एक news website का homepage रोज़ 50 लाख बार खुलता है, और editors इसे लगभग हर 10 मिनट में अपडेट करते हैं। Caching design कीजिए।

Show a sample answerएक sample जवाब देखें
  • Cache the rendered homepage (or its API response) in Redis with a TTL of about 1 minute. Most visitors never touch the database.Rendered homepage (या उसका API response) Redis में लगभग 1 मिनट के TTL के साथ cache कीजिए। ज़्यादातर visitors database तक पहुँचते ही नहीं।
  • When an editor publishes, delete the key so the next request rebuilds it with fresh news.Editor publish करे, तो key delete कीजिए ताकि अगली request ताज़ा ख़बरों के साथ उसे दोबारा बनाए।
  • Prevent a stampede: only one request rebuilds the page while others get the old copy for a moment.Stampede रोकिए: सिर्फ़ एक request page दोबारा बनाए, बाक़ी को एक पल के लिए पुरानी copy मिले।
  • Serve all images, CSS and JS through a CDN.सारी images, CSS और JS CDN से serve कीजिए।

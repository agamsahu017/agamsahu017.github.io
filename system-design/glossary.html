System design glossarySystem design glossary

59 words you'll hear in system design, each explained in one or two simple lines. Use the search box to find a word quickly.

System design में सुनाई देने वाले 59 शब्द, हर एक का मतलब एक-दो आसान लाइनों में। किसी शब्द को जल्दी ढूँढने के लिए search box इस्तेमाल कीजिए।

Web basicsWeb basics

Client
The app or browser that asks for something, like your phone's WhatsApp or Chrome.वो app या browser जो कुछ माँगता है, जैसे आपके phone का WhatsApp या Chrome।
Server
A computer that runs your backend code and answers requests from clients.एक computer जो आपका backend code चलाता है और clients की requests का जवाब देता है।
Request
A message from the client to the server asking for data or an action.Client से server को भेजा गया message, जिसमें data या कोई काम माँगा जाता है।
Response
The server's reply to a request, usually with data and a status code.Request पर server का जवाब, आमतौर पर data और status code के साथ।
HTTP / HTTPS
The language browsers and servers use to talk. HTTPS is the encrypted, secure version.वो भाषा जिसमें browser और server बात करते हैं। HTTPS उसका encrypted, सुरक्षित रूप है।
API
A set of URLs (endpoints) your server offers so other programs can ask it for data or actions.URLs (endpoints) का एक set जो server देता है, ताकि दूसरे programs उससे data या काम माँग सकें।
Endpoint
One URL of an API, like GET /users/42.API का एक URL, जैसे GET /users/42।
REST
A common style for APIs: URLs name the things (/orders) and HTTP methods say the action (GET, POST).APIs का एक common style: URL चीज़ का नाम बताते हैं (/orders) और HTTP methods काम (GET, POST)।
JSON
A simple text format for data, like { "name": "Riya" }. Most APIs send JSON.Data के लिए एक आसान text format, जैसे { "name": "Riya" }। ज़्यादातर APIs JSON भेजती हैं।
Status code
A number in the response: 200 = OK, 404 = not found, 500 = server error.Response में एक number: 200 = OK, 404 = नहीं मिला, 500 = server error।
DNS
The internet's phonebook: turns a name like google.com into an IP address.Internet की phonebook: google.com जैसे नाम को IP address में बदलता है।
IP address
The numeric address of a computer on the internet, like 142.250.183.14.Internet पर किसी computer का number वाला address, जैसे 142.250.183.14।
Webhook
A URL on your server that another service calls when something happens, like "payment succeeded".आपके server का एक URL जिसे कोई दूसरी service कुछ होने पर call करती है, जैसे "payment हो गया"।
WebSocket
A connection that stays open so the server can push messages instantly, used in chat apps.एक connection जो खुला रहता है ताकि server तुरंत messages भेज सके, chat apps में इस्तेमाल होता है।

Scale and performanceScale और performance

Latency
How long one request takes, for example 120 milliseconds. Lower is better.एक request में कितना समय लगता है, जैसे 120 milliseconds। जितना कम, उतना अच्छा।
Throughput
How many requests a system handles per second.System एक second में कितनी requests संभालता है।
QPS
Queries (requests) per second. 1,000 QPS = a thousand requests every second.Queries (requests) per second। 1,000 QPS = हर second हज़ार requests।
Scalability
The ability to handle more users by adding resources.Resources बढ़ाकर ज़्यादा users संभालने की क्षमता।
Vertical scaling
Making one machine bigger (more CPU and RAM).एक ही machine को बड़ा करना (ज़्यादा CPU और RAM)।
Horizontal scaling
Adding more machines that share the work.और machines जोड़ना जो काम बाँट लें।
Load balancer
Sits in front of servers and spreads incoming requests across them.Servers के आगे बैठता है और आने वाली requests को उनमें बाँटता है।
Stateless
A server that keeps no user data in its own memory between requests, so any server can serve any user.ऐसा server जो requests के बीच user का data अपनी memory में नहीं रखता, ताकि कोई भी server किसी भी user को serve कर सके।
Session
Information that keeps a user logged in across requests.वो जानकारी जिससे user requests के बीच logged in रहता है।
JWT
JSON Web Token: a signed token the client sends with each request to prove who it is.JSON Web Token: एक signed token जो client हर request के साथ भेजता है यह साबित करने के लिए कि वो कौन है।
Single point of failure (SPOF)
A part with only one copy. If it fails, the whole system fails.ऐसा हिस्सा जिसकी सिर्फ़ एक copy हो। वो fail हो, तो पूरा system fail।
Bottleneck
The slowest part that limits the whole system, like a narrow bottle neck.सबसे धीमा हिस्सा जो पूरे system को रोकता है, जैसे बोतल की पतली गर्दन।
Monolith
One application containing all features, deployed together. Simple to start with.एक ही application जिसमें सारे features हों, एक साथ deploy हो। शुरुआत में आसान।
Microservices
Many small services, each owning one feature, deployed separately. Flexible but more complex.कई छोटी services, हर एक के पास एक feature, अलग-अलग deploy। Flexible पर ज़्यादा मुश्किल।

DatabasesDatabases

Database
Software that stores data safely on disk and lets you search and update it.Software जो data को disk पर सुरक्षित रखता है और उसे ढूँढने और बदलने देता है।
SQL database
A database with tables, columns and relations, like PostgreSQL or MySQL.Tables, columns और relations वाला database, जैसे PostgreSQL या MySQL।
NoSQL database
A database with a flexible structure (documents, key-value), built to spread across many machines.Flexible structure (documents, key-value) वाला database, कई machines पर फैलने के लिए बना।
Transaction
A group of database changes that happen together, or not at all.Database के बदलावों का समूह जो साथ में होते हैं, या बिल्कुल नहीं होते।
ACID
Promises of a good transaction: all-or-nothing, valid data, no mixing, and saved data isn't lost.अच्छे transaction के वादे: पूरा या कुछ नहीं, सही data, आपस में न मिलना, और save हुआ data न खोना।
Primary key
A column that uniquely identifies each row, like user id.एक column जो हर row को अलग पहचान देता है, जैसे user id।
Index
A lookup structure that makes searching a column fast, like a book's index.एक lookup structure जो किसी column में ढूँढना तेज़ करता है, जैसे किताब का index।
Replica / replication
A copy of a database that stays in sync. Replicas serve reads and can take over on failure.Database की copy जो साथ-साथ अपडेट होती रहती है। Replicas reads देते हैं और failure पर काम सँभाल सकते हैं।
Replication lag
The small delay before a replica receives the latest changes.Replica तक ताज़ा बदलाव पहुँचने में लगने वाली छोटी देरी।
Sharding
Splitting data across several databases, each holding a part.Data को कई databases में बाँटना, हर एक में एक हिस्सा।
Shard key
The field that decides which shard a row goes to, like user_id.वो field जो तय करती है कि row किस shard में जाएगी, जैसे user_id।
Failover
Automatically switching to a backup when the main machine fails.Main machine fail होने पर अपने आप backup पर चले जाना।

CachingCaching

Cache
Fast memory that keeps frequently used data so you don't fetch it again from a slow source.तेज़ memory जो बार-बार इस्तेमाल होने वाला data रखती है, ताकि धीमी जगह से दोबारा न लाना पड़े।
Cache hit / miss
Hit: the data was in the cache (fast). Miss: it wasn't, so we read the database (slow).Hit: data cache में मिल गया (तेज़)। Miss: नहीं मिला, तो database पढ़ा (धीमा)।
TTL
Time to live: how long a cached item is kept before it expires.Time to live: cache में रखा item कितनी देर बाद expire होगा।
LRU
Least Recently Used: when the cache is full, remove the item unused for the longest time.Least Recently Used: cache भरने पर वो item हटाओ जो सबसे लंबे समय से इस्तेमाल नहीं हुआ।
Cache invalidation
Removing or updating cached data when the original data changes.Original data बदलने पर cached data को हटाना या अपडेट करना।
CDN
Content Delivery Network: servers around the world that keep copies of images, videos and files close to users.Content Delivery Network: दुनिया भर के servers जो images, videos और files की copies users के पास रखते हैं।

Async workAsync काम

Message queue
A waiting line for jobs. The API adds a job and replies fast; a worker does the job later.Jobs की एक लाइन। API job जोड़कर जल्दी जवाब देता है; worker बाद में job करता है।
Asynchronous (async)
Work that happens in the background, without making the user wait.Background में होने वाला काम, बिना user को इंतज़ार कराए।

ReliabilityReliability

Availability
How much of the time the system is up and working, like 99.9%.System कितने समय चालू और काम करता रहता है, जैसे 99.9%।
Consistency
Whether everyone sees the latest data. Eventual consistency means it becomes the same everywhere after a short time.क्या सबको ताज़ा data दिखता है। Eventual consistency का मतलब है थोड़ी देर बाद हर जगह एक जैसा हो जाता है।
CAP theorem
When the network between servers breaks, you must choose: always correct data (consistency) or always answer (availability).Servers के बीच network टूटे, तो चुनना पड़ता है: हमेशा सही data (consistency) या हमेशा जवाब (availability)।
Idempotency
Doing the same request twice has the same effect as doing it once. Vital for payments.एक ही request दो बार करने का असर एक बार करने जैसा हो। Payments के लिए बहुत ज़रूरी।
Rate limiting
Limiting how many requests a user can make, like 100 per minute, to protect the system.User कितनी requests कर सकता है उसकी सीमा, जैसे 100 per minute, system को बचाने के लिए।
Health check
A regular ping to see if a server is alive. Unhealthy servers get no traffic.Server ज़िंदा है या नहीं, यह देखने के लिए नियमित ping। बीमार servers को traffic नहीं मिलता।

ToolsTools

Redis
A very fast in-memory store, used for caching, sessions, counters and rate limits.बहुत तेज़ in-memory store, caching, sessions, counters और rate limits के लिए।
Kafka / SQS / RabbitMQ
Message queue tools that pass jobs and events between services.Message queue tools जो services के बीच jobs और events पहुँचाते हैं।
S3 (object storage)
Cloud storage for files like images, videos and PDFs. The database stores only the file's URL.Images, videos और PDFs जैसी files के लिए cloud storage। Database सिर्फ़ file का URL रखता है।
PostgreSQL / MySQL
Popular SQL databases for structured data and transactions.Structured data और transactions के लिए popular SQL databases।
MongoDB / DynamoDB / Cassandra
Popular NoSQL databases for flexible or very large data.Flexible या बहुत बड़े data के लिए popular NoSQL databases।

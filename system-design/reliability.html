Rate limiting and reliabilityRate limiting और reliability

In one line: Give every call a timeout, retry only temporary failures with backoff and jitter, rate-limit users, and use a circuit breaker so one sick service can't take everything down.

Retries and rate limiting in codeCode में retries और rate limiting

Senior levelSenior level

Backoff means waiting longer after each failure. Jitter adds a little randomness so a thousand clients don't all retry at the same second. Only retry safe (idempotent) operations, and only for temporary errors like timeouts or 503, never for 400 or 403.

Backoff का मतलब है हर failure के बाद ज़्यादा देर रुकना। Jitter थोड़ा random-पन जोड़ता है ताकि हज़ार clients एक ही second में retry न करें। सिर्फ़ सुरक्षित (idempotent) operations retry कीजिए, और सिर्फ़ थोड़ी देर वाली errors जैसे timeout या 503 पर, 400 या 403 पर कभी नहीं।

// 1) Retry with exponential backoff + jitter
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
async function withRetry(fn, attempts = 4, baseMs = 100) {
  for (let i = 1; i <= attempts; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === attempts) throw err;
      const wait = baseMs * 2 ** (i - 1) + Math.random() * 50; // 100, 200, 400 ms + a little jitter
      console.log(`attempt ${i} failed (${err.message}), retrying`);
      await sleep(wait);
    }
  }
}

let calls = 0;
const flakyApi = async () => {
  calls++;
  if (calls < 3) throw new Error("timeout");
  return "OK";
};
console.log("result:", await withRetry(flakyApi));

// 2) Token bucket rate limiter: 3 requests at once, then 1 more every second
function tokenBucket(capacity, refillPerSec) {
  let tokens = capacity, last = 0;
  return (nowMs) => {
    tokens = Math.min(capacity, tokens + ((nowMs - last) / 1000) * refillPerSec);
    last = nowMs;
    if (tokens >= 1) { tokens -= 1; return "allowed"; }
    return "429 Too Many Requests";
  };
}
const allow = tokenBucket(3, 1);
for (const t of [0, 0, 0, 0, 0, 1000]) console.log(`t=${t}ms:`, allow(t));

The token bucket is like a bowl of 3 tokens that refills by 1 every second. Each request takes a token; no token means "wait" (HTTP 429). It allows short bursts but limits the average. With many servers, keep the counts in Redis so all servers share them.

Token bucket 3 tokens के कटोरे जैसा है जो हर second 1 token से भरता है। हर request एक token लेती है; token नहीं तो "रुकिए" (HTTP 429)। यह थोड़ी देर की भीड़ allow करता है पर औसत को सीमित रखता है। कई servers हों तो गिनती Redis में रखिए ताकि सब servers उसे share करें।

Circuit breaker: stop hitting a sick serviceCircuit breaker: बीमार service को बार-बार मत मारिए

Senior levelSenior level

If the payment service is down, retrying every request makes things worse: your threads pile up waiting, and the sick service can't recover. A circuit breaker, like the trip switch at home, opens after a few failures and fails fast for a while. After a cool-down it lets one trial request through (half-open). If that works, it closes again.

अगर payment service बंद है, तो हर request retry करना हालत बिगाड़ता है: आपके threads इंतज़ार में जमा होते हैं, और बीमार service ठीक नहीं हो पाती। Circuit breaker, घर के trip switch की तरह, कुछ failures के बाद खुल जाता है और कुछ देर तुरंत fail करता है। Cool-down के बाद एक trial request जाने देता है (half-open)। वो चली तो फिर बंद हो जाता है।

The service starts DOWN. Send 3 requests, then try a 4th.Service शुरू में DOWN है। 3 requests भेजिए, फिर चौथी आज़माइए।
// Circuit breaker: after 3 failures, stop calling the sick service for a while.
class CircuitBreaker {
  constructor(fn, { failLimit = 3, coolDownMs = 5000 } = {}) {
    Object.assign(this, { fn, failLimit, coolDownMs, failures: 0, state: "CLOSED", openedAt: 0 });
  }
  call(now) {
    if (this.state === "OPEN") {
      if (now - this.openedAt < this.coolDownMs) return "fail fast (circuit OPEN)";
      this.state = "HALF-OPEN"; // cool-down over: allow one trial call
    }
    try {
      const result = this.fn();
      this.failures = 0;
      this.state = "CLOSED";
      return result;
    } catch {
      this.failures++;
      if (this.state === "HALF-OPEN" || this.failures >= this.failLimit) {
        this.state = "OPEN";
        this.openedAt = now;
      }
      return "error";
    }
  }
}

let serviceUp = false;
const breaker = new CircuitBreaker(() => { if (!serviceUp) throw new Error("down"); return "OK"; });
for (const t of [0, 100, 200, 300, 400]) console.log(`t=${t}:`, breaker.call(t), `[${breaker.state}]`);
serviceUp = true;
console.log("t=6000:", breaker.call(6000), `[${breaker.state}]`);

📌 Remember these 4 thingsये 4 बातें याद रखिए
  1. Timeout everything. A call with no timeout can hang forever.हर चीज़ पर timeout। बिना timeout की call हमेशा अटकी रह सकती है।
  2. Retry only temporary errors, with exponential backoff + jitter.सिर्फ़ थोड़ी देर वाली errors retry कीजिए, exponential backoff + jitter के साथ।
  3. Token bucket allows bursts but limits the average; return 429.Token bucket थोड़ी भीड़ allow करता है पर औसत सीमित रखता है; 429 लौटाइए।
  4. Circuit breaker: CLOSED → OPEN → HALF-OPEN → CLOSED.Circuit breaker: CLOSED → OPEN → HALF-OPEN → CLOSED।

Exercise 1: Your checkout calls a payment gateway that sometimes takes 40 seconds and sometimes fails. Users see a spinning wheel forever. What do you add?Exercise 1: आपका checkout एक payment gateway call करता है जो कभी 40 second लेता है और कभी fail होता है। Users को हमेशा घूमता चक्का दिखता है। आप क्या जोड़ेंगे?

Show a sample answerएक sample जवाब देखें
  • A timeout (for example 10 seconds) on the gateway call.Gateway call पर timeout (जैसे 10 second)।
  • Retries with backoff only for timeouts and 5xx, using an idempotency key so the customer is never charged twice.सिर्फ़ timeouts और 5xx पर backoff के साथ retries, idempotency key के साथ ताकि customer से दो बार पैसा न कटे।

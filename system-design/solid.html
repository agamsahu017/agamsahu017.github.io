SOLID principles, the easy waySOLID principles, सबसे आसान तरीक़े से

⏱️ 25 min read + practice25 मिनट पढ़ाई + प्रैक्टिस🏗️ HLD + LLD🎯 Interview focusedइंटरव्यू के हिसाब से

In one line: SOLID = one job per class, add instead of edit, replacements must behave the same, small contracts, and plug helpers in instead of gluing them.

एक लाइन में: SOLID = हर class का एक काम, बदलने की जगह जोड़ना, replacement वैसे ही चले, छोटे contracts, और helpers चिपकाने की जगह plug करना।

SOLID in one minuteएक minute में SOLID

Beginnerशुरुआती

SOLID is 5 simple rules for writing classes that are easy to change without breaking other things. You don't need to memorise definitions; remember the pictures.

SOLID पाँच आसान नियम हैं, ऐसी classes लिखने के लिए जिन्हें बिना कुछ और तोड़े आसानी से बदला जा सके। Definitions रटने की ज़रूरत नहीं; तस्वीरें याद रखिए।

S: Single Responsibility (one class, one job)S: Single Responsibility (एक class, एक काम)

Beginnerशुरुआती

At a busy chai stall, if one person makes chai, takes money and washes cups, everything slows down, and changing how payments work disturbs the chai-making too. Give each job to one person, and each job to one class.

भीड़ वाली chai stall पर अगर एक ही आदमी चाय बनाए, पैसे ले और कप धोए, तो सब धीमा हो जाता है, और payment का तरीक़ा बदलने से चाय बनाना भी गड़बड़ाता है। हर काम एक इंसान को दीजिए, और हर काम एक class को।

Warning sign: a class name with "and" in its description, or a file you open for many unrelated reasons ("the Report class calculates, formats and emails").

चेतावनी: class के description में "और" आए, या वो file जिसे आप कई अलग-अलग वजहों से खोलते हैं ("Report class हिसाब भी करती है, format भी, और email भी")।

// S: one class, one job. Calculating, formatting and sending are separate jobs.
class SalesReport {
  constructor(sales) { this.sales = sales; }
  total() { return this.sales.reduce((sum, s) => sum + s.amount, 0); }
}
class ReportFormatter {
  toText(report) { return `Total sales today: ₹${report.total()}`; }
}
class ReportSender {
  send(to, text) { console.log(`To ${to}: ${text}`); }
}

const report = new SalesReport([{ amount: 120 }, { amount: 80 }, { amount: 300 }]);
new ReportSender().send("owner@shop.in", new ReportFormatter().toText(report));
To owner@shop.in: Total sales today: ₹500

Now switching from email to WhatsApp changes only ReportSender. The maths is never touched.

अब email से WhatsApp पर जाने पर सिर्फ़ ReportSender बदलता है। हिसाब वाला code छुआ ही नहीं जाता।

O: Open/Closed (add, don't edit)O: Open/Closed (जोड़िए, बदलिए मत)

Beginnerशुरुआती

You add new apps to your phone without opening it up. Your code should work the same way: open for adding new behaviour, closed for editing old, tested code.

आप phone खोले बिना नई apps जोड़ते हैं। आपका code भी ऐसे ही काम करे: नया व्यवहार जोड़ने के लिए खुला, पुराने, tested code को बदलने के लिए बंद।

Warning sign: a long if / else if or switch on a type that you edit every time something new arrives (every new festival offer, every new payment method).

चेतावनी: type पर लंबा if / else if या switch जिसे हर नई चीज़ आने पर बदलना पड़े (हर नया festival offer, हर नया payment method)।

// O: add new behaviour by adding code, not by editing old code.
class NoDiscount      { apply(price) { return price; } }
class DiwaliDiscount  { apply(price) { return price * 0.8; } }   // 20% off
class HoliDiscount    { apply(price) { return price - 100; } }   // ₹100 off
// Next festival? Write a new class. checkout() never changes.

function checkout(price, discount) {
  return `Pay ₹${discount.apply(price)}`;
}

console.log(checkout(1000, new NoDiscount()));
console.log(checkout(1000, new DiwaliDiscount()));
console.log(checkout(1000, new HoliDiscount()));
Pay ₹1000
Pay ₹800
Pay ₹900

L: Liskov Substitution (a replacement must behave the same)L: Liskov Substitution (replacement वैसे ही चले)

Senior levelSenior level

A spare tyre that doesn't fit your car is useless, even if it's "a tyre". In code, if B extends A, then anywhere you use an A you must be able to use a B with no surprises.

जो spare tyre आपकी car पर फ़िट न हो वो बेकार है, भले वो "tyre" ही क्यों न हो। Code में, अगर B extends A, तो जहाँ भी A चलता है वहाँ B बिना किसी हैरानी के चलना चाहिए।

Warning sign: a child class that throws "not supported" for a parent method, or quietly changes what the parent's methods mean.

चेतावनी: child class जो parent के method पर "not supported" फेंके, या चुपचाप parent के methods का मतलब बदल दे।

// L: a child class must work wherever the parent works, with no surprises.
class Rectangle {
  setWidth(w) { this.width = w; }
  setHeight(h) { this.height = h; }
  area() { return this.width * this.height; }
}
class Square extends Rectangle {          // "a square is a rectangle"... in maths
  setWidth(w) { this.width = w; this.height = w; }
  setHeight(h) { this.width = h; this.height = h; }
}

function makeFloorPlan(shape) {           // written for any Rectangle
  shape.setWidth(5);
  shape.setHeight(10);
  return shape.area();                    // expects 5 x 10 = 50
}

console.log("Rectangle:", makeFloorPlan(new Rectangle())); // 50
console.log("Square:", makeFloorPlan(new Square()));       // 100: surprise! LSP broken
Rectangle: 50
Square: 100

Fix: don't make Square a child of Rectangle. Make both separate shapes that each have an area() method. "Is a" in real life doesn't always mean "extends" in code.

हल: Square को Rectangle का child मत बनाइए। दोनों को अलग shapes बनाइए जिनमें अपना area() method हो। असल ज़िंदगी का "है एक" code में हमेशा "extends" नहीं होता।

I: Interface Segregation (small, focused contracts)I: Interface Segregation (छोटे, focused contracts)

Senior levelSenior level

Don't force a juice shop to put biryani on its menu just because restaurants "should" have one. In code, don't force a class to have methods it can't really support. Split big contracts into small abilities.

Juice shop से biryani सिर्फ़ इसलिए menu में मत डलवाइए कि restaurants में "होनी चाहिए"। Code में, किसी class पर ऐसे methods मत थोपिए जो वो सच में नहीं कर सकती। बड़े contracts को छोटी क्षमताओं में बाँटिए।

Warning sign: methods that only throw "not implemented", or classes that must write empty methods just to satisfy a big interface.

चेतावनी: ऐसे methods जो सिर्फ़ "not implemented" फेंकें, या classes जिन्हें बड़ा interface पूरा करने के लिए ख़ाली methods लिखने पड़ें।

// I: don't force a class to have methods it can't support. Keep contracts small.
// Bad: one big "Machine" contract forces a basic printer to fake scan() and fax().
class BasicPrinterBad {
  print(doc) { return `printing ${doc}`; }
  scan() { throw new Error("I can't scan!"); }
  fax() { throw new Error("I can't fax!"); }
}
try { new BasicPrinterBad().scan(); } catch (e) { console.log("Bad design:", e.message); }

// Good: small, separate abilities. Each device has only what it can really do.
const canPrint = { print(doc) { return `printing ${doc}`; } };
const canScan = { scan() { return "scanning page"; } };

const basicPrinter = { ...canPrint };
const officeMachine = { ...canPrint, ...canScan };
console.log(basicPrinter.print("bill.pdf"), "| can scan?", "scan" in basicPrinter);
console.log(officeMachine.print("report.pdf"), "|", officeMachine.scan());
Bad design: I can't scan!
printing bill.pdf | can scan? false
printing report.pdf | scanning page

JavaScript has no interface keyword, but the idea is the same. In TypeScript, write small interfaces like Printable and Scannable instead of one giant Machine.

JavaScript में interface keyword नहीं है, पर idea वही है। TypeScript में एक बड़े Machine की जगह Printable और Scannable जैसे छोटे interfaces लिखिए।

D: Dependency Inversion (plug in, don't glue)D: Dependency Inversion (plug कीजिए, चिपकाइए मत)

Beginnerशुरुआती

Your phone has a USB-C port. Any charger that fits the port works: Samsung, a local brand, a power bank. If the charger were glued to the phone, you'd need a new phone to change chargers. In code, a class should receive its helpers from outside (plug in), not create a fixed one inside (glue).

आपके phone में USB-C port है। Port में फ़िट होने वाला कोई भी charger चलता है: Samsung, local brand, power bank। अगर charger phone से चिपका होता, तो charger बदलने के लिए नया phone लेना पड़ता। Code में, class को अपने helpers बाहर से मिलने चाहिए (plug in), अंदर एक तय वाला बनाना नहीं चाहिए (चिपकाना)।

Warning sign: new SomeService() written inside another class, which makes it hard to test or swap ("we can't test OrderService without sending real SMS").

चेतावनी: किसी class के अंदर लिखा new SomeService(), जिससे test करना या बदलना मुश्किल होता है ("असली SMS भेजे बिना OrderService test नहीं कर सकते")।

// D: depend on a "socket" (any object with send()), not on one fixed brand.
class SmsSender      { send(to, msg) { console.log(`SMS to ${to}: ${msg}`); } }
class WhatsAppSender { send(to, msg) { console.log(`WhatsApp to ${to}: ${msg}`); } }
class FakeSender {                       // for tests: sends nothing, just remembers
  constructor() { this.sent = []; }
  send(to, msg) { this.sent.push(msg); }
}

class OrderService {
  constructor(sender) { this.sender = sender; }   // plugged in from outside
  confirm(phone) { this.sender.send(phone, "Your order is confirmed"); }
}

new OrderService(new SmsSender()).confirm("98xxxxxx10");
new OrderService(new WhatsAppSender()).confirm("98xxxxxx10");

const fake = new FakeSender();
new OrderService(fake).confirm("98xxxxxx10");
console.log("Test check, messages sent:", fake.sent.length);
SMS to 98xxxxxx10: Your order is confirmed
WhatsApp to 98xxxxxx10: Your order is confirmed
Test check, messages sent: 1

NestJS and Angular do exactly this with dependency injection: you ask for a service in the constructor, and the framework plugs it in.

NestJS और Angular dependency injection से बिल्कुल यही करते हैं: आप constructor में service माँगते हैं, और framework उसे plug कर देता है।

How to explain SOLID in an interviewInterview में SOLID कैसे समझाएँ

Beginnerशुरुआती

Don't recite 5 definitions. Pick one or two and connect them to your own project, in 3 parts: the problem, the principle, the result.

पाँच definitions मत रटिए। एक-दो चुनिए और अपने project से जोड़िए, 3 हिस्सों में: problem, principle, नतीजा।

🎤 "Our notification code had a big switch for SMS, email and WhatsApp, and every new channel meant editing and re-testing it. I applied Open/Closed and Dependency Inversion: each channel became a class with a send() method, injected through NestJS. Adding Telegram later was one new class and no changes to existing code."

🎤 "Our notification code had a big switch for SMS, email and WhatsApp, and every new channel meant editing and re-testing it. I applied Open/Closed and Dependency Inversion: each channel became a class with a send() method, injected through NestJS. Adding Telegram later was one new class and no changes to existing code."

⚠️ Common mistakesआम ग़लतियाँ
  • Creating 10 tiny classes for a 20-line script. SOLID is for code that will grow and change.20 lines की script के लिए 10 छोटी classes बनाना। SOLID उस code के लिए है जो बढ़ेगा और बदलेगा।
  • Saying "I always follow SOLID" without a real example. Interviewers ask for one.बिना असली उदाहरण के "मैं हमेशा SOLID follow करता हूँ" कहना। Interviewers उदाहरण माँगते हैं।
📌 Remember these 4 thingsये 4 बातें याद रखिए
  1. S: chai stall, one job each. O: new app, phone not opened.S: chai stall, हर किसी का एक काम। O: नई app, phone खोला नहीं।
  2. L: the spare tyre must fit. Square extends Rectangle breaks it.L: spare tyre फ़िट होना चाहिए। Square extends Rectangle इसे तोड़ता है।
  3. I: no biryani at the juice shop. D: USB-C port, not a glued charger.I: juice shop पर biryani नहीं। D: USB-C port, चिपका charger नहीं।
  4. In interviews: one real example from your project beats five definitions.Interview में: आपके project का एक असली उदाहरण पाँच definitions से बेहतर है।

S (Single Responsibility). Saving, emailing and PDF generation are three jobs. Move them into UserRepository, WelcomeMailer and ProfilePdfService.

Exercise 2: Which principle is broken? function shippingCost(type) { if (type === "bluedart") return 80; if (type === "delhivery") return 60; /* add a new if for every courier */ }Exercise 2: कौन-सा principle टूटा है? function shippingCost(type) { if (type === "bluedart") return 80; if (type === "delhivery") return 60; /* हर नए courier के लिए नया if */ }
